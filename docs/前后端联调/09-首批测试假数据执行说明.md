## 四、推荐执行命令

### 4.1 MySQL

推荐使用本机 MySQL 客户端：

```powershell
& 'C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe' -h localhost -P 3306 -u root -p device_watch < 'D:\python\device_alarm\data_watch\docs\数据库\fake_data_seed_mysql.sql'
```

说明：

- `-p` 后不要直接写明文密码，由操作者交互输入。
- 若真实库结构与脚本不一致，应先修正事实源文档再执行。

### 4.2 TDengine

推荐使用本机 TDengine WebSocket CLI：

```powershell
Copy-Item 'D:\python\device_alarm\data_watch\docs\数据库\fake_data_seed_tdengine.sql' 'C:\TDengine\fake_data_seed_tdengine.sql' -Force
& 'C:\TDengine\taos.exe' -Z WebSocket -h 127.0.0.1 -P 6041 -u root -pHry19990910 -f 'C:\TDengine\fake_data_seed_tdengine.sql'
```

原因：

- 当前 `taos.exe -f` 无法稳定解析中文工作目录路径
- 因此执行前需先复制到 ASCII 路径
- 这里的“ASCII 路径”要求作用于完整绝对路径，而不只是文件名；父目录中也不能包含中文

验证脚本：

```powershell
Copy-Item 'D:\python\device_alarm\data_watch\docs\数据库\fake_data_verify_tdengine.sql' 'C:\TDengine\fake_data_verify_tdengine.sql' -Force
& 'C:\TDengine\taos.exe' -Z WebSocket -h 127.0.0.1 -P 6041 -u root -pHry19990910 -f 'C:\TDengine\fake_data_verify_tdengine.sql'
```

清理脚本：

```powershell
Copy-Item 'D:\python\device_alarm\data_watch\docs\数据库\fake_data_cleanup_tdengine.sql' 'C:\TDengine\fake_data_cleanup_tdengine.sql' -Force
& 'C:\TDengine\taos.exe' -Z WebSocket -h 127.0.0.1 -P 6041 -u root -pHry19990910 -f 'C:\TDengine\fake_data_cleanup_tdengine.sql'
```

执行完成后清理临时脚本：

```powershell
Remove-Item -LiteralPath 'C:\TDengine\fake_data_seed_tdengine.sql' -Force -ErrorAction SilentlyContinue
Remove-Item -LiteralPath 'C:\TDengine\fake_data_verify_tdengine.sql' -Force -ErrorAction SilentlyContinue
Remove-Item -LiteralPath 'C:\TDengine\fake_data_cleanup_tdengine.sql' -Force -ErrorAction SilentlyContinue
```

统一约束：

1. 所有通过 `taos.exe -f` 执行的联调脚本，都必须先复制到 ASCII 临时路径。
2. 不要直接从仓库中文目录执行 `-f`。
3. 每次执行完成后，清理 `C:\TDengine\` 下的临时副本，避免后续误执行旧脚本。

## 六、当前仍保留的阻塞与风险

1. **`error / pong / reconnect` 不能靠 seed 数据直接覆盖**
   - 这三类事件属于后端 WebSocket 运行时行为
   - 下一阶段应补充后端联调验收步骤，而不是继续增加 DB 样本

2. **TDengine CLI 对中文路径兼容性差**
   - 当前已验证 `taos.exe -f` 直接读取中文路径会失败
   - 后续运行脚本时需继续采用“复制到 ASCII 路径再执行”的方式

3. **当前 TDengine CLI 只能稳定验证子表元数据，直接查子表数据仍有兼容性异常**
   - 已确认测试子表、列结构、TAG 均已落库
   - 若要进一步核对样本内容，建议后续直接通过后端查询链路或其他客户端验证
