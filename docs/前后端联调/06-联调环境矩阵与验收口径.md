# 联调环境矩阵与验收口径

> 更新时间：2026-05-19
> 作用：明确联调依赖、真实服务 + 测试假数据策略和最小闭环验收标准

---

## 一、环境矩阵

| 依赖项 | 用途 | 首选方式 | 备选方式 | 是否阻塞最小闭环 | Owner |
|--------|------|----------|----------|------------------|-------|
| MySQL | 设备、点位、分组、告警规则等主数据 | 本地可用实例 | SQL Seed + 临时数据文件 | 是 | `@database`, `@backend` |
| Redis | 实时最新值、短窗口缓存、待入库 Stream、WebSocket 推送数据源 | 本地可用实例 | 采集进程内短窗口缓存（仅开发兜底） | 是 | `@collector`, `@backend`, `@ingestion`, `@test` |
| TDengine | 历史时序数据，按设备宽表批量落库 | 本地可用实例 | 将测试假数据写入真实 TDengine | 是 | `@ingestion`, `@backend`, `@test` |
| PLC / 协议驱动 | 实时采集来源 | 真实设备 / 仿真器 | 由测试假数据写入 MySQL / TDengine 的真实链路替代 | 否（M2 可降级） | `@collector`, `@test` |
| WebSocket | 实时订阅推送 | 本地后端服务 | 后端基于 Redis 最新值 / 短窗口生成标准事件 | 是 | `@backend`, `@test` |
| Fake Data | 无真实设备时的联调数据来源 | 固定样例集 | Seed SQL + 写入脚本 | 是 | `@test`, `@collector` |

说明：

- Redis 现在作为实时态基础设施和待入库队列纳入联调矩阵；TDengine 只承担历史落库与历史查询，落库动作由独立入库模块完成。

## 二、最小闭环（M2）依赖基线

最小闭环目标：

1. 设备树
2. 设备列表
3. 实时初始化
4. WebSocket 推送
5. 前端实时监控页

为达成 M2，至少应具备：

| 能力 | 必要条件 |
|------|----------|
| 设备树 | MySQL 或等价 Seed 数据可用 |
| 设备列表 | MySQL 或等价 Seed 数据可用 |
| 实时初始化 | 后端可从 MySQL + Redis 最新值生成结构化响应 |
| WebSocket 推送 | 后端可稳定发送 `snapshot/update/alarm/error/pong` 事件 |
| 前端实时页 | 路由、菜单、页面、字段映射和错误态已统一 |

说明：

- M2 不强依赖真实 PLC
- M2 **强依赖真实 TDengine 可读写**
- M2 可以基于写入真实 MySQL / TDengine 的 Fake Data 完成第一轮联调
- M2 禁止使用 mock API、mock WebSocket 或前端本地 mock 页面数据替代真实服务链路

---

## 二点五、M2 分层验收

为避免真实现场阻塞首轮联调，M2 拆分为两层：

| 层级 | 名称 | 目标 | 依赖 |
|------|------|------|------|
| M2-A | 联调可验收 | 先打通设备树、设备列表、实时初始化、WS 推送、Realtime 页面 | MySQL Seed + 真实 TDengine 测试假数据 + 后端 WS + 前端页面 |
| M2-B | 环境增强验收 | 在 M2-A 基础上补充真实 PLC / 仿真器、长稳运行与现场级验证 | 真实 PLC / 仿真器 / 完整 smoke 环境 |

说明：

- 若 PLC 未就绪，不阻塞 M2-A
- TDengine 是 M2-A 当前基础依赖
- M2-B 是增强验收，不是首轮闭环门槛

---

## 三、测试假数据策略

联调优先使用以下数据层级：

1. **真实设备数据**
2. **仿真器数据**
3. **写入真实 MySQL / TDengine 的固定 Fake Data**
4. **手工构造并写入真实服务的样例**

约束：

1. Fake Data 只能作为测试数据来源，不能替代真实 MySQL / TDengine / backend 服务链路。
2. 禁止通过 mock API、mock WebSocket、前端本地 mock 数据直接完成联调验收。
3. 后端对外 REST 与 WebSocket 仍必须基于真实服务中的数据进行统一归一化输出。

建议最小 Fake Data 覆盖：

- 3 类设备类型
- 2 种在线状态
- 1 组离线设备
- 1 组异常值
- 1 组活跃告警
- 1 组过期点位

## 四、验收口径

### 4.1 什么叫“接口可联调”

满足以下条件即可视为“接口可联调”：

- 路径、方法、请求字段、响应字段已冻结
- 至少有一组成功示例
- 至少有一组空态示例
- 至少有一组错误态示例
- 前端能按文档消费，不需要猜字段

### 4.2 什么叫“实时页可验收”

满足以下条件即可视为“实时页可验收”：

- 能正常进入 `/device-monitor/realtime`
- 左侧设备树可展示
- 右侧初始化数据可展示
- WebSocket 可收到至少 3 类事件：`snapshot`、`update`、`error`
- 断连后有可见的提示或恢复策略

### 4.2.1 什么叫“M2-A 联调可验收”

满足以下条件即可：

- 不依赖真实 PLC
- 依赖真实 TDengine 可写入、可查询最新值
- TDengine 中的测试假数据可驱动首屏，但必须经真实后端服务输出
- 后端可统一输出结构化 WS 事件
- 前端可稳定渲染 Realtime 页面并完成 smoke 演示

### 4.3 什么叫“历史查询可验收”

满足以下条件即可视为“历史查询可验收”：

- 能选择设备与点位
- 能返回 `times + points[].values`
- 图表和表格都能在空数据下稳定渲染
- 导出失败有明确提示

### 4.4 什么叫“Dashboard 可验收”

满足以下条件即可视为“Dashboard 可验收”：

- 统计卡片可加载
- 图表为空时不报错
- 单模块失败不阻断整页
- 连接健康和最近事件可单独降级

## 五、联调 Smoke Checklist

### 5.1 前端

- [ ] 路由和菜单一致
- [ ] 页面能加载空态
- [ ] 403 / 500 不白屏
- [ ] Realtime 页支持断连提示

### 5.2 后端

- [ ] API 文档与响应字段一致
- [ ] WebSocket 事件类型稳定
- [ ] TDengine 缺值时返回结构化空态
- [ ] 分页字段兼容 `pageNo/pageSize` 和 `current/size`

### 5.3 数据与基础设施

- [ ] MySQL Seed 可加载
- [ ] TDengine 测试假数据可写入真实实例
- [ ] 至少一组写入真实 MySQL / TDengine 的 Fake Data 可驱动 Realtime 页
- [ ] 不依赖 mock API / mock WS 完成联调
- [ ] 历史查询可从真实 TDengine 返回数据

---

## 六、阻塞升级规则

以下情况出现任一项，应升级给 `@coordinator`：

1. 同一个页面依赖的字段在文档和返回结果中不一致
2. Realtime 页因 TDengine / WS 不可用而无法形成最小闭环
3. 路由路径与菜单注册不一致
4. Fake Data 无法覆盖实时页和 Dashboard 的关键状态
