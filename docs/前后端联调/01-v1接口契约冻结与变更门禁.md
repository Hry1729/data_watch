# v1 接口契约冻结与变更门禁

> 更新时间：2026-04-13
> 适用范围：`/api/device-monitor` HTTP 接口与 `WS /api/device-monitor/ws/realtime`

---

## 一、目标

本文件用于落实以下治理要求：

- API / WebSocket 契约以文档为唯一事实源
- 联调期间遵循“先改文档、后改实现”
- 避免前后端各自演化、字段漂移、分页口径不一致
- 将“结构冻结”和“说明性补充”区分开来

---

## 二、唯一事实源

当前 `device-monitor` 业务域的唯一契约事实源为：

- `docs/后端/API接口文档.md`

以下文件均视为派生文件，不得反向成为接口事实源：

- `frontend/src/api/device-monitor.ts`
- `frontend/src/types/api/device-monitor.d.ts`
- 前端页面实现代码
- 后端接口实现代码
- 测试中的示例载荷

---

## 三、当前冻结状态

截至 2026-04-13，v1 联调契约采用以下状态：

| 状态项 | 当前值 | 说明 |
|--------|--------|------|
| HTTP 契约 | 冻结基线 | 除历史查询外，不允许结构性变更 |
| WebSocket 契约 | 冻结基线 | 允许补充说明，不允许新增强依赖字段 |
| 历史查询 | 保持现状 | 继续使用 `times + points[].values`，本轮不做破坏性调整 |
| 示例载荷 | 可补充 | 可新增样例、空态、错误态说明 |
| 文档状态 | 待签收 | 可做说明性补充，但不允许私自改结构 |

---

## 四、冻结范围

下列内容视为 v1 冻结范围：

1. 接口前缀：`/api/device-monitor`
2. 统一响应结构：`code/msg/data`
3. 时间与时区口径：`YYYY-MM-DD HH:mm:ss`，不接收 `timezone`
4. 分页语义：前端优先 `pageNo/pageSize`，兼容 `current/size`
5. 错误码语义：`400/401/403/500`
6. WebSocket 推送用途：实时监控初始化、订阅与推送
7. 历史查询本轮继续保持 `times + points[].values`
8. 空数据和错误数据的返回结构完整性

---

## 五、允许变更与禁止变更

### 5.1 允许的变更

以下内容可以在联调期间补充：

- 新增示例请求与示例响应
- 新增空态、错误态、无权限态说明
- 新增字段解释、默认值解释、枚举解释
- 新增兼容性说明与联调注意事项
- 修正文案错误、排版错误、编号错误

### 5.2 禁止的变更

以下内容不得在未发起评审前直接修改：

- 删除字段、重命名字段、修改字段类型
- 修改分页主口径
- 修改错误码语义
- 修改 WebSocket 主载荷结构
- 修改实时初始化接口的主响应结构
- 将历史查询切换为其他结构
- 新增前端强依赖字段但不更新事实源

---

## 六、变更门禁流程

所有结构性变更都必须按以下顺序执行：

1. 提出变更原因
2. 说明影响范围
3. 先修改 `docs/后端/API接口文档.md`
4. 再同步修改本目录中的相关治理文档
5. 由 `@backend`、`@frontend`、`@test` 至少三方签收
6. 最后才允许进入实现与联调

---

## 七、最小变更单模板

结构性变更必须至少包含以下信息：

| 字段 | 说明 |
|------|------|
| 变更编号 | 如 `API-CHANGE-001` |
| 变更类型 | 新增 / 删除 / 重命名 / 类型调整 / 语义调整 |
| 影响接口 | HTTP / WS 路径列表 |
| 影响页面 | Dashboard / Device / Realtime / History 等 |
| 影响测试 | 契约测试 / 联调测试 / Smoke / 回归 |
| 向后兼容性 | 是否兼容，若不兼容如何回退 |
| 评审人 | `@backend` / `@frontend` / `@test` / `@coordinator` |

---

## 八、签收角色

| 角色 | 必签场景 |
|------|----------|
| `@backend` | 任何接口字段、错误码、分页、WS 变更 |
| `@frontend` | 任何页面依赖字段、空态、导出、分页、路由语义变更 |
| `@test` | 任何会影响契约测试、联调测试、回归测试的变更 |
| `@coordinator` | 任何会影响里程碑、优先级或跨模块范围的变更 |

---

## 九、联调期间默认原则

1. 先对齐文档，再对齐类型，再进入实现。
2. 示例载荷不是真实契约，真实契约只认 API 文档。
3. 历史查询接口本轮不优化结构，只保证可联调。
4. WebSocket 推送允许宽松结构，但禁止新增前端强依赖字段。
5. 若前后端口径冲突，以本文和 `docs/后端/API接口文档.md` 为准，不以页面代码和本地类型为准。
