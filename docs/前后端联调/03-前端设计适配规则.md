# 前端设计适配规则

> 更新时间：2026-04-13
> 作用：将 `frontend/DESIGN.md` 的设计语言转译为 ArtDesignPro 可执行规则

---

## 一、目标

本文件不直接产出页面设计稿，而是回答一个问题：

**如何在不推翻 ArtDesignPro 现有工程结构的前提下，保持 `frontend/DESIGN.md` 的视觉气质与设计一致性。**

---

## 二、设计优先级

前端视觉和交互规范按以下顺序执行：

1. `frontend/DESIGN.md`
2. 本文件
3. `docs/前端/页面设计文档.md`
4. `docs/前端/开发必读文档.md`

冲突裁决原则：

1. **工程结构服从 ArtDesignPro**
2. **视觉气质服从 `frontend/DESIGN.md`**
3. **若二者冲突，以监控场景可读性与一致性优先**
4. **禁止为了追求设计还原度而重造一套脱离 ArtDesignPro 的新框架**

---

## 三、必须继承的设计原则

以下原则在后续页面设计中必须保留：

1. **双模式气质**
   - 信息型、管理型区域以浅色背景为主
   - 重点展示区、总览区、品牌区可使用深色背景

2. **标题与正文分层**
   - 标题层使用更强字重与更紧行高
   - 正文、表格、辅助文本保持克制、可读

3. **Token 驱动**
   - 颜色、阴影、边框、圆角、间距必须优先抽象成变量
   - 禁止在页面中散落大量一次性样式值

4. **克制的视觉深度**
   - 阴影要轻，不追求悬浮感
   - 圆角保持 2px-8px 区间，不走夸张的胶囊风

5. **企业基础设施气质**
   - 强调秩序、可信、清晰，而不是炫技
   - 图表与状态色必须服务监控可读性

---

## 四、可与 ArtDesignPro 对接的实现层

| 设计层 | 保持 `DESIGN.md` 原则 | 落地方式 |
|--------|------------------------|----------|
| 页面布局 | 保持双模式、信息分区、重点区强调 | 复用 ArtDesignPro 的布局和页面容器 |
| 卡片 | 保持轻阴影、窄圆角、层级清晰 | 优先复用现有卡片组件，调整 token |
| 表格 | 保持信息密度与留白平衡 | 使用 `ArtTable`，统一标题、边距、状态色 |
| 图表 | 保持监控导向和品牌克制 | 使用现有 ECharts 组件，统一主题 token |
| 树和筛选区 | 保持清晰、轻量、功能先行 | 使用现有树、表单、搜索栏组件 |
| 按钮 | 保持主次分明、不夸张 | 保留框架结构，统一颜色、半径、边框、焦点样式 |

---

## 五、必须先定义的前端 Token 层

在进入页面实现前，应先固定以下 token 分类：

| Token 类别 | 说明 |
|------------|------|
| 品牌主色 | 主体黑、深灰、蓝色动作色、强调色 |
| 中性色阶 | 页面背景、卡片背景、分割线、次级文字 |
| 状态色 | 正常、警告、错误、离线、禁用 |
| 圆角 | 2px / 4px / 5px / 8px 四档为主 |
| 阴影 | 卡片默认微阴影、交互态微抬升 |
| 字体层级 | 页面标题、区块标题、卡片标题、正文、辅助文案、标签 |
| 间距层级 | 页面外边距、区块间距、卡片内边距、表单间距 |

## 六、页面级适配规则

### 6.1 Dashboard

- 允许使用深色重点区或深浅拼接
- 卡片、图表、事件列表必须统一同一套 token
- 不允许每个模块各用一套配色

### 6.2 Device / Point / Realtime

- 以高可读性和操作效率为优先
- 左树右内容布局要统一树宽、内容区边距、状态色规则
- 状态标签和异常值高亮必须统一

### 6.3 History / Log

- 以查询和结果对比为主，避免过度装饰
- 筛选区、图表区、表格区的层级顺序必须固定

---

## 七、禁止事项

以下行为在后续页面设计中禁止出现：

1. 将 `frontend/DESIGN.md` 直接机械照搬成一套与 ArtDesignPro 完全脱节的新框架
2. 随意引入未沉淀为 token 的颜色、阴影、圆角、字号
3. 单个页面私自定义新的主视觉风格
4. 将监控页面做成营销站风格
5. 用动画替代信息层级，用炫目色替代状态表达

---

## 八、设计适配结论

前端后续执行时应遵循以下落地判断：

- **保留气质，不重造框架**
- **保留 token，不散落样式**
- **保留层级，不堆砌装饰**
- **保留一致性，不让单页风格游离**

换句话说：

`frontend/DESIGN.md` 是设计气质来源，ArtDesignPro 是工程落地底座，本文件是两者之间的翻译层。

---

## 九、外部设计稿接入规则

后续若存在外部设计产物（例如由其他智能体借助 Pencil 输出的页面草图、线框稿或交互稿），前端应按以下原则处理：

1. 外部设计稿视为**设计输入**，不是可直接落地的最终实现规范
2. 外部设计稿必须经过本文件与 `frontend/DESIGN.md` 的双重校验
3. 若外部设计稿与 ArtDesignPro 结构冲突，应优先保留框架结构，在视觉层做适配
4. 若外部设计稿与 `frontend/DESIGN.md` 气质冲突，应优先回到 token、层级、间距和信息组织规则
5. 后续若用户提供 Pencil 设计稿，应作为前端二次对齐的上游输入，而不是绕过本治理文档直接实现
