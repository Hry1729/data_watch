## 四、建议最小字段口径

下面不是最终唯一 DDL，而是 **后端联调所需的最小字段集合**。数据库工程师可以在此基础上扩展，但不建议少于这些核心字段。

### 4.1 `alarm_level`

建议字段：

- `id`
- `level_code`：如 `INFO / WARN / ERROR / CRITICAL`
- `level_name`
- `severity`：数值等级，便于排序和聚合
- `color`
- `sort`
- `enabled`
- `create_time`
- `update_time`

作用：

- 作为告警等级字典表
- 供 `alarm_rule`、`alarm_record` 关联或冗余引用

### 4.2 `alarm_rule`

建议字段：

- `id`
- `rule_code`
- `rule_name`
- `device_id`
- `point_id`
- `alarm_type`
- `level_id` 或 `level_code`
- `compare_op`
- `threshold_value`
- `recover_value`
- `enabled`
- `description`
- `create_time`
- `update_time`

作用：

- 表示某设备 / 点位的告警判定规则
- 后续可供规则管理、事件解释和统计维度复用

### 4.3 `alarm_record`

建议字段：

- `id`
- `alarm_no` 或 `event_id`
- `rule_id`
- `device_id`
- `device_code`
- `device_name`
- `point_id`
- `point_name`
- `alarm_type`
- `level_code`
- `status`
- `alarm_value`
- `threshold_value`
- `content`
- `start_time`
- `end_time`
- `ack_time`
- `ack_by`
- `recover_time`
- `create_time`

最关键说明：

- 这张表是 `dashboard/recent-events` 的主事实源
- 也是 `dashboard/alarm-distribution` 的主统计源
- 为了降低联调复杂度，建议在记录表中冗余 `device_code / device_name / point_name / level_code / alarm_type`

### 4.4 `alarm_active`

建议字段：

- `id`
- `record_id`
- `rule_id`
- `device_id`
- `device_code`
- `point_id`
- `point_name`
- `alarm_type`
- `level_code`
- `status`
- `start_time`
- `latest_time`
- `create_time`
- `update_time`

作用：

- 维护当前仍未恢复 / 未关闭的活动告警
- 可直接支撑工作台 `activeAlarmTotal`

### 4.5 `operation_log`

建议字段：

- `id`
- `log_time`
- `operator_id`
- `operator_name`
- `module_name`
- `action_name`
- `level`
- `content`
- `detail_json`
- `create_time`

说明：

- 这张表偏“用户操作审计”
- 可以被后端统一映射为前端 `type = system`

### 4.6 `system_log`

建议字段：

- `id`
- `log_time`
- `level`
- `log_type`：建议约束为 `system / collect / storage / alarm`
- `source`
- `device_id`
- `device_code`
- `content`
- `detail_json`
- `trace_id`
- `create_time`

说明：

- 这张表偏“系统运行与采集运行日志”
- 当前前端日志页最终需要输出：
  - `time`
  - `level`
  - `type`
  - `content`

## 七、建议的最小种子数据

为了让页面联调一落表就能看出效果，建议新增一批 **可识别的联调测试数据**：

### 7.1 告警侧

- `alarm_level`：至少 3 条
  - `INFO`
  - `WARN`
  - `ERROR`
- `alarm_rule`：至少 3 条
  - 分别挂到已有设备 / 点位上
- `alarm_record`：至少 10 条
  - 覆盖近 24h、近 7d
  - 覆盖不同 `alarm_type`
  - 覆盖不同 `level_code`
  - 覆盖 `active / handled / recovered`
- `alarm_active`：至少 2~3 条
  - 与 `alarm_record` 对应
  - 用于工作台活动告警总数验证

### 7.2 日志侧

- `operation_log`：至少 10 条
  - 覆盖菜单访问、配置修改、登录登出等
- `system_log`：至少 20 条
  - 覆盖 `system / collect / storage / alarm`
  - 覆盖 `INFO / WARN / ERROR`

约束：

- 这些测试数据必须是 **新增数据**
- 不允许覆盖或修改你当前已有的业务数据
