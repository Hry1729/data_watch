# 项目环境与启动说明

## 一、路径占位符

为避免项目迁移到其他电脑后路径失效，本文使用以下占位符：

```text
<项目根目录>        项目所在目录，例如 D:\python\device_alarm\data_watch
<后端Python3.14t>   Python 3.14 free-threading 解释器路径
<采集Python3.14>    普通 Python 3.14 解释器路径
```

当前电脑的实际项目路径是：

```text
D:\python\device_alarm\data_watch
```

迁移到其他电脑时，请把命令中的 `<项目根目录>` 替换成目标电脑上的实际路径。

## 二、环境概览

### 1. 前端环境

目录：

```text
<项目根目录>\frontend
```

环境：

```text
Node.js
pnpm
```

启动：

```powershell
cd <项目根目录>\frontend

```

访问：


说明：

- 前端不需要安装 Python 依赖。
- `frontend/node_modules` 不建议迁移，应在目标设备重新执行 `pnpm install`。

### 2. 后端环境

后端需要 Python 3.14 free-threading。

#### 2.1 当前电脑正在使用的方式

当前电脑实际使用的是：

```text
Python 解释器：
C:\Users\Hry\.local\bin\python3.14t.exe

后端本地依赖目录：
D:\python\device_alarm\data_watch\backend\.py314t-site

额外依赖目录：
C:\Users\Hry\AppData\Local\Python\pythoncore-3.14-64\Lib\site-packages
```

这种方式可以运行，但不适合作为迁移到其他电脑的主推方式，因为它依赖当前用户目录和手动设置 `PYTHONPATH`。

#### 2.2 推荐迁移方式

推荐在后端目录创建标准虚拟环境：

```powershell
cd <项目根目录>\backend

& "<后端Python3.14t>" -m venv .venv-314t
.\.venv-314t\Scripts\python.exe -m pip install -r requirements.txt
.\.venv-314t\Scripts\python.exe -m pip install pytest pytest-asyncio
```

启动后端：

```powershell
cd <项目根目录>\backend

.\.venv-314t\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

测试后端：

```powershell
cd <项目根目录>\backend

.\.venv-314t\Scripts\python.exe -m pytest app\tests -q
```

#### 2.3 当前电脑兼容启动方式

如果当前电脑暂时仍使用 `.py314t-site`，可以这样手动启动：

```powershell
cd D:\python\device_alarm\data_watch\backend

$env:PYTHONPATH = "D:\python\device_alarm\data_watch\backend\.py314t-site;C:\Users\Hry\AppData\Local\Python\pythoncore-3.14-64\Lib\site-packages"
$env:PYTHONUTF8 = "1"
$env:PYTHONIOENCODING = "utf-8"

& "C:\Users\Hry\.local\bin\python3.14t.exe" -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

说明：

- 这是当前电脑的兼容方式。
- 不建议把这段作为其他电脑的通用启动方式。

### 3. 采集模块环境

采集模块使用普通 Python 3.14 虚拟环境。

推荐创建方式：

```powershell
cd <项目根目录>\collector

& "<采集Python3.14>" -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

启动采集模块：

```cmd
cd /d <项目根目录>\collector

run.bat
```

也可以直接启动主进程：

```powershell
cd <项目根目录>\collector

.\.venv\Scripts\python.exe main.py
```

说明：

- 推荐优先使用 `run.bat`。
- `run.bat` 会先检测 OPC DA center/sidecar 协议，再启动采集主进程。
- 直接启动 `main.py` 会跳过 OPC DA 自动检测和辅助服务启动。
- 当前采集主链路以 MySQL 配置为事实源，启动后会注册设备/点位、初始化 Redis 实时缓存与待入库 Stream、连接设备、启动调度器、HTTP ingest、聚合器和健康检查。
- 当前目标核心能力：S7 / GE-SRTP / OPC UA / OPC DA center 驱动适配、HTTP Push / OPC DA sidecar 入队、DataBuffer 异步队列、DataAggregator 去重与失败回滚、Redis 实时最新值/短窗口/Stream、独立入库模块批量写 TDengine 设备宽表。
- TDengine 当前目标结构为 `device_data` 单库、`qc/asc/agv` 三个超级表、每设备一个子表、点位值宽列；历史表不再保存 `quality`。

## 三、项目启动方式

### 1. 一键启动前端和后端

PowerShell：

```powershell
cd <项目根目录>

.\start-dev.ps1
```

CMD：

```cmd
cd /d <项目根目录>

start-dev.cmd
```

如果端口已占用，但确认需要强制打开新窗口：

```powershell
.\start-dev.ps1 -Force
```

当前 `start-dev.ps1` 会自动寻找后端 Python。为了移植更稳定，后续建议优先查找：

```text
backend\.venv-314t\Scripts\python.exe
```

再回退到当前电脑的 `C:\Users\Hry\.local\bin\python3.14t.exe`。

### 2. 手动启动前端

```powershell
cd <项目根目录>\frontend

pnpm dev
```

### 3. 手动启动后端

推荐方式：

```powershell
cd <项目根目录>\backend

.\.venv-314t\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

当前电脑兼容方式见“二、2.3 当前电脑兼容启动方式”。

### 4. 启动采集模块

```cmd
cd /d <项目根目录>\collector

run.bat
```

## 五、迁移注意事项

不要迁移以下目录：

```text
frontend/node_modules/
frontend/dist/
backend/.py314t-site/
backend/.venv-314t/
collector/.venv/
__pycache__/
.pytest_cache/
logs/
.tmp_*
```

迁移后应重新执行：

```text
frontend：pnpm install
backend：重新创建 .venv-314t 并安装 requirements.txt
collector：重新创建 .venv 并安装 requirements.txt
```

这样可以避免旧电脑绝对路径残留导致启动或测试异常。
