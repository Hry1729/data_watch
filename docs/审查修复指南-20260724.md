## 第一部分：阻断问题 (P0)

### P0-1 【数据正确性】质量窄表无法可靠保存同一时刻的多个点位质量

**位置**: `writer/tdengine_writer.py:401` + `writer/quality_schema.py:71`

**问题描述**:
- 当前 DDL: `(ts TIMESTAMP PRIMARY KEY, var_id BIGINT, quality TINYINT)`
- 每台设备共用一个 `{device_code}_q` 子表
- 一次采样写入多个相同 ts、不同 var_id 的记录 → **主键冲突或覆盖**

**根本原因**: TDengine 只有复合主键才能区分同时间戳记录 (官方文档: https://docs.tdengine.com/reference/taos-sql/table/)

**修复方案**:

```python
# writer/quality_schema.py:71 附近
DDL_TEMPLATE = """
CREATE TABLE IF NOT EXISTS {stable_name} (
    ts TIMESTAMP,
    var_id BIGINT COMPOSITE KEY,
    quality TINYINT
) TAGS (device_code BINARY(64));
"""
```

**必做验证**:
1. 增加启动时 schema 校验 (检测已有表是否缺 COMPOSITE KEY，给出迁移提示)
2. 真实 TDengine 多点同时间戳写入测试:
   ```python
   # 伪代码
   INSERT INTO device_001_q VALUES 
       ('2026-07-24 10:00:00', 1, 192),
       ('2026-07-24 10:00:00', 2, 192),
       ('2026-07-24 10:00:00', 3, 0);
   SELECT COUNT(*) FROM device_001_q WHERE ts='2026-07-24 10:00:00';
   # 期望: 3，不是 1
   ```
3. 已有错误表的迁移方案 (CREATE 新表 → INSERT SELECT → RENAME)

**影响**: 不修复则质量数据全部错误，后续测试无意义。

### P0-2 【数据一致性】卸载使用错误的驱动标识，导致"数据库已删、驱动仍在"

**位置**: 
- `app/src/pages/DriverManagementPage.tsx:179` (App 传 protocol)
- `backend/app/services/driver_lifecycle.py:268` (Backend 用 protocol 调 Agent)
- `backend/app/services/driver_lifecycle.py:289` (404 误判为已卸载)

**问题描述**:
- Manifest 定义 `id` (安装目录名) 和 `protocol` (通信协议) 是两个独立字段
- 如果 `id != protocol`，Agent 返回 404
- Backend 把 404 当成"已卸载"，继续删除 MySQL 的 `comm_protocol` 记录
- **实际 Agent 的安装目录仍然存在**

**修复方案**:

1. **Backend 持久化完整驱动元数据** (新建或扩展表):
   ```sql
   ALTER TABLE comm_protocol ADD COLUMN (
       driver_id VARCHAR(100),      -- Manifest.id, Agent 安装目录名
       driver_version VARCHAR(50),
       driver_sha256 CHAR(64),
       install_source VARCHAR(20)   -- 'builtin' | 'zip'
   );
   -- 或新建 installed_drivers 表
   ```

2. **Backend 调用 Agent 必须使用 driver_id**:
   ```python
   # backend/app/services/driver_lifecycle.py:268
   agent_url = f"{agent_base}/admin/drivers/{driver_id}"  # 不是 protocol
   ```

3. **404 前先核实**:
   ```python
   # 伪代码
   agent_list = requests.get(f"{agent_base}/admin/drivers").json()
   if driver_id in [d['id'] for d in agent_list]:
       # 仍存在，404 是路径错误
       raise DriverUninstallError(f"Agent returned 404 but {driver_id} still exists")
   # 404 且列表不存在，才认为已卸载
   ```

**必做验证**:
- 创建 `id=custom_modbus`, `protocol=modbus_tcp` 的测试包
- 注册后卸载，确认:
  - Agent 目录删除
  - MySQL 记录删除
  - 不出现"目录在、记录无"的不一致

### P1-4 【契约一致性】Stream v2 契约校验与设计文档不一致

**位置**: 
- `writer/consumer.py:516` (version 降级)
- `writer/consumer.py:565` (质量对齐检查缺失)

**问题描述**:
- 当前: 非法 `contract_version` 降级为 v1，缺失/额外质量直接忽略
- 设计要求: `qualities` 与 `values` 键集合必须对齐 (docs/superpowers/specs/2026-07-21-quality-code-end-to-end-design.md:142)

**修复方案**:

```python
# writer/consumer.py:516 附近
def _determine_contract_version(entry: dict) -> int:
    version = entry.get('contract_version')
    if version is None:
        return 1  # 字段缺失 → v1 (向后兼容)
    if version not in (1, 2):
        raise ValueError(f"Unsupported contract_version: {version}")  # 不降级
    return version

# writer/consumer.py:565 附近 (v2 路径)
def _validate_v2_qualities(values: dict, qualities: dict, stored_var_ids: set):
    # 过滤非存储点后比较键集合
    stored_values = {k: v for k, v in values.items() if k in stored_var_ids}
    stored_qualities = {k: v for k, v in qualities.items() if k in stored_var_ids}
    
    if set(stored_values.keys()) != set(stored_qualities.keys()):
        raise QualityAlignmentError(
            f"Values keys {set(stored_values.keys())} != qualities keys {set(stored_qualities.keys())}"
        )
```

**必做验证**:
- `contract_version=999` → DLQ (不是降级)
- `values={1,2,3}, qualities={1,2}` → DLQ (缺失质量)
- `values={1,2}, qualities={1,2,3}` → DLQ (额外质量)

   ```python
       registry = get_driver_registry()
       return [{
           'id': d.id,
   ```

   ```python
   # agent/app/services/driver_installer.py
   def _wait_for_driver_loaded(driver_id: str, version: str, sha256: str, timeout: int = 30):
       start = time.time()
       target_gen = _get_collector_generation() + 1  # 期望重启后的代际
       
       while time.time() - start < timeout:
           resp = requests.get("http://localhost:6868/drivers")
   ```

### P1-7 【性能】Backend 卸载在异步接口中同步阻塞最长 120 秒

**位置**: `backend/app/services/driver_lifecycle.py:279` (urlopen)

**问题描述**:
- 使用同步 `urlopen`，Agent 重启/网络异常时阻塞事件循环
- 单机影响一个管理员，分布式会放大

**修复方案**:

```python
# backend/app/services/driver_lifecycle.py:279
import httpx

async def uninstall_driver_from_agent(driver_id: str, agent_base: str, agent_token: str):
    async with httpx.AsyncClient(timeout=30.0) as client:
        resp = await client.delete(
            f"{agent_base}/admin/drivers/{driver_id}",
            headers={"Authorization": f"Bearer {agent_token}"}
        )
        if resp.status_code == 404:
            # 先核实 (见 P0-2)
            list_resp = await client.get(f"{agent_base}/admin/drivers")
            if driver_id in [d['id'] for d in list_resp.json()]:
                raise DriverUninstallError("404 but still exists")
        resp.raise_for_status()
```

**必做验证**:
- 卸载时模拟 Agent 不可达 → 30s 超时返回错误 (不是 120s 阻塞)

## 第四部分：架构级隐患

### A1 【战略冲突】驱动管理与分布式部署方案的冲突

**背景**: 已定稿的《分布式部署架构方案》要求:
- 边缘 collector 读本地 SQLite 配置
- 中心 Backend 通过心跳推送配置到边缘 Agent
- 设备分散在多个边缘节点

**当前设计隐含前提**: 单机部署 (Backend → Agent http://127.0.0.1:7070)

**冲突点**:
1. Backend 只知道本机 Agent，不知道多边缘拓扑
2. 卸载检查只能查本机绑定，无法判断"设备在边缘 3，不能卸载驱动 X"
3. 驱动安装后如何通知对应边缘的 Agent 同步配置?

**建议**:
- **方案 A (推荐)**: 驱动管理推迟到分布式阶段，作为"Agent 配置同步"的一部分重新设计
  - 当前只保留 Agent 层的 ZIP 校验 + 安装事务
  - Backend 编排层标记 `@deprecated`
  - 分布式文档加"驱动同步"章节
  
- **方案 B**: 当前只做单机版，文档明确标注"分布式需重构"
  - 上线前补端到端冒烟测试
  - 3 个月后分布式合并时整体替换

### A2 【技术决策】质量窄表的性能验证缺失

**当前决策依据**: "max_point_count=3072 下平行 __q 会超 4096 列"

**推理Bug**: 
- 窄表是 `(ts, var_id, quality)` **固定 3 列**，不会超 4096
- 真实权衡应该是: 密集 vs 稀疏、写入性能 vs 查询复杂度

**风险**:
- 窄表写入要拆 3072 行 INSERT，可能比宽表慢 > 20%
- 历史查询要 JOIN，延迟可能 > 500ms
- 宽表+窄表分离写入，TDengine 无跨表事务，质量写入失败时值已落盘 → 不一致

**必做压测** (在修 P0-1 后):
```python
# 场景: 100 台设备、1000 点位/台、10% 质量覆盖率、持续 1 小时
# 指标:
# - 窄表写入延迟 P99
# - 历史查询(带质量) P99
# - TDengine CPU/内存
# 判断标准:
# - 窄表写入 < 宽表 120%
# - 历史查询 < 500ms
# - 无 TDengine 异常
```

**如果压测失败**:
- 回退到宽表 + 按需创建 `__q_*` 列 (初始只创建有质量的点位列)
- 或优化 INSERT 批次 (单语句多 VALUES vs 事务批量)

**补充修复** (无论用哪个方案):
```python
# writer/tdengine_writer.py
try:
    # 写宽表
    self._write_values(device_id, samples)
    # 写窄表
    self._write_qualities(device_id, qualities)
except QualityWriteError as e:
    # 质量写入失败，值已落盘 → 记DLQ + 指标，不回滚宽表
    logger.error(f"Quality write failed for {device_id}: {e}")
    self._metrics.inc('quality_write_failures')
    self._dlq.push(entry)
```
