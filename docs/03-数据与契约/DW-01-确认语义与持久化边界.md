# DW-01 确认语义与持久化边界

## 当前实现

- 集中式 Collector 的轮询和 HTTP 采集先写本地 SQLite 队列，使用 WAL + synchronous=FULL。保存原始点值、质量、时间戳、配置版本；成功返回表示本地事务已提交。后台独立线程批量重放，因此重启后即使没有新采样也能排空积压。
- 中心接收确认选择 **Redis 持久接收**，不是 TDengine 最终入库确认。Ingest 在同一非事务 pipeline 连接上执行 Lua 与 `WAITAOF 1 0 2000`；只有本地 AOF 确认成功才返回成功结果。失败或不支持 WAITAOF 时返回 commit_unknown，边缘保留副本重试。
- 成功 ACK 带 `durability=redis-aof`。新边缘不接受缺少该标记的成功 ACK，避免旧中心只确认内存就触发边缘清理。必须先升级中心，再升级边缘。
- 集中式 Redis 出口也在同一连接中对批量帧执行 Lua + WAITAOF，全部成功后才删除本地队列记录。原帧 ID 用于 Redis 重放去重，去重记录保留 7 天；超过该期限允许重复投递，历史仍使用原采样时间戳。保证为至少一次，而非严格恰好一次。
- Collector 持久出口与 Ingest 不按 MAXLEN 裁剪历史 Stream。Writer 只有成功入库或明确隔离到 DLQ 后才确认，正常清理由 Writer 负责。Redis noeviction 拒写后，上游积压保留。
- 边缘本地 SQLite 也改为 FULL。已持久确认的 sent 记录默认额外保留 24 小时；该留存是运维缓冲，不是可靠性证明或自动对账机制。

## 容量与失败边界

集中式队列默认最多 50,000 条，数据库页面最多 1 GiB，并在磁盘可用空间低于 256 MiB 时拒绝新样本。满载不会删除既有未确认记录；新样本无法持久化会明确报错，因此不承诺无限断网期间零丢失。WAL、文件系统与其他进程仍有额外磁盘开销。

本地事务提交前的进程退出、硬件损坏、磁盘丢失、不遵守 fsync 的设备、人工删除数据、切换到未同步副本，均不在此保证内。Redis 持久接收也不等价于 TDengine 已最终入库；坏数据可能进入 DLQ，需要运维处理。

## 部署要求

1. Redis **7.2 或更新版本**，开启 AOF，持久化目录放在可靠持久卷中，ACL 允许 WAITAOF。仓库配置使用 everysec，但成功确认还额外等待实际 AOF fsync。
2. Redis 版本不足、AOF 关闭或落盘超时会保留上游积压，不降级成不可靠成功。不要在未迁移现有 RDB 数据的情况下直接重建 Redis 容器；按 Redis 官方 AOF 迁移流程验证并备份。
3. 升级现有系统前的内存 ACK 和此前已删除副本不能追溯修复。新保证从双方升级并成功收到新 ACK 后开始。
4. Collector 队列位于 DATAWATCH_DATA_ROOT（兼容 DATAWATCH_HOME）下 runtime/collector-retry.db；默认 C:\ProgramData\DataWatch。配置数据目录应使用独立可写目录。

## 验证边界

单元回归覆盖 AOF 超时保留、重启原样重放、并发重放互斥、满载不逐出、实时历史分离和新旧 ACK 兼容。真实 Redis / TDengine 故障注入与磁盘断电测试须在隔离环境验收，不能将 mock 测试称为现场零丢失验收。

未采用之前的“最大已写入时间戳水位”提案：存在乱序、部分失败和多点位批次时，最大时间戳无法证明此前所有数据完整入库。
