# DW-01 确认语义与持久化边界

> **适用形态（D39 拆分）**：确认语义按**部署形态**分别定义，两套口径**不可互换**。
>
> - **中心式（现行）**：PLC/OPC → 中心 Collector → **`RedisWriter` 直写 Redis** → Writer → TDengine。
> - **分布式（现行）**：边缘 Edge Collector → 本地 SQLite Outbox → Uploader → 中心 Ingest → Redis → Writer → TDengine。
>
> 本文件此前把「集中式本地 SQLite 队列 + 逐批 `WAITAOF`」写在「当前实现」之下，那是**已撤销的中心 Durable 方案**。
> 现行中心式**不构造 SQLite Outbox、不逐批 `WAITAOF`**；`WAITAOF` 门禁只存在于**分布式中心 Ingest**。
> 被撤销方案的历史口径**保留**在 §4 并标记 `Superseded`，仅供迁移与遗留处置参考，**不得**再当作当前实现引用。

## 1. 现行确认矩阵（中心式 / 分布式）

| 环节 | 中心式（现行） | 分布式（现行） |
|---|---|---|
| 生产入口 | `collector/main.py:181-192`（`writer_factory is None` 的默认分支） | `edge/collector_main.py:20`（经 `writer_factory` 注入 `EdgeOutboxWriter`） |
| 采样 → 本地持久 | **不经本地队列**；解析/分组后直接批量写 Redis | 边缘先写**本地 SQLite Outbox**；成功返回 = 本地事务已提交 |
| 持久回放 | **无** Durable 回放线程（`collector/tests/test_central_runtime_redis_only.py:187`） | 边缘 Uploader 单实例、严格有序领取、逐项 ACK；重启后继续排空积压 |
| Redis 接受 | `RedisWriter` 直写（`collector/main.py:188`）；导入面仅 `RedisWriter`（`:52`） | 中心 Ingest 在**同一非事务 pipeline 连接**上先 Lua 后 `WAITAOF 1 0 2000`（`ingest/app/redis_store.py:356-365`） |
| AOF 持久确认 | **不发起 `WAITAOF`、不等 AOF fsync**（`collector/tests/test_central_runtime_redis_only.py:192`） | `numlocal >= 1` 才返回成功；否则 `CommitUnknownError`，**不降级为内存确认**（`ingest/app/redis_store.py:367-368`） |
| 成功 ACK 标记 | 无边缘 ACK 链路 | 成功 ACK 带 `durability=redis-aof`（`ingest/app/schemas.py:150`）；新边缘拒绝缺该标记的成功 ACK（`edge/app/uploader.py` 的 `_upload_records()` 中 `if result.get("durability") != "redis-aof":` 这一判断；该文件正被并行整改、行号不稳定，故只引函数名与语句，不引行号） |
| Stream 清理 | **仅在生效的 `redis.stream_maxlen <= 0` 时**不按 MAXLEN 裁剪（**不是无条件**，见 §3 条件限定）；Writer 成功入库或明确隔离 DLQ 后才确认 | 同左（Ingest 侧另有其自身的 `stream_maxlen` 开关，见 §3） |
| 交付 ≠ 入库 | Redis 持久接收 ≠ TDengine 最终入库 | 同左 |

> **易被误读的陷阱（必须写清）**：`collector/main.py:20` 确有 `import sqlite3`，
> 但它**只**服务于 `:117` 的**只读**表结构探查（`mode=ro&immutable=1`），
> 供 `_check_legacy_sampling_outbox()`（`:97-129`，在 `:142-143` 中心分支构造时调用）在**旧中心采样队列仍有未决数据时拒绝启动**。
> **它不代表中心使用 SQLite Outbox。**

## 2. 中心式（现行）

- 中心式采集（PLC/OPC 轮询与 HTTP 采集）在解析/分组后**直接批量写 Redis**（latest / window / Stream）：
  不经本地 SQLite、不做持久回放、不维护采样 receipt/session/seq、**不逐批等 `WAITAOF`**
  （`collector/main.py:182-192`）。该形态已被钉成防复发断言：`collector/tests/test_central_redis_only_default.py:78-96`。
- **接收确认语义**：中心式没有独立的「Ingest 接收确认」环节，写入 Redis 即完成中心侧交付。
  本文件**不对中心式承诺 AOF 级持久确认**——中心直写不等 AOF fsync
  （`RedisWriter.storage_path == "redis_only"`，`collector/tests/test_central_redis_only_default.py:114`）。
- 中心式没有本地采样队列，因此 §4 中「队列 50,000 条 / 页面 1 GiB / 磁盘低 256 MiB 拒收」等中心侧边界
  **对现行中心式不适用**（那些参数属已撤销的 `CollectorRetryOutbox`）。
- 与 TDengine 的边界：Redis 持久接收 ≠ TDengine 最终入库；坏数据可能进入 DLQ，需运维处理。
- 迁移遗留：若旧中心遗留 `runtime/collector-retry.db` 仍有未决行，中心**拒绝启动**而不是静默切换
  （`collector/main.py:97-129`）。这是遗留处置路径，不是现行写入路径。

## 3. 分布式（现行）

- 链路：边缘 Edge Collector → Edge Storage(本地 SQLite Outbox) → Uploader → 中心 Ingest → Redis → Writer → TDengine。
- 边缘本地 SQLite Outbox 使用 WAL + `synchronous=FULL`；成功返回表示本地事务已提交。
  已持久确认的 sent 记录默认额外保留 24 小时；该留存是运维缓冲，不是可靠性证明或自动对账机制。
- **中心接收确认选择 Redis 持久接收，不是 TDengine 最终入库确认。** 中心 Ingest 在**同一非事务 pipeline 连接**上
  执行 Lua 与 `WAITAOF 1 0 2000`；只有本地 AOF 确认成功（`numlocal >= 1`）才返回成功结果。
  失败或不支持 `WAITAOF` 时返回 `commit_unknown`，边缘保留副本重试（`ingest/app/redis_store.py:356-368`）。
- 成功 ACK 带 `durability=redis-aof`。新边缘不接受缺少该标记的成功 ACK，避免旧中心只确认内存就触发边缘清理。
  必须先升级中心（此处的「中心」指**分布式中心 Ingest**），再升级边缘。
- 边缘本地容量与失败边界：磁盘水位按**使用率百分比**判定（`>= 70%` warning / `>= 85%` critical / `>= 95%` overflow，
  `overflow` 时拒绝新的持久数据）。该逻辑位于 `edge/app/outbox.py` 的 `_disk_status()` 与 `_ensure_disk_writable()`；
  **该模块正被并行整改、行号不稳定，故本文件只引函数名、不引行号**。本地事务提交前的进程退出、硬件损坏、磁盘丢失、不遵守 fsync 的设备、
  人工删除数据、切换到未同步副本，均不在此保证内。
- **「不按 MAXLEN 裁剪」是带条件的，不是无条件承诺**（`stream_maxlen = 0` 才成立）：
  - **中心式直写（`RedisWriter`）**：仅当**生效值** `redis.stream_maxlen <= 0` 时不给 `XADD` 传裁剪参数 ——
    `collector/storage/redis_writer.py` 的 `_stream_trim_kwargs()`：`<= 0` 返回 `{}`，`> 0` 返回
    `{"maxlen": …, "approximate": True}`，由紧邻的 `pipe.xadd(...)` 使用。
    生效值优先级为「中心 MySQL `collector_setting.stream_maxlen` **>** `settings.toml` **>** 代码默认」
    （`collector/core/config_db.py` 的 `load_config()` → `_load_stream_maxlen()`）。
    代码默认值确为 `0`（`collector/core/config.py:78`；`collector/config/settings.toml.example:50` 注「0=不主动裁剪」），
    且 `collector/core/config_validator.py` 明确 `stream_maxlen > 0` 是**有损应急上限**；
    **但安装包为中心式铺的 `settings.toml` 模板是 `50000`**（`installer/templates/collector-settings.toml.example:39`，
    由 `installer/DataWatchRole.iss` 的 `ProvisionRoleConfig` 对 `centralized` 角色 `CopyIfAbsent` 到
    `…\collector\config\settings.toml`），中心后台默认值也是 `50000`
    （`backend/app/services/collector_config.py` 的 `DEFAULT_STREAM_MAXLEN`、`backend/app/models/collector.py` 的默认列值）。
    ⇒ **「不裁剪」只在生效值为 `0` 时成立；装好的中心机器默认是裁剪的（近似上限 50000/shard）。**
  - **分布式 Ingest**：Lua 内确有近似裁剪分支（`stream_maxlen > 0` 时 `XTRIM … MAXLEN ~`，
    `ingest/app/redis_store.py` 的 `INGEST_BATCH_LUA`），但现行**唯一**提交调用点 `process_batch()` 把该参数
    **硬编码为 `"0"`**（同行注释 `never trim unconsumed data`）；`INGEST_STREAM_MAXLEN` 虽被读取
    （`ingest/app/config.py:48`，默认 `0`）却未传入脚本（清单条目 B27 跟踪该配置未生效）。
    故**现行 Ingest 路径实际不发生裁剪**；B27 若落地，本句须同步更新。
  - **行号易变处一律以函数名/语句为准。**
- **确认与清理**：Writer 只有成功入库或明确隔离到 DLQ 后才确认，
  正常清理由 Writer 负责。Redis noeviction 拒写后，上游积压保留。

## 4. 已撤销方案：中心 Durable（SQLite Outbox + 逐批 WAITAOF）—— Superseded

> **状态：`Superseded`（已撤销）**，不再是任何生产路径。
>
> **撤销依据**：中心默认分支已改为 `RedisWriter` 直写（`collector/main.py:52`、`:181-192`）；
> `collector/tests/test_central_runtime_redis_only.py:81-85` 把 `DurableRedisWriter.__init__` 与
> `CollectorRetryOutbox.__init__` 替换成「调用即抛 `AssertionError`」后，真实 `CollectorApp`（**不传** `writer_factory`）
> 仍能跑完一轮采集 → 解析 → 分组 → Redis 写入 → 关闭（同文件 `:100` 构造 `CollectorApp` 且不传 `writer_factory`）。
> 相关组件保留在仓库内**仅供历史诊断与遗留处置**：`collector/storage/durable_redis_writer.py:190`
> （`class DurableRedisWriter(RedisWriter)`）、同文件 `:467`（`pipe.execute_command("WAITAOF", 1, 0, 2000)`）。
> 撤销记录见 `docs/06-验证记录/2026-09/central-runtime-fix-20260927.md:21`。

以下为**被撤销方案当时的口径原文**（保留原文，勿再当作当前实现）：

1. 原文：「集中式 Collector 的轮询和 HTTP 采集先写本地 SQLite 队列，使用 WAL + synchronous=FULL。保存原始点值、质量、时间戳、配置版本；成功返回表示本地事务已提交。后台独立线程批量重放，因此重启后即使没有新采样也能排空积压。」
   - **现行差异**：中心式**不构造**任何采样 SQLite 队列，也**无**后台重放线程。
2. 原文：「集中式 Redis 出口也在同一连接中对批量帧执行 Lua + WAITAOF，全部成功后才删除本地队列记录。原帧 ID 用于 Redis 重放去重，去重记录保留 7 天；超过该期限允许重复投递，历史仍使用原采样时间戳。保证为至少一次，而非严格恰好一次。」
   - **现行差异**：中心式不发起 `WAITAOF`、没有「删除本地队列记录」这一步；该段描述的是 `DurableRedisWriter`（`:467`）。
3. 原文：「集中式队列默认最多 50,000 条，数据库页面最多 1 GiB，并在磁盘可用空间低于 256 MiB 时拒绝新样本。满载不会删除既有未确认记录；新样本无法持久化会明确报错，因此不承诺无限断网期间零丢失。WAL、文件系统与其他进程仍有额外磁盘开销。」
   - **现行差异**：这些参数属 `CollectorRetryOutbox`（`collector/storage/collector_outbox.py:112`、`:186`、`:334`），中心式已不构造该类。
4. 原文：「Collector 队列位于 DATAWATCH_DATA_ROOT（兼容 DATAWATCH_HOME）下 runtime/collector-retry.db；默认 C:\ProgramData\DataWatch。」
   - **现行差异**：中心式**不再创建**该库；该路径现仅出现在遗留启动检查与遗留诊断语境（`collector/main.py:97-101`）。

## 5. 部署要求

1. **分布式**：Redis **7.2 或更新版本**（`WAITAOF` 自 Redis 7.2 引入），开启 AOF，持久化目录放在可靠持久卷中，
   ACL 允许 `WAITAOF`。仓库配置使用 `everysec`，但成功确认还额外等待实际 AOF fsync。
2. **中心式**：**不需要** `WAITAOF` ACL 授权——中心直写不等待 AOF fsync。Redis 侧仍应按运维要求开启持久化，
   但其丢失窗口**不由本文件承诺**为 AOF 级确认。
3. Redis 版本不足、AOF 关闭或落盘超时会保留上游积压，不降级成不可靠成功。
   不要在未迁移现有 RDB 数据的情况下直接重建 Redis 容器；按 Redis 官方 AOF 迁移流程验证并备份。
4. 升级现有系统前的内存 ACK 和此前已删除副本不能追溯修复。新保证从双方升级并成功收到新 ACK 后开始。
5. **分布式**：配置数据目录应使用独立可写目录。（原第 4 条「Collector 队列位于……runtime/collector-retry.db」
   的中心式路径要求已随该方案撤销，见 §4。）

## 6. 验证边界

- **中心式（现行）**：`collector/tests/test_central_redis_only_default.py`（导入面、默认分支、无采样 Outbox、
  `writer_factory` 边界、`storage_path` 语义）与 `collector/tests/test_central_runtime_redis_only.py`
  （真实 `CollectorApp` 运行、`_durable_threads() == []`、`WAITAOF` 调用计数前后不变）。
  二者在未配置隔离 Redis 时**跳过**，不触碰现场栈。
- **分布式（现行）**：Ingest 的 AOF 门禁（`ingest/tests/test_redis_store.py:33` 断言 `("WAITAOF", 1, 0, 2000)`）、
  边缘有序 ACK（`edge/tests/test_uploader.py:62`）与「仅内存 ACK 时保留本地积压」
  （同文件 `:304` `test_memory_only_ack_retains_local_backlog`）。
- **已撤销方案的回归项**（「AOF 超时保留 / 重启原样重放 / 并发重放互斥 / 满载不逐出」）属
  `collector/tests/test_collector_outbox.py` 等中心 Outbox 测试，**对现行中心入口不再适用**，仅对遗留诊断有意义。
- 真实 Redis / TDengine 故障注入与磁盘断电测试须在隔离环境验收，不能将 mock 测试称为现场零丢失验收。
