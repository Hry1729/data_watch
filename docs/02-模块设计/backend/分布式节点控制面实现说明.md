# 分布式节点控制面实现说明

> 对应《分布式部署架构方案》阶段 1 至阶段 4 的中心控制面。

## 1. 管理接口

- `POST /api/distributed/nodes/registration-codes`：管理员创建一次性注册码。
- `GET /api/distributed/nodes`：查询节点审批、在线状态、配置版本、Collector/Storage/Uploader 状态和积压。
- `PATCH /api/distributed/nodes/{node_uuid}/status`：批准或吊销节点；吊销与退休 active/preparing assignment 在同一事务完成。
- `PUT /api/distributed/nodes/{node_uuid}/assignments`：以 `deviceIds` 作为该节点的完整目标集合，支持空集合撤销和跨节点迁移。已分配后被停用的设备保留归属；新节点不能选择已停用或已被其他节点占用的设备。
- `PATCH /api/distributed/nodes/{node_uuid}/settings`：设置可选 `readTimeoutMs`；传 null 恢复协议驱动默认，每次修改递增节点 config version。

管理接口沿用中心 Backend 用户认证，仅 `R_SUPER`、`R_ADMIN` 可访问。

## 2. 边缘控制面接口

- `POST /api/distributed/edge/register`：一次性注册码注册。
- `POST /api/distributed/edge/{node_uuid}/heartbeat`：签名心跳并获取 desired revision。
- `GET /api/distributed/edge/{node_uuid}/config`：签名获取配置快照。
- `POST /api/distributed/edge/{node_uuid}/rotate-key`：用当前密钥签名提交新公钥；旧钥仅可在 5 分钟内幂等重试同一新公钥。

注册公钥必须是合法 Ed25519 公钥。注册重试仅在注册码、node_uuid 和公钥三者与已提交记录一致时幂等返回；其他复用一律拒绝。

心跳、配置和轮换请求使用方法、路径、时间戳、nonce、规范 JSON SHA-256 组成签名消息。中心验证已批准节点 current/previous 公钥，并通过 Redis `SET NX EX` 拒绝 nonce 重放。previous key 仅在轮换宽限期有效；规范 JSON 使用 UTF-8 原文编码，中文错误信息与边缘签名保持一致。

节点列表同时展示 Collector/Storage/Uploader 进程状态、Storage 队列深度、提交 P99、错误数、outbox 积压、SQLite 字节数、磁盘使用率、70%/85%/95% 水位、累计丢弃数和 key_version；这些是心跳监控快照，不参与 Ingest high_watermark 裁决。

## 3. 配置快照

中心 MySQL 是设备拓扑和 assignment 的权威源。快照包含设备及其 `enabled` 状态、已启用点位、可配置 `scan_rate_ms`、assignment epoch/status、`collect_from_ms`、`collect_until_ms`、config version、可选 `read_timeout_ms` 和 SHA-256 checksum。边缘 checksum 校验通过后才由 Storage 在单个 SQLite 事务中切换。

设备的“归属”和“启停”是两个维度：停用设备不会从现有 assignment 删除，快照继续携带该设备但 `enabled=false`，边缘保留展示并停止采集；重新启用后沿用原归属恢复采集。分配弹窗应展示当前节点全部已分配设备，停用项显示为不可新选但不得在确认时被隐式删除；已归属其他节点的设备同样不可选择。

Backend 的普通新增、Excel 导入和模板导入统一先分配 point group/TDengine 列位，并在同一事务插入 `device_variable` 与永久 `point_storage_mapping`。DB6 未启用的中心式库保持原行为；DB6 已启用后，point 的 `var_type`、设备类型及完整物理坐标不可原地改变，需软删旧 point 后创建新 point id。点位删除只软删采集配置；存在永久 mapping 的设备禁止物理删除，应改为停用，避免离线补传失去解码坐标。

本实现没有固定 200ms 采集或上传默认值。Uploader 节拍由边缘当前已启用 assignment 的最小有效 `scan_rate_ms` 动态计算。分布式中心节点页可编辑 `read_timeout_ms`；留空沿用协议驱动默认，允许大于 `scan_rate`，同设备仍保持单请求在途。
## 4. 设备迁移与时钟门禁

分配入口只接受 `approved` 节点；目标节点 `clock_anomaly=1` 时拒绝分配和迁移。请求在一个 MySQL 事务中锁定目标设备和当前 active assignment：未归属设备直接创建 active epoch；跨节点迁移把旧 epoch 标为 retired 并创建下一 active epoch；目标集合中被移除的设备进入计划撤销。

中心显式使用 UTC+8 解释 MySQL `DATETIME`。迁移 `cutover_at` 取中心当前时间加 60 秒，`grace_until` 再延后 5 分钟；新 owner 的 `collect_from_ms=cutover-30s`，有继任 owner 的旧节点 `collect_until_ms=cutover+30s`，无继任 owner 的撤销在 cutover 停采。旧、新节点的 config revision 在同一事务中分别递增。

Ingest 继续按样本时间执行严格时间窗：旧 epoch 只接受 `ts < cutover_at`，新 epoch 只接受 `ts >= cutover_at`；Stream 和 Writer 契约不增加 epoch 字段。
