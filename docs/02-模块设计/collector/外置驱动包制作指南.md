# 外置驱动包（ZIP）制作指南

> 面向协议开发者：如何从零制作、打包、安装、升级一个可冷加载的外置驱动。  
> 产品口径统一称「驱动 / 驱动包」，不另设「插件管理」入口。

相关设计见：[调用链与协议设计](调用链与协议设计.md)。
样板包见：仓库 `packages/modbus_tcp/`。

---

## 1. 适用场景

- 新增非内置协议（例如 Modbus TCP 试点），希望通过 App「驱动管理」安装 ZIP，由 Agent 落盘并冷重启 collector 加载。
- 不适用于：改调度器、写 Redis、连 MySQL、替代内置 S7/GE/OPC 路径（那些仍走内置驱动扩展，见 [collector README §11.2](README.md)）。

安装后落盘位置：

```text
%DATAWATCH_DATA_ROOT%\drivers\<id>\
```

默认数据根多为 `C:\ProgramData\DataWatch`。

---

## 2. 目录与 ZIP 布局

### 2.1 源码目录（推荐放在 `packages/<id>/`）

```text
my_proto/                      ← 包根目录名必须等于 id
  driver.toml                  ← 必填清单
  my_proto/                    ← Python 顶层包名必须等于 id
    __init__.py
    driver.py                  ← 含 create_driver(...)
    planner.py                 ← 声明 batch_* 时需要
    ...
  vendor/                      ← 可选：钉死的纯 Python 依赖
  vendor_meta.toml             ← 有 vendor 时建议提供（版本/许可/哈希）
```

### 2.2 ZIP 约束（Agent 静态校验）

| 规则 | 说明 |
|------|------|
| 唯一包根 | ZIP 内恰好一个顶层目录，名 = `id`；不得夹带散落文件 |
| 必须有清单 | 包根下存在可读的 `driver.toml` |
| 大小上限 | ZIP ≤ 50MB；单文件解压 ≤ 20MB；解压总量 ≤ 100MB；条目 ≤ 5000 |
| 路径安全 | 禁止 `..`、绝对路径、符号链接、路径穿越 |
| 名称冲突 | 条目经 NFC 规范化后不得大小写碰撞、前缀冲突 |
| 安装阶段 | 只解压与静态校验，**不** import / 不执行驱动代码 |

推荐用 PowerShell 打包（会把文件夹名打进 ZIP，正好满足唯一包根）：

```powershell
$src = "D:\python\device_alarm\data_watch\packages\my_proto"
$out = "D:\python\device_alarm\data_watch\packages\my_proto-1.0.0.zip"
if (Test-Path $out) { Remove-Item $out -Force }
Compress-Archive -Path $src -DestinationPath $out
```

不要手动把多个平级文件夹塞进同一个 ZIP，也不要只压缩包根**内部**文件导致缺少顶层目录名。

## 3. `driver.toml` 契约

### 3.1 最小示例

```toml
manifest_version = 1
driver_api = "1.0"

id = "my_proto"
protocol = "my_proto"
name = "我的协议"
description = "……"
version = "1.0.0"
entry = "my_proto.driver:create_driver"

python_abi = "cp314t"
os = ["windows"]
architectures = ["x86_64"]

capabilities = [
  "poll",
  "read",
]

read_write = "只读"
```

### 3.2 必填字段

| 字段 | 约束 |
|------|------|
| `manifest_version` | 第一期固定 `1` |
| `driver_api` | 第一期固定 `"1.0"` |
| `id` | `[a-z][a-z0-9_]{1,63}`，与包根目录名、Python 顶层包名一致 |
| `protocol` | 写入 MySQL `comm_protocol.protocol`；与设备绑定一致 |
| `name` / `description` | 产品展示文本 |
| `version` | SemVer `x.y.z`；同版本内容覆盖会被拒绝，升级必须升版本号 |
| `entry` | `package.module:function`；顶层包名必须 = `id`，且模块在包内 |
| `python_abi` | 必须匹配现场 collector；当前为 **`cp314t`**（CPython 3.14 free-threaded） |
| `os` / `architectures` | 至少包含当前平台：`windows`、`x86_64` |
| `capabilities` | 非空；只能使用平台已知枚举（见下表） |
| `read_write` | `只读` 或 `读写`；不得与能力声明矛盾（只读时不能声明 `write`） |

### 3.3 能力枚举

| 能力 | 含义 |
|------|------|
| `poll` | 周期轮询 |
| `read` | 读取 |
| `write` | 写入 |
| `batch_contiguous` | 同区域连续地址合并 |
| `batch_random` | 一次请求读多个非连续项 |
| `health_check` | 实现有效的 `ping()` |
| `native_quality` | 可返回原生质量码 |
| `source_timestamp` | 可返回设备源时间 |

能力用于配置、任务规划与 UI，**不以** `hasattr` 猜测。

只在协议**真的**能给出质量信息时才声明 `native_quality`。OPC DA / OPC UA 报文自带质量位，
适合声明；Modbus TCP、S7 这类协议只有「读到」和「读失败」两种结果，没有质量位，
声明了也只能填假的 `Good`——反而让上层以为质量经过判定。样板 `packages/modbus_tcp`
因此只声明 `["poll", "batch_contiguous", "read"]`。不声明时平台把成功标量归一为
`Good`，语义与自己填 `Good` 一致，但不会误导排障。`source_timestamp` 同理：
协议不回设备时间就不要声明。

### 3.4 与内置协议的冲突

`protocol` / `id` **不得**占用内置协议名及其别名，例如：

- `s7` / `snap7`
- `ge_srtp`
- `opcua`
- `opcda_*` 等中心/外部推送类协议

历史库里的 `SNAP7` 等别名由 Backend/catalog 映射到内置，**新外置包不要再使用这些名字**。

可选字段 `min_collector_version`：SemVer `x.y.z`，声明本驱动要求的最低 collector 版本。
加载时与 `collector/core/version.py` 的 `__version__` 比对，现场 collector 偏低则该包
单独进入 `manifest` 校验失败（不影响其他驱动）。缺省表示不限制。用到新契约（如
`DriverSample`）的驱动应声明它，否则装到旧 collector 上会以更难排查的方式失败。

可选扩展字段（设计已预留，按需声明）：`address_schema`、`config_schema`、`planner` 等，格式同 `entry`（`包.模块:符号`）。

## 4. 驱动 API（工厂与类）

### 4.1 工厂签名（冻结）

```python
def create_driver(context: DriverContext) -> BaseDriver:
    ...
```

`DriverContext` 由平台注入，仅含允许依赖，例如：

- `protocol` / `driver_id` / `driver_version` / `driver_api`
- `logger`
- `read_executor`（同步协议库时可借用有界线程池）
- `data_root`（只读数据根）

### 4.2 `BaseDriver` 最小 ABI

须实现（与内置驱动一致的语义）：

- `connect(config)`
- `disconnect()`
- `read(blocks)` → `Dict[address, value]`（键为**原始点位 address**）
- `write(points)`（只读驱动可按基类约定拒绝或不声明 `write`）
- 可选：`ping()`、`reconnect(config)`

未声明 `native_quality` 时，`value` 保持裸标量或连续块列表，平台按 `Good`
处理。声明 `native_quality` 后，每个成功样本必须返回 `DriverSample`：

```python
from drivers.base import DriverSample

return {
    block.address: DriverSample(
        value=value,
        quality=platform_quality,
        source_timestamp=source_timestamp,
        protocol_quality=raw_protocol_quality,
    )
}
```

`quality` 必须是 `core.quality_codes` 中的平台质量码；`source_timestamp`
必须是 `datetime`。声明 `native_quality` 却返回裸值时，平台会保留数值但将质量
标记为 `ConfigDecodeError`，避免漏传质量被静默当成 `Good`。`value=None`
表示本轮无样本，不进入 Stream。

### 4.3 禁止事项

驱动**不得**：

- 自行创建调度器、写 Redis、访问 MySQL
- 改变 collector generation，或启动无法关闭的后台服务
- 永久污染 `sys.path`（vendor 仅导入期临时使用）
- 覆盖标准库、collector 模块或其他驱动包
- 现场联网 `pip install`（依赖打进 `vendor/`）

### 4.4 批读与解码

声明 `batch_contiguous` / `batch_random` 时：

1. 提供 planner（地址规划 / 合并读块）。
2. 提供 decoder（或注册适配层约定的解码入口）。
3. `read` 回结果键必须是**原始点位 address**，不要改成内部键，否则上层会丢点。
4. 声明 `native_quality` / `source_timestamp` 时，解码结果须带上对应字段。

未声明批读、也不提供原生质量时，可用默认标量适配（成功标量归一为 Good）。

非法地址/类型应在配置阶段暴露，使设备进入 `CONFIG_ERROR`（禁连、禁采、禁重连），而不是静默吞错。

## 5. 依赖（vendor）

第一阶段优先**自包含纯 Python** 依赖：

1. 将已验证版本的依赖放入 `vendor/`（参考 Modbus 的 pymodbus 钉死方式）。
2. 建议附带 `vendor_meta.toml` 记录版本、许可、哈希。
3. 注意：外置驱动经 `datawatch_ext.<id>` 隔离的是**驱动自身模块名**；第三方库仍进进程全局 `sys.modules`，**同一进程只能有一个版本**。不要假设多驱动可并行加载同一库的不同大版本。

原生扩展（`.pyd` / 带 ABI 的 wheel）必须与 `python_abi`（当前 `cp314t`）和 Windows x86_64 严格匹配；第一期优先纯 Python。

## 6. 从零制作新驱动（推荐流程）

1. **复制样板**  
   复制 `packages/modbus_tcp` 为 `packages/<你的_id>`，全局替换 id / protocol / 包名。

2. **填写 `driver.toml`**  
   按 §3 填齐必填字段；`python_abi` 先写成 `cp314t`；能力只声明真实实现的部分。

3. **实现工厂与驱动类**  
   在 `<id>/driver.py` 实现 `create_driver` 与 `BaseDriver` 子类；连接参数沿用设备配置字段约定（如 `ip`/`host`、`port`、协议特有字段）。声明 `native_quality` 时按 §4.2 返回 `DriverSample`。

4. **按需实现 planner**  
   声明了 `batch_*` 再做；否则先保证单点/简单 `read` 正确。

5. **本地单元测试**  
   在 `collector/tests/` 写测试：工厂创建 → `connect`/`read` → 断言 address→value；声明 `native_quality` 时同时覆盖 Good/Uncertain/Bad、源时间戳和非法质量码。不必先经 ZIP 安装。

   若要脱离 `collector/tests/` 单独跑驱动包自带的测试，注意 `drivers.base` 现在
   `from core.quality_codes import QUALITY_GOOD`，所以 `import DriverSample` 需要
   **collector 根目录**在 `sys.path` 上，光有 `drivers/` 不够：

   ```powershell
   $env:PYTHONPATH = "D:\python\device_alarm\data_watch\collector"
   python -m pytest packages\<你的_id>\tests
   ```

   在 collector 根目录下跑 `python -m pytest tests` 时 cwd 已注入，无需额外设置。

6. **打 ZIP**  
   使用 §2.2 的 `Compress-Archive`；检查 ZIP 内只有一层 `<id>/`。

7. **安装验证**  
   - App「驱动管理」需具备权限 `device_monitor:driver:manage`  
   - 选择 ZIP → Agent 静态校验 → 激活到数据根 → 冷重启 collector  
   - 列表状态应为已安装 / loaded（Backend 应写入 `comm_protocol` + `installed_driver`）  
   - 新建或编辑设备，绑定该 `protocol`，确认能采到点

8. **升级**  
   改代码后**升高 `version`**，重新打 ZIP 再装；同版本重复内容会被拒绝或幂等跳过。

9. **卸载**  
   无设备绑定该协议时可卸；卸载同样会触发 collector 冷重启。有绑定须先改设备协议或下线设备。

## 7. 安装链路与排障要点

```text
App 上传 ZIP
  → Agent 静态校验并解压到 staging
  → 激活到 DATAWATCH_DATA_ROOT/drivers/<id>
  → 冷重启 collector
  → Backend 注册 comm_protocol / installed_driver（生命周期）
```

常见问题：

| 现象 | 可能原因 |
|------|----------|
| ZIP 校验失败 | 包根名 ≠ id、缺 `driver.toml`、超大小、路径不安全 |
| 安装成功但「未注册」 | Backend 过旧或缺生命周期接口；或 Agent Token / Agent URL 配错 |
| 状态 load_failed | `entry` 导不进、ABI 不匹配、缺依赖、工厂抛错 |
| 设备采不到数 | 设备 `protocol` 与驱动 `protocol` 不一致；或 `read` 键不是原始 address |
| 权限不足 | 账号缺少 `device_monitor:driver:manage` |

安全提示：安装驱动等同于允许其在 **collector 进程内执行代码**。第一期仅接受管理员从受控来源上传的内部包，暂无第三方签名市场。

## 8. 发布前 Checklist

- [ ] 包根目录名 = `id` = Python 顶层包名  
- [ ] `entry` 指向包内工厂，格式 `包.模块:函数`  
- [ ] `python_abi = "cp314t"`（或与当前 collector 实测 ABI 一致）  
- [ ] `os` / `architectures` 覆盖现场平台  
- [ ] `protocol` 不与内置协议冲突  
- [ ] `capabilities` 与 `read_write`、真实实现一致  
- [ ] 批读能力已配齐 planner/decoder，且结果键为原始 address  
- [ ] 依赖已进 `vendor/`，无现场 pip  
- [ ] `version` 已按 SemVer 升级（若为升级包）  
- [ ] ZIP 仅一层包根，体积与条目在限制内  
- [ ] 本地测试通过；安装后 UI 显示已安装且设备可采集
