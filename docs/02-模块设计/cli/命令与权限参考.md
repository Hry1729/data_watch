# CLI 命令与权限参考

## 1. 命令形式

安装版统一使用：

```powershell
data-watch [全局选项] <命令组> <动作> [参数]
```

源码开发版将 `data-watch` 替换为 `python -m cli.main`。

全局选项必须出现在一级命令之前，例如：

```powershell
data-watch --profile production --pretty devices status --device QC100
```

## 2. 全局选项

| 选项 | 作用 |
|---|---|
| `--profile NAME` | 本次调用使用指定 Profile |
| `--api-url URL` | 临时覆盖 Backend 地址 |
| `--timeout SECONDS` | 临时覆盖 HTTP 超时，范围 0 到 300 秒 |
| `--pretty` | 格式化 JSON；自动化默认不要启用 |
| `--debug` | 内部错误额外返回异常类型，不输出堆栈 |
| `--dry-run` | 解析并验证写请求，但不发送 |
| `--select EXPR` | 对成功结果的 `data` 执行 JMESPath 投影 |
| `--idempotency-key KEY` | 写请求增加 `X-Idempotency-Key` 追踪头 |
| `--yes` | 显式确认无人值守高风险操作 |
| `--all-pages` | 自动聚合支持的分页 GET 接口 |
| `--max-items N` | 自动分页最大条数，默认 10000，最大 100000 |

## 3. 命令发现

```powershell
data-watch --help
data-watch devices --help
data-watch commands list
data-watch commands schema "history query"
data-watch auth capabilities
```

- `commands list` 返回全部叶子命令、参数和访问要求。
- `commands schema` 返回单个命令的参数类型、必填项、默认值和权限。
- `auth capabilities` 根据当前账号实时列出允许与拒绝的命令。

这三个命令是自动化程序的事实源。文档表格用于人工导航，不替代运行时 schema。

## 4. 完整命令组

当前共 128 个叶子命令。

| 命令组 | 叶子动作 | 主要访问边界 |
|---|---|---|
| `auth` | `login`、`logout`、`refresh`、`whoami`、`capabilities`、`change-password` | 登录公开，其余需登录 |
| `commands` | `list`、`schema` | 公开 |
| `config` | `show`、`set-url`、`profile list/create/update/delete/use` | 本机配置，公开 |
| `dashboard` | `overview`、`trend`、`device-types`、`connection-health`、`pipeline-health` | `device_monitor:dashboard:view` |
| `devices` | `status`、`list`、`get`、`groups`、`create`、`update`、`enable`、`disable`、`import`、`export`、`delete`、`delete-batch` | 状态用监控权限；目录/管理按 device 权限码 |
| `points` | `resolve`、`list`、`get`、`groups`、`variables`、`template`、`create`、`update`、`enable`、`disable`、`import`、`export`、`delete`、`delete-batch` | 解析满足 point/history/monitor/realtime 任一查看权限；管理按 point 权限码 |
| `realtime` | `tree`、`get`、`window`、`watch` | `monitor:view` 或 `realtime:view` |
| `history` | `devices`、`device-types`、`points`、`query`、`chart`、`raw`、`matrix`、`export`、`export-status`、`export-download` | 查询用 `history:view`，导出用 `history:export` |
| `system-alerts` | `summary`、`list` | 汇总用 dashboard 权限，列表用 log:view |
| `modules` | `status`、`collector`、`writer`、`rates`、`collector-config show/set` | 诊断用监控权限，修改用 `collector_config:update` |
| `drivers` | `list`、`options`、`register`、`uninstall`、`uninstall-status` | 查看或 manage 权限 |
| `nodes` | `list`、`occupancy`、`assignments`、`assign`、`unassign`、`assign-set`、`enable`、`disable`、`settings`、`registration-code`、`sync-device-status` | `R_ADMIN` 或 `R_SUPER` |
| `logs` | `list`、`stats`、`tdengine-files`、`tdengine-tail`、`policy show/set`、`debug enable/disable`、`cleanup` | 分别使用 log:view/policy/debug/cleanup |
| `users` | `list`、`get`、`create`、`update`、`enable`、`disable`、`reset-password`、`delete` | 对应 `system:user:*` |
| `roles` | `list`、`get`、`options`、`create`、`update`、`enable`、`disable`、`delete`、`grants get/set` | 对应 `system:role:*` |
| `menus` | `current`、`list`、`create`、`update`、`delete`、`permissions list/create/update/delete` | 对应 `system:menu:*`；当前菜单只需登录 |
| `system` | `health`、`compatibility` | 公开 |
| `update` | `check`、`download`、`apply`、`rollback` | 公开；应用和回滚需确认 |
| `doctor` | 根命令 | 健康/兼容性公开，存在凭据时附带认证检查 |
| `version` | 根命令 | 公开 |

## 5. 默认三级角色

默认角色只是初始授权模板，最终能力取决于账号收到的 `permission_code`。自定义角色可能跨越以下边界。

| 能力 | `R_USER` | `R_ADMIN` | `R_SUPER` |
|---|---:|---:|---:|
| 仪表盘、运行状态、实时、历史查询 | 是 | 是 | 是 |
| 模块和日志只读诊断 | 是 | 是 | 是 |
| 设备/点位配置管理 | 否 | 按授权 | 是 |
| 历史导出、驱动管理 | 否 | 按授权 | 是 |
| 边缘节点管理 | 否 | 是 | 是 |
| 用户、角色、菜单管理 | 否 | 否 | 是 |
| 日志策略、DEBUG、清理 | 否 | 通常否 | 是 |

CLI 的判断规则：

1. 读取 `/api/user/info.permissions`；
2. 对 `permissionsAny` 使用 OR 语义；
3. 对节点命令额外检查 `R_ADMIN` 或 `R_SUPER`；
4. 本地放行后 Backend 仍再次鉴权。

## 6. 业务查询示例

```powershell
# 设备启停与采集连接状态
data-watch devices status --device 桥吊100

# 点位全局唯一时可省略设备
data-watch realtime get --point DB1702.DBW0

# 同名点位使用现场设备名称限定
data-watch realtime get --device 轨道吊701陆侧 --point I101

# AI 友好的 10 秒有界窗口
data-watch realtime window --device QC100 --point CraneID --seconds 10 --max-events 100

# 历史查询；--point 可重复
data-watch history query --device AGV801 --point CraneID `
  --start "2026-08-12 09:00:00" --end "2026-08-12 10:00:00"

# 聚合所有分页并只返回设备名
data-watch --all-pages --max-items 5000 --select "list[].deviceName" devices list
```

## 7. 管理命令示例

复杂 JSON 可从文件或 stdin 输入：

```powershell
data-watch --dry-run devices create --file device.json
Get-Content device.json -Raw | data-watch --dry-run devices create --file -
```

节点分配有三种明确语义：

```powershell
# add：保留原分配并追加
data-watch nodes assign <node-uuid> --device AGV801 --confirm <node-uuid>

# remove：仅移除指定设备
data-watch nodes unassign <node-uuid> --device AGV801 --confirm <node-uuid>

# set：用给定列表精确替换全部分配
data-watch nodes assign-set <node-uuid> --device QC100 --device AGV801 --confirm <node-uuid>
```

## 8. 高风险确认

以下类型必须显式确认：

- 删除或批量删除设备、点位、用户、角色、菜单；
- 卸载驱动；
- 节点分配、精确替换、停用和关键设置；
- 用户/角色停用、密码重置、角色授权修改；
- 日志清理；
- CLI 更新应用与回滚。

交互调用优先使用命令自己的 `--confirm <资源标识>`。AI/无人值守调用只有在用户已明确授权具体写操作后才能增加全局 `--yes`；`--yes` 不是权限提升，也不会绕过 Backend 鉴权。

## 9. 告警边界

`system-alerts` 是系统日志事件，不是设备点位告警。当前禁止生成或查询以下不存在的能力：

- 点位阈值越限；
- 通讯中断告警状态机；
- bool 状态位告警；
- 告警确认、恢复和处置记录。

设备点位告警引擎独立立项完成后，才能增加对应 CLI 命令。
