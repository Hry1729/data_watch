# 登录与路由缺陷修复

> 状态：已修复并验证（vue-tsc 0 报错 + 浏览器实测）｜日期：2026-06-03
> 范围：登录页登录逻辑、HTTP 错误提示、滑块重置、前端静态路由 catch-all 命名
> 改动文件：`views/auth/login/index.vue`、`router/routes/staticRoutes.ts`、`router/guards/beforeEach.ts`

## 背景

登录页用户名控件为 `ElSelect`（`filterable + allow-create + default-first-option + clearable`，
下拉含「游客」与历史账号）。现场反馈：**下拉选「游客」能登录，手动打字输入自己的账号点登录无反应**；
排查中又连带暴露两个隐性缺陷与一个路由告警。以下逐项记录根因与修复。

---

## 问题一：手输账号点登录无反应（主缺陷）

**现象**：手动在用户名框打字输入账号后点登录，界面毫无反应；控制台打印 `{username: Array(1)}`。

**根因**：
- `{username: Array(1)}` 是 **Element Plus 表单 `validate()` 校验失败时 reject 出的「未通过字段」对象**，不是后端返回。
- `ElSelect` 在 `allow-create` 模式下，**纯打字未点选下拉新建项 / 未回车时，输入内容只是「筛选关键词」，不会写入 `v-model`（`formData.username`）**，于是 username 为空 → `required` 校验失败 → `validate()` 抛出该对象。
- 游客是下拉「点选」触发 `@change → onAccountChange`，`formData.username` 有值，所以能登录。

**修复**（`views/auth/login/index.vue`）：
- `ElSelect` 增加 `:filter-method="onUsernameFilter"`，用 `usernameQuery` ref 实时记录输入框关键词；
- 增加 `@clear` 与 `onAccountChange` 内同步 `usernameQuery`，避免残留旧关键词误登录；
- `handleSubmit` 校验前兜底回填：`formData.username = normalizeAccount(usernameQuery.value || formData.username)`。
  - 经浏览器实测，`usernameQuery` 在按键（含退格）时实时更新且能存活到提交，故让其**优先**，`formData.username` 仅兜底。

## 问题二：登录失败静默无提示

**现象**：原 `catch` 把非 `HttpError` 的异常统一 `console.error('[Login] Unexpected error')` 吞掉，用户看不到任何反馈。

**根因 / 事实**：
- HTTP 层 `handleError()` 总是抛 `HttpError`，且 `request()` 对 `HttpError` 已统一 `ElMessage.error`，即**密码错 / 网络错本就有弹窗**；真正静默的只有「表单校验失败」这条路径。

**修复**（`views/auth/login/index.vue`）：`catch` 改为三分支——
- `HttpError`：http 层已弹窗，跳过；
- 表单校验失败对象（`isFormValidateError` 判定：非 `Error` 实例的普通对象且值含数组）：字段下方已有行内红字，静默；
- 其余真实异常（含 `Error` 实例与非 `Error` 抛出值）：`ElMessage.error('登录失败，请检查账号密码或稍后重试')` 并记录日志。

## 问题三：登录成功后滑块重置空引用崩溃

**现象**：登录成功后控制台抛 `TypeError: Cannot read properties of null (reading 'reset')`（`resetDragVerify`）。

**根因**：登录成功 → `router.replace` 跳走 → 登录组件卸载 → 模板 ref `dragVerify` 变 `null` → `finally` 里 `dragVerify.value.reset()` 空引用。该崩溃在游客登录成功时同样会触发，只是手输登录此前走不到成功这一步未暴露。

**修复**（`views/auth/login/index.vue`）：`dragVerify.value?.reset()` 加可选链守卫。

## 问题四：路由 catch-all 与后端 `Exception404` 重名，致 `No match` 告警

**现象**：登出后再次登录（不刷新整页），控制台报
`[Vue Router warn]: No match found for location with path "/device-monitor/dashboard"`，但页面随后能正常落地。

**根因**：
- vue-router 仅在 `matched.length === 0`（**连 catch-all 都没匹配上**）时打该告警。
- 静态 catch-all `/:pathMatch(.*)*` 的 `name` 原为 **`Exception404`**（`staticRoutes.ts`），`createRouter` 时注册。
- 本项目为 **backend 权限模式**（`VITE_ACCESS_MODE=backend`），登录后守卫拉后端菜单动态 `addRoute`。后端菜单种子在 `Exception` 目录下含子项 **`Exception404`（`/exception/404`）**（`backend/app/services/auth_bootstrap.py`）。
- vue-router 规则：`addRoute` 一个**已存在 name** 的路由会先删旧的。`RouteRegistry.register()` 只校验顶级名（`Exception` 不存在→注册），其 children 里的 `Exception404` 在注册时**覆盖并移除了静态 catch-all**。
- 登出时 `routeRegistry.unregister()` 移除动态路由（含该 `Exception404`），但 vue-router **不会恢复被覆盖的静态 catch-all**。于是再登录时 catch-all 已不存在，业务动态路由又尚未注册完，`router.replace(redirect)` 短暂 0 匹配 → 告警；守卫随后注册路由并重导航 → 页面正常。
- 因此「首次刷新后登录」不报、「登出再登录」必报。

**修复**（重命名消除重名，治本）：
- `router/routes/staticRoutes.ts`：静态 catch-all 的 `name` 由 `Exception404` 改为 **`NotFoundCatchAll`**；
- `router/guards/beforeEach.ts`：`isStaticRoute()` 中排除 catch-all 的判断同步改为 `route.name === 'NotFoundCatchAll'`；
- `next({ name: 'Exception404' })`（业务 404 跳转）**保持不变**，继续指向后端菜单里的 `/exception/404` 页面；
- **不改后端菜单种子名**（数据库已有 `Exception404` 菜单记录及权限绑定，改动面更大）。

修复后：静态 catch-all 与动态 `/exception/404` 不再重名 → 登录注册动态路由时不会顶掉 catch-all → 登出后 catch-all 仍在 → 再登录无告警，且按 path 的 404 兜底恢复。

## 验收口径

- 手输账号 + 密码 + 滑块 → 点登录 / 回车，均能成功登录；
- 故意输错密码 → 有可见错误提示，而非「无反应」；
- 登录成功后控制台无 `reading 'reset'` 报错；
- 整页硬刷新后「登出 → 再登录」，控制台不再出现 `No match found for location with path "/device-monitor/dashboard"`；
- 「游客一键登录」「历史账号」「滑块验证」等既有功能不回退。
