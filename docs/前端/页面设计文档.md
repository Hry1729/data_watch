# 自动化码头设备数据采集与监控平台 - 页面设计文档

> **版本**: v3.0 (设备监控、实时监控与系统日志定稿)
> **更新时间**: 2026-05-23
> **变更说明**: 融入实时监控四段式布局、点位分组与双模式图表；系统日志拆分为管理页和日志终端，补充清理策略与 DEBUG 模式控制

---

## 一、页面整体规划

本平台共设计 **9 个核心页面**：

| 序号 | 页面名称 | 路由 | 核心功能 |
|------|---------|------|---------|
| 1 | 工作台（总览页） | `/device-monitor/dashboard` | 系统全局状态监控、关键指标展示、趋势分析 |
| 2 | 设备通讯 | `/device-monitor/monitor` | 一屏总览大量设备通讯状态，小卡片 + 呼吸灯，按类型分组、筛选、跳转实时监控 |
| 3 | 驱动管理 | `/device-monitor/driver` | 驱动信息展示、可用性巡检（只读） |
| 4 | 设备管理 | `/device-monitor/device` | 设备信息管理、分组筛选、批量操作 |
| 5 | 点位管理 | `/device-monitor/point` | 采集点位配置、设备关联、当前值预览 |
| 6 | 实时监控 | `/device-monitor/realtime` | 实时数据展示、状态监控、异常高亮 |
| 7 | 历史数据 | `/device-monitor/history` | 历史数据查询、可视化图表、数据导出 |
| 8 | 系统日志 | `/device-monitor/log` | 日志数据统计、管理、清理和 DEBUG 开关配置 |
| 9 | 日志终端 | `/device-monitor/log-terminal` | 面向实时排障，像终端一样实时观察日志流 |

#### 趋势图落地说明（2026-06-03）

「采集量 / 告警趋势」是本页唯一手动 `echarts.init()` 的图表（另外两个用封装组件 `ArtRingChart`/`ArtHBarChart`，自管尺寸）。针对两个问题做了修复：

- **首屏 / 切换时图表空白**（控制台报 `Can't get DOM width or height`）：根因是 keep-alive `onActivated` 后立刻 init，容器尚未布局出宽高，ECharts 以 0 尺寸创建且不再自动重测。
  修复：`ensureChart()` 在 `echarts.init()` 前先 `await nextTick()`，再用 `ResizeObserver` 等容器 `clientWidth/Height > 0`（最长 1500ms 超时则放弃返回 null，避免页面隐藏/异常时卡死）；`setOption()` **之前**补一次 `resize()` 让首绘读到最终尺寸（放之后会打断入场动画）。
- **切换时间范围时"点先蹦出、线后追"**：改为先画线、点后淡入——曲线 `showSymbol: false` + `animationDuration = TREND_LINE_DRAW_MS`（默认 500ms）只画线；线画完后用定时器把 `showSymbol` 切 `true`，数据点再淡入。每次重画前清掉上一次定时器避免叠加，`onDeactivated`/`onUnmounted` 一并清理。
- 时间切换按钮实际为「今天 / 24h / 7d」（`today` / `last24h` / `last7d`），布局图中的范围标识为示意。

#### 页面头部

| 区域 | 说明 |
|------|------|
| **左侧标题** | Device Monitor（英文小标题）/ 设备通讯（中文大标题） |
| **右侧统计卡片** | 4 个统计卡片：设备总数、在线、异常、离线（统一白底，数字按状态色区分） |
| **筛选区** | 无外层卡片，设备类型/状态下拉 + 关键字输入 + 重置按钮直接贴右上角，顶部/底部与统计卡对齐；输入框与按钮圆角 12px，与左侧卡片一致 |

#### 卡片内容说明

卡片刻意做小，**只显示设备编号**（不再有图标/名称/按钮/驱动/采集时间），靠颜色和呼吸灯传达状态：

| 字段 | 说明 | 样式 |
|------|------|------|
| **设备编号** | 经显示规则处理后的编号（见下表），居中 | 大字号，颜色随状态 |
| **状态配色** | 🟢 在线 / 🟠 异常 / 🔴 离线 | 整卡边框 + 背景按状态着色 |
| **离线呼吸灯** | 仅离线（红）卡片有呼吸动画，吸引注意 | `card-breathe` 4s 循环，多卡错相位 |
| **点击** | 跳转实时监控页，携带 deviceId | 整卡可点 |

#### 设备编号显示规则（`formatDeviceCode`）

| 规则 | 示例 |
|------|------|
| 去掉类型字母前缀，只留数字 | `qc100` → `100`、`agv801` → `801` |
| 轨道吊（asc）四位编号：末位 `1`→`L`、`2`→`S` | `asc7011` → `701L`、`asc7012` → `701S` |
| 无法匹配规则时按原编号显示 | — |

#### 设备分组（`groupedDevices`）

- 按 `deviceType` 分组渲染，每组一个小标题：**类型名 · N 台**。
- 一种类型卡片排满后换行再排下一类型；无类型归入「未分类」。

#### 状态判定规则（全系统统一）

基于「最近采集数据时间」`age = now - last_collect_time` 判定，阈值集中在后端 `app/core/status_thresholds.py`：

| 状态 | 条件 | 颜色 |
|------|------|------|
| 在线 online | `age ≤ 60s`（`ONLINE_MAX_AGE_SECONDS`） | 🟢 |
| 异常 unstable | `60s < age ≤ 120s`（`UNSTABLE_MAX_AGE_SECONDS`） | 🟠 |
| 离线 offline | `age > 120s` 或无数据 | 🔴 |

> catalog / dashboard / monitor / module_monitor 四个 service 统一 import 该模块，调阈值只改这一处。

#### 筛选功能

| 筛选项 | 说明 |
|--------|------|
| **设备类型** | 下拉选择（全部/桥吊/轨道吊/AGV 等） |
| **在线状态** | 下拉选择（全部/在线/异常/离线/未启用），映射到 `deviceStatus` + `connectStatus` |
| **关键字搜索** | 输入框，支持设备编号和名称模糊搜索 |

#### 功能说明

| 功能 | 说明 |
|------|------|
| **卡片展示** | `grid` 自适应列（`auto-fill`），一行约 14 个，一屏铺满 |
| **加载方式** | 一次拉取（`pageSize: 1000`）全量分组展示，**无分页** |
| **定时刷新** | 每 15s（`REFRESH_INTERVAL`）静默刷新设备状态与统计，不打断浏览 |
| **跳转** | 点击卡片跳转实时监控页面，携带 deviceId 参数 |

#### 数据依赖

| 数据项 | 数据源 | API |
|--------|--------|-----|
| 设备列表 | MySQL + Redis/TDengine 采集时间 | `fetchDeviceList()` |
| 设备类型选项 | MySQL | `fetchDeviceGroupTree()` |
| 统计数据 | MySQL | 根据 `fetchDeviceList()` 结果计算 |

#### 页面路由与菜单划分

---

#### 页面一：系统日志管理页

##### 页面布局与 6 个统计卡片
- **今日日志总数**：今日系统日志与操作日志总数，并对比昨日升降幅。
- **今日 WARN/ERROR 数**：错误日志数汇总，点击可快速对下方表格应用“异常日志”筛选。
- **DEBUG 记录状态**：展示当前 DEBUG 落库是否开启、剩余时长、操作人及原因。
- **日志总容量**：以进度条展示 `当前已用容量 / 上限容量`（例如 `642MB / 1024MB`），超过 80% 会高亮预警。
- **最近清理时间**：展示上次清理时间、删除条数和清理方式（自动/手动）。
- **采集运行摘要**：展示最近 1 小时 collector 报警数、设备离线数与采集状态。

##### 图表分析区
- **日志级别趋势图**：横轴为时间，按 INFO、WARN、ERROR、CRITICAL 分组展示最近 24 小时级别趋势。
- **日志类型占比图**：以饼图或环形图展示各业务模块类型（system、auth、operation、collect、storage 等）日志占比，支持点击图例联动筛选表格。

##### 表格与详情抽屉
- **ArtSearchBar 筛选栏**：支持时间范围、级别、类型、服务来源、设备/操作人、requestId/traceId 等精细筛选。
- **列表显示**：ERROR 和 CRITICAL 级别行浅红背景高亮，WARN 行浅黄背景高亮，点击行即可滑出右侧详情抽屉，展示结构化 JSON、TraceID 及关联操作。

##### 交互说明
- **终端主体**：纯黑背景，等宽字体。INFO 显示为蓝色，WARN 显示为黄色，ERROR 及以上以醒目红色闪烁高亮。
- **自动滚动与暂停**：默认随新消息滚动到底部；手动向上查看时自动暂停，点击“暂停”按钮可缓存日志，并显示“暂停期间新增 N 条”。
- **虚拟滚动限制**：内存中仅保留最近 1000 条日志流数据，防止 DOM 节点过多卡死浏览器。

#### 页面三：清理策略与 DEBUG 模式控制

##### 自动/手动清理设置
- **清理参数配置**（只对 `R_SUPER` 角色开放）：
  - 自动清理开关、保留天数（默认 7 天）、总容量上限（默认 1024MB）、每日清理时间。
  - 手动清理支持：按当前策略清理、清理指定时间范围之前的日志、强制清理最近 24 小时（需要勾选强制选项并手动输入“确认清理”）。

##### DEBUG 模式热开关
- 只有超级管理员可限时开启 DEBUG 落库，默认关闭以保护 MySQL 免受海量数据冲垮。
- 开启时须配置“开启时长”(默认 1 小时)与“开启原因”。开启后，页面顶部出现黄色状态条进行倒计时提醒；剩余 5 分钟以内时变为红色 Warn 预警，到期后自动关闭 DEBUG 落库。
