# 系统日志前端设计文档

## 一、设计目标

系统日志前端用于帮助运维、管理员和开发人员直观看到平台自身运行日志、用户操作审计和排障信息。页面不展示设备点位报警明细，而是聚焦 backend、collector、frontend 自身的启动关闭、错误、采集摘要、连接状态、登录操作、配置操作和日志清理记录。

设计目标：

- 一个页面可以像终端一样实时观察系统日志流。
- 一个页面可以作为日志管理台，提供统计、筛选、表格、详情、清理和策略配置。
- 支持 DEBUG 落库开关，默认关闭，遇到 bug 时由超级管理员限时开启。
- 普通用户可查看日志，超级管理员可清理日志和修改策略。
- 页面可以支撑日常运维、故障复盘、用户操作追踪和系统排障。

## 二、页面信息架构

建议在现有“系统日志”菜单下扩展为两个标签页，或拆成两个子页面：

- 日志终端：面向实时排障，像一个大的终端窗口，持续追加日志。
- 日志管理：面向历史查询和管理，包含统计卡片、趋势图、分类图、筛选表格、详情抽屉和清理工具。

如果第一阶段只保留一个路由 `/device-monitor/log`，可以在页面顶部使用 Tabs：

- `终端模式`
- `管理模式`
- `清理与策略`

## 三、页面一：日志终端页

### 3.1 页面定位

日志终端页用于排障现场观察，强调“持续流动、快速过滤、重点高亮”。它不是完整历史检索页，只保留最近一段时间或最近固定条数的日志。

### 3.2 布局

页面结构：

1. 顶部工具栏
   - 服务来源筛选：全部、backend、collector、frontend。
   - 日志级别筛选：DEBUG、INFO、WARN、ERROR、CRITICAL。
   - 类型筛选：system、auth、operation、collect、storage、frontend、security、alarm。
   - 关键词输入框。
   - 自动滚动开关。
   - 暂停 / 继续按钮。
   - 清空当前屏幕按钮，注意只清空前端显示，不删除数据库。
   - 复制可见日志按钮。
2. 状态条
   - 当前连接状态：连接中、已连接、已暂停、重连中、连接失败。
   - 当前显示条数。
   - 最后一条日志时间。
   - DEBUG 状态和剩余时间。
3. 终端主体
   - 黑底或深色背景，等宽字体。
   - 每条日志一行，级别用颜色区分。
   - ERROR / CRITICAL 行更醒目。
   - 关键词高亮。
4. 右侧或底部详情面板
   - 点击日志行后展开详情。
   - 展示结构化 JSON、异常堆栈、traceId、requestId、设备编号、操作人、耗时等。

### 3.3 日志行格式

默认格式：

```text
2026-05-06 14:20:31.123 | WARN | collector | collect | AGV801 | 采集周期延迟 1350ms | trace=abc123
```

字段顺序：

- 时间
- 级别
- 服务名
- 类型
- 设备编号或模块名
- 内容
- traceId / requestId 简写

### 3.4 交互行为

- 自动滚动开启时，新日志到达后滚动到底部。
- 用户手动向上滚动时，自动滚动临时暂停，并显示“已暂停自动滚动”。
- 点击“回到底部”后恢复自动滚动。
- 暂停后仍然可以后台缓存新日志，并显示“暂停期间新增 N 条”。
- 点击日志行打开详情面板，再次点击同一行关闭详情。
- 支持复制单行日志、复制 traceId、复制异常堆栈。
- 当 DEBUG 开启时，终端顶部出现明显状态条：`DEBUG 日志记录中，剩余 58 分钟`。
- 当 DEBUG 剩余时间小于 5 分钟时，状态条变为 WARN 样式，提示即将自动关闭。

### 3.5 性能要求

- 终端模式默认只保留最近 1000 条日志。
- 超过 1000 条时从头部丢弃前端内存数据，不删除数据库。
- 表现层建议使用虚拟滚动，避免大量 DOM 导致卡顿。
- 日志刷新可以使用 WebSocket、SSE 或短轮询，第一版可用 `sinceId` 短轮询实现。

## 四、页面二：系统日志管理页

### 4.1 页面定位

系统日志管理页用于历史查询、统计分析、详情查看和清理管理。它扩展当前 `frontend/src/views/device_monitor/log/index.vue` 的能力。

### 4.2 顶部统计卡片

建议展示 6 个卡片：

1. 今日日志总数
   - 展示今日 `operation_log + system_log` 总数。
   - 可显示较昨日变化。
2. 今日 WARN / ERROR 数
   - 展示 WARN、ERROR、CRITICAL 总数。
   - 点击后自动筛选异常日志。
3. DEBUG 状态
   - 显示开启 / 关闭。
   - 开启时显示剩余时间、开启人、原因。
   - `R_SUPER` 可从卡片进入开关弹窗。
4. 日志总容量
   - 展示当前日志总容量，例如 `642MB / 1GB`。
   - 接近阈值时显示 WARN 状态。
5. 最近清理时间
   - 展示上次清理时间、删除条数、触发方式。
6. 采集运行摘要
   - 展示最近 1 小时 collector WARN / ERROR 数、设备掉线数、采集摘要数。

### 4.3 图表区

建议包含两个图表：

1. 日志级别趋势图
   - 横轴为时间。
   - 按 INFO、WARN、ERROR、CRITICAL、DEBUG 分组。
   - 默认展示最近 24 小时。
2. 日志类型占比图
   - system、auth、operation、collect、storage、frontend、security、alarm 占比。
   - 点击图例时联动表格筛选。

### 4.4 筛选区

筛选项：

- 时间范围：开始时间、结束时间。
- 日志级别：DEBUG、INFO、WARN、ERROR、CRITICAL。
- 日志类型：system、auth、operation、collect、storage、frontend、security、alarm。
- 日志种类：全部、系统运行日志、用户操作日志。
- 来源：backend、collector、frontend、log-cleaner、collector-scheduler 等。
- 服务名：backend、collector、frontend。
- 设备编号：如 AGV801、QC100。
- 操作人：如 Super、Admin、User。
- 结果状态：success、failed、denied。
- requestId / traceId。
- 关键词：匹配 content、source、deviceCode、operatorName。

筛选行为：

- 点击搜索后刷新表格和统计。
- 点击重置后恢复默认最近 24 小时。
- 点击统计卡片或图表项时，自动回填对应筛选条件。
- 筛选条件应体现在 URL query 或页面状态中，方便刷新保留。

### 4.5 表格设计

表格列：

| 列 | 说明 |
| --- | --- |
| 时间 | 日志发生时间，精确到秒或毫秒 |
| 级别 | DEBUG / INFO / WARN / ERROR / CRITICAL 彩色标签 |
| 类型 | system / collect / storage 等彩色标签 |
| 种类 | 系统运行 / 用户操作 |
| 来源 | backend-api、collector-scheduler、frontend-runtime 等 |
| 服务 | backend / collector / frontend |
| 设备 | 设备编号，没有则显示 `-` |
| 操作人 | 用户操作日志显示操作人，系统日志显示 `system` 或 `-` |
| 内容 | 日志摘要，超长省略 |
| 结果 | success / failed / denied |
| 耗时 | durationMs / elapsedMs |
| requestId | 可复制 |
| 操作 | 查看详情、复制、按 traceId 筛选 |

表格行为：

- 默认按时间倒序。
- 默认分页 20 条，可切换 50、100。
- ERROR 和 CRITICAL 行使用浅红背景提示。
- WARN 行使用浅黄色背景提示。
- 点击 requestId / traceId 可一键筛选同链路日志。
- 内容列保留 tooltip，完整内容在详情抽屉展示。

### 4.6 详情抽屉

点击“详情”后打开右侧抽屉。

详情内容：

- 基础信息：时间、级别、类型、来源、服务、主机、设备、点位、操作人。
- 链路信息：requestId、traceId、IP、User-Agent。
- 操作信息：moduleName、actionName、bizType、bizId、resultStatus、durationMs。
- 结构化详情：格式化展示 `detail_json`。
- 异常堆栈：展示 `exception_stack`，支持复制。
- 关联操作：复制日志、复制 traceId、按 traceId 查询、按设备查询、按操作人查询。

异常堆栈默认折叠，避免页面过长。

## 五、清理与策略设计

### 5.1 清理入口

清理入口只对 `R_SUPER` 展示。入口位置：

- 日志管理页顶部工具栏。
- 日志总容量卡片。
- `清理与策略` Tab。

### 5.2 清理设置弹窗

字段：

- 自动清理开关。
- 保留天数，默认 7 天。
- 总容量上限，默认 1024MB。
- 每日清理时间，默认 03:00。
- 容量检查间隔，默认 30 分钟。
- 单批删除数量，默认 5000。
- 是否保留最近 24 小时，默认开启。

交互：

- 修改策略前需要二次确认。
- 保存成功后写入操作日志。
- 设置非法时前端直接校验，例如保留天数不能小于 1，容量上限不能小于 100MB。

### 5.3 手动清理弹窗

清理模式：

- 按当前策略清理。
- 清理指定时间之前的日志。
- 清理指定时间范围内的日志。
- 清理当前筛选结果。

保护规则：

- 默认不允许清理最近 24 小时日志。
- 如果范围包含最近 24 小时，需要勾选“强制清理最近 24 小时日志”。
- 强制清理需要输入确认文字，例如 `确认清理`。
- 清理执行前展示预计影响范围和当前筛选条件。

清理结果展示：

- 删除 operation_log 条数。
- 删除 system_log 条数。
- 清理前容量。
- 清理后容量。
- 耗时。
- 触发人。
- 清理任务日志 ID。

## 六、DEBUG 开关设计

### 6.1 权限

只有 `R_SUPER` 可以开启或关闭 DEBUG 落库。`R_ADMIN` 和 `R_USER` 只能查看 DEBUG 当前状态。

### 6.2 默认状态

DEBUG 默认关闭，不写入数据库。关闭时：

- 前端不显示 DEBUG 日志，除非历史里已有开启期间的 DEBUG 日志。
- backend / collector / frontend 的 DEBUG 可以继续写控制台或本地文件，但不落 MySQL。

### 6.3 开启弹窗

字段：

- 是否开启 DEBUG。
- 开启时长：30 分钟、1 小时、4 小时、自定义。
- 开启原因，必填。
- 影响范围：backend、collector、frontend，默认全部。

默认值：

- 开启时长 1 小时。
- 影响范围全部。

提示文案：

- DEBUG 会显著增加日志量，建议只在排障期间限时开启。
- DEBUG 到期后会自动关闭。
- 开启和关闭操作会被记录到系统日志。

### 6.4 DEBUG 状态展示

开启后需要在两个页面都展示明显提示：

- 顶部状态条：`DEBUG 日志记录中，剩余 58 分钟`。
- DEBUG 卡片：显示开启人、开启原因、开启时间、到期时间。
- 剩余 5 分钟以内变为 WARN 样式。
- 到期自动关闭后显示最近一次关闭时间。

### 6.5 DEBUG 验收

- 默认关闭。
- `R_SUPER` 可以开启并设置时长。
- 开启后日志列表可筛选到 DEBUG 日志。
- 到期后自动关闭。
- 关闭后新的 DEBUG 不再入库。
- 开启、关闭、到期自动关闭都有操作记录。

## 七、前端权限

| 能力 | R_USER | R_ADMIN | R_SUPER |
| --- | --- | --- | --- |
| 查看日志列表 | 是 | 是 | 是 |
| 查看日志详情 | 是 | 是 | 是 |
| 使用日志终端 | 是 | 是 | 是 |
| 查看统计卡片 | 是 | 是 | 是 |
| 导出日志 | 否 | 是 | 是 |
| 手动清理日志 | 否 | 否 | 是 |
| 修改清理策略 | 否 | 否 | 是 |
| 开启 / 关闭 DEBUG | 否 | 否 | 是 |
| 上报前端错误 | 是 | 是 | 是 |

前端应根据 `user/info.buttons` 或角色隐藏无权限按钮。后端仍必须做权限校验。

## 八、前端 API 契约

### 8.1 日志列表

`GET /api/device-monitor/log/list`

请求参数：

```ts
interface LogSearchParams {
  pageNo?: number
  pageSize?: number
  keyword?: string
  startTime?: string
  endTime?: string
  level?: 'DEBUG' | 'INFO' | 'WARN' | 'ERROR' | 'CRITICAL'
  type?: 'system' | 'auth' | 'operation' | 'collect' | 'storage' | 'frontend' | 'security' | 'alarm'
  kind?: 'all' | 'system' | 'operation'
  source?: string
  serviceName?: string
  deviceCode?: string
  operatorName?: string
  requestId?: string
  resultStatus?: 'success' | 'failed' | 'denied'
}
```

返回项：

```ts
interface LogListItem {
  id: number
  kind: 'system' | 'operation'
  time: string
  level: 'DEBUG' | 'INFO' | 'WARN' | 'ERROR' | 'CRITICAL'
  type: string
  source: string
  serviceName: string
  moduleName?: string
  actionName?: string
  operatorName?: string
  deviceCode?: string
  content: string
  resultStatus?: string
  durationMs?: number
  requestId?: string
  traceId?: string
  detail?: Record<string, unknown>
}
```

### 8.2 日志统计

`GET /api/device-monitor/log/stats`

返回：

```ts
interface LogStats {
  todayTotal: number
  todayWarnTotal: number
  todayErrorTotal: number
  todayCriticalTotal: number
  debugEnabled: boolean
  debugEnabledUntil?: string
  debugRemainingSeconds?: number
  totalSizeMb: number
  maxTotalMb: number
  lastCleanupTime?: string
  lastCleanupDeletedTotal?: number
  levelTrend: Array<{ time: string; level: string; count: number }>
  typeRatio: Array<{ type: string; count: number; ratio: number }>
  sourceRatio: Array<{ source: string; count: number; ratio: number }>
}
```

### 8.3 日志增量

第一版可以用短轮询：

`GET /api/device-monitor/log/list?sinceId=xxx&pageSize=200`

后续可升级为：

`GET /api/device-monitor/log/stream`

或 WebSocket：

`WS /api/device-monitor/log/ws`

### 8.4 日志策略

`GET /api/device-monitor/log/policy`

`PUT /api/device-monitor/log/policy`

```ts
interface LogPolicy {
  enabled: boolean
  retentionDays: number
  maxTotalMb: number
  cleanupTime: string
  capacityCheckIntervalMinutes: number
  batchSize: number
  debugDbEnabled: boolean
  debugEnabledUntil?: string
  debugReason?: string
}
```

### 8.5 DEBUG 开关

`POST /api/device-monitor/log/debug`

```ts
interface DebugSwitchPayload {
  enabled: boolean
  durationMinutes?: number
  reason?: string
  scopes?: Array<'backend' | 'collector' | 'frontend'>
}
```

### 8.6 手动清理

`POST /api/device-monitor/log/cleanup`

```ts
interface LogCleanupPayload {
  mode: 'policy' | 'beforeTime' | 'range' | 'currentFilter'
  beforeTime?: string
  startTime?: string
  endTime?: string
  kinds?: Array<'system' | 'operation'>
  force?: boolean
  filters?: LogSearchParams
}
```

### 8.7 客户端日志上报

`POST /api/device-monitor/log/client`

```ts
interface ClientLogPayload {
  level: 'DEBUG' | 'WARN' | 'ERROR' | 'CRITICAL'
  type: 'frontend'
  source: 'frontend-runtime' | 'frontend-http' | 'vue-error-handler'
  content: string
  detail?: Record<string, unknown>
  exceptionStack?: string
  routePath?: string
  userAgent?: string
  traceId?: string
}
```

## 九、交互状态

### 9.1 加载中

- 统计卡片显示骨架屏。
- 表格显示 loading。
- 终端页显示连接中状态。

### 9.2 空数据

- 表格空态文案：`当前筛选条件下暂无系统日志`。
- 终端空态文案：`暂无实时日志，等待系统事件产生`。

### 9.3 错误状态

- 查询失败：展示模块级错误提示和重试按钮。
- 终端连接失败：展示重连按钮和错误原因。
- 清理失败：展示后端返回错误，并保留清理参数方便重试。

### 9.4 无权限

- 无日志查看权限：显示无权限空态。
- 无清理权限：隐藏清理按钮。
- 无 DEBUG 权限：只显示 DEBUG 状态，不显示开关按钮。

### 9.5 清理中

- 清理按钮进入 loading。
- 弹窗显示清理进行中，不允许重复提交。
- 完成后展示清理结果，并刷新统计和表格。

### 9.6 DEBUG 已开启

- 顶部固定状态条提醒。
- 统计卡片展示剩余时间。
- 级别筛选中 DEBUG 可见并高亮。

### 9.7 DEBUG 即将到期

- 剩余 5 分钟以内，状态条变为 WARN 样式。
- `R_SUPER` 可点击延长时间。

## 十、验收标准

- 日志管理页可按时间、级别、类型、来源、服务、设备、操作人、requestId、关键词筛选。
- 日志表格支持分页、刷新、详情抽屉、复制 requestId / traceId。
- 统计卡片能显示今日日志数、异常数、DEBUG 状态、容量、最近清理时间。
- 趋势图和类型占比图能与筛选联动。
- 日志终端页能持续追加日志，支持暂停、自动滚动、关键词高亮、详情展开。
- `R_SUPER` 可打开清理设置、手动清理、开启和关闭 DEBUG。
- 普通用户和管理员看不到无权限操作按钮。
- DEBUG 默认关闭，开启后状态明显，到期自动关闭。
- 清理操作必须二次确认，完成后显示删除条数和容量变化。
- 前端全局错误能通过客户端日志接口上报，且上报失败不影响页面使用。

## 十一、实施建议

第一阶段建议只扩展现有系统日志页，先完成管理模式：统计卡片、筛选表格、详情抽屉、清理设置和 DEBUG 状态。第二阶段再增加日志终端页，并根据后端能力选择短轮询、SSE 或 WebSocket。

推荐实施顺序：

1. 扩展前端类型定义和 API 封装。
2. 扩展现有系统日志页筛选项和表格列。
3. 增加详情抽屉。
4. 增加统计卡片和图表。
5. 增加清理设置和手动清理弹窗。
6. 增加 DEBUG 开关和状态条。
7. 增加日志终端页。
8. 增加前端全局错误上报。
