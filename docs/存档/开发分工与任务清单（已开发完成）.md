# 开发分工与任务清单

> 对应设计文档：Redis 实时缓冲层与点位分组设计方案 v0.6  
> 项目规模：305 台设备，每台约 1000 点，支持扩展至单设备 5000+ 点  
> 文档用途：明确各模块开发边界、任务步骤、依赖关系，作为开发阶段的执行依据

---

## 一、模块总览与分工边界

| 模块 | 目录 | 职责边界 |
|---|---|---|
| **数据库初始化** | `scripts/` | MySQL schema 变更、数据迁移、TDengine 建表、Redis Consumer Group 初始化 |
| **采集模块** | `collector/` | 从 PLC 采集数据，写 Redis（latest / window / stream） |
| **入库模块** | `writer/` | 从 Redis Stream 消费，批量写 TDengine |
| **后端** | `backend/` | 提供 HTTP / WebSocket 接口，读 Redis（实时）/ TDengine（历史） |
| **前端** | `frontend/` | 实时监控页（WebSocket）、历史查询页 |

---

## 二、开发阶段与依赖关系

```
阶段 0：数据库基础
    ↓
阶段 1：采集模块（collector 写 Redis）
    ↓
阶段 2：入库模块（writer 消费 Stream 写 TDengine）
    ↓
阶段 3：后端接口（读 Redis 实时 + TDengine 历史）
    ↓
阶段 4：前端（WebSocket 实时 + 历史查询）
```

硬性依赖：

- 阶段 1 需要阶段 0 的 MySQL 点位分组数据和 Redis Consumer Group 就绪
- 阶段 2 需要阶段 0 的 TDengine 子表就绪，阶段 1 的 Stream 有数据
- 阶段 3 需要阶段 1、2 的 Redis / TDengine 数据存在
- 阶段 4 需要阶段 3 的接口完成联调
- 每个阶段启动前运行 `scripts/check_prerequisites.py`，确认所有前置资源就绪；不满足时打印缺失项并以非零退出码退出，阻止后续服务启动

### 任务 DB-1：MySQL 新增 device_point_group 表

**目标**：为每台设备的每个点位分组创建记录，固化列位分配。

步骤：

1. 在 MySQL 中执行建表 DDL：

```sql
CREATE TABLE IF NOT EXISTS device_point_group (
    id                  BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
    device_id           BIGINT UNSIGNED NOT NULL COMMENT '设备 ID',
    group_no            INT UNSIGNED    NOT NULL COMMENT '分组序号，从 1 开始',
    group_code          VARCHAR(16)     NOT NULL COMMENT '分组编码，如 g001',
    group_name          VARCHAR(64)              COMMENT '分组名称，可为空',
    max_point_count     INT UNSIGNED    NOT NULL DEFAULT 3072,
    active_point_count  INT UNSIGNED    NOT NULL DEFAULT 0,
    disabled_point_count INT UNSIGNED   NOT NULL DEFAULT 0,
    deleted_point_count INT UNSIGNED    NOT NULL DEFAULT 0,
    used_column_count   INT UNSIGNED    NOT NULL DEFAULT 0,
    next_column_index   INT UNSIGNED    NOT NULL DEFAULT 1,
    status              VARCHAR(16)     NOT NULL DEFAULT 'active' COMMENT 'active / full / disabled',
    config_version      INT UNSIGNED    NOT NULL DEFAULT 1,
    create_user         VARCHAR(64),
    create_time         DATETIME        DEFAULT CURRENT_TIMESTAMP,
    update_user         VARCHAR(64),
    update_time         DATETIME        DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (id),
    UNIQUE KEY uq_device_group (device_id, group_code),
    KEY idx_device_id (device_id)
```

### 任务 DB-3：数据迁移脚本（为存量设备初始化分组）

**目标**：为现有 305 台设备创建 g001 分组，按 var_seq 顺序分配 group_index 和 td_column_name。

步骤：

1. 编写迁移脚本 `scripts/migrate_point_groups.py`，逻辑如下：

> **幂等要求**：对每台设备，INSERT 前先查询 device_point_group 是否已存在该 device_id + group_code 记录，已存在则跳过 INSERT；device_variable 的 UPDATE 加条件 `WHERE td_column_name IS NULL`，已映射的点位不重复写入。脚本每次执行均输出 created / skipped 计数，可安全重复运行。

```text
FOR 每台设备 device:
    INSERT INTO device_point_group (device_id, group_no, group_code, ...)
    VALUES (device.id, 1, 'g001', max_point_count=3072, ...)

    FOR 每个点位 var (按 var_seq 排序):
        group_index = 点位在该设备中的顺序（从 1 开始）
        td_column_name = 'v' + str(group_index).zfill(4)
        UPDATE device_variable SET
            point_group_id = <新建分组 id>,
            group_index = group_index,
            td_column_name = td_column_name,
            enable = 1,
            deleted = 0
        WHERE id = var.id

    UPDATE device_point_group SET
        active_point_count = 点位总数,
        used_column_count = 点位总数,
        next_column_index = 点位总数 + 1,
        config_version = 1
    WHERE id = <新建分组 id>
```

2. 在测试库执行一次，验证：
   - 所有设备均有 g001 分组记录
   - 所有 device_variable 的 point_group_id、group_index、td_column_name 已填充
   - active_point_count = 实际点位数，不变式成立：
     `active + disabled + deleted <= used_column_count`

3. 在生产库执行，执行前备份 device_variable 表。

### 任务 DB-6：Redis Consumer Group 初始化脚本

**目标**：为每个 Stream 分片创建 Consumer Group，writer 启动前必须就绪。

步骤：

1. 编写脚本 `scripts/init_redis_consumer_groups.py`：

```python
import redis

r = redis.Redis(host=..., port=..., decode_responses=True)
device_types = ['qc', 'asc', 'agv']
group_codes = ['g001']
shard_count = 4

for dtype in device_types:
    for gc in group_codes:
        for shard in range(shard_count):
            key = f"rt:stream:{dtype}:{gc}:{shard}"
            try:
                r.xgroup_create(key, 'writer_cg', id='$', mkstream=True)
                print(f"created: {key}")
            except redis.exceptions.ResponseError as e:
                if 'BUSYGROUP' in str(e):
                    print(f"already exists: {key}")
                else:
                    raise
```

> **幂等要求**：`BUSYGROUP` 错误（Consumer Group 已存在）已捕获并记录日志，不报错退出。脚本可安全重复执行。

2. 执行并验证：`XINFO GROUPS rt:stream:qc:g001:0`，确认 Consumer Group 名称为 `writer_cg`。

### 任务 COL-2：新增 RedisWriter 模块

**目标**：封装写 latest / window / stream 的完整逻辑，供采集任务调用。

步骤：

1. 新增 `collector/storage/redis_writer.py`：

```python
class RedisWriter:
    def __init__(self, r: redis.Redis, config):
        self.r = r
        self.shard_count = config.redis.stream_shard_count  # 默认 4
        self._maxlen = config.redis.stream_maxlen            # 默认 500000

    def write_latest(self, device_code: str, group_code: str,
                     fields: dict[str, dict]) -> None:
        """fields: {var_id: {"v": str, "t": int, "q": int}}"""
        key = f"rt:latest:{device_code}:{group_code}"
        mapping = {str(k): json.dumps(v, separators=(',', ':'))
                   for k, v in fields.items()}
        self.r.hset(key, mapping=mapping)
        # 不设 TTL，由设备管理操作显式清理

    def write_window(self, device_code: str, group_code: str,
                     scan_rate_ms: int, frame: dict) -> None:
        """frame: 完整帧 JSON 对象"""
        key = f"rt:window:{device_code}:{group_code}:{scan_rate_ms}"
        pipe = self.r.pipeline(transaction=False)
        pipe.lpush(key, json.dumps(frame, separators=(',', ':')))
        pipe.ltrim(key, 0, 9)
        pipe.execute()

    def write_stream(self, device_code: str, device_type: str,
                     group_code: str, scan_rate_ms: int,
                     ts: int, config_version: int,
                     values: dict[str, str]) -> None:
        """values: {var_id: value_str}，已过滤 STRING 和 is_storage=0"""
        shard_no = hash(device_code) % self.shard_count
        stream_key = f"rt:stream:{device_type}:{group_code}:{shard_no}"
        maxlen = self._maxlen
        self.r.xadd(
            stream_key,
            {
                "device_code": device_code,
                "device_type": device_type,
                "group_code": group_code,
                "scan_rate": str(scan_rate_ms),
                "ts": str(ts),
                "config_version": str(config_version),
                "values": json.dumps(values, separators=(',', ':')),
            },
            maxlen=maxlen,
            approximate=True,
        )
```

2. 单元测试 `collector/tests/test_redis_writer.py`：
   - 测试 latest 写入后 HGETALL 能读到正确 JSON
   - 测试 window LTRIM 后长度不超过 10
   - 测试 stream XLEN 不超过 MAXLEN

3. 监控提示：collector 侧无需主动监控 Stream lag，但本地压测时可执行 `XINFO GROUPS rt:stream:qc:g001:0` 观察 `lag` 字段（消费滞后条数）。`lag` 持续增长说明写入速度超过 writer 消费速度，需调低 `interval_ms` 或扩容 writer 实例数。

### 任务 COL-3：采集任务层接入 RedisWriter

```text
  恢复采集
```

**目标**：重启后先清理上次未 ACK 的 pending 消息，再进入正常消费。

1. 启动函数 `drain_pending(r, stream_key, consumer_name)`：

### 任务 TD-4：正常消费主循环

**目标**：从 Stream 批量读取 → 按 stable 归并 → 批量写 TDengine → ACK。

步骤：

1. 消费循环核心逻辑：

```text
while running:
    entries = XREADGROUP GROUP writer_cg {consumer_name}
              COUNT {batch_count} BLOCK {flush_interval_ms/2}
              STREAMS {stream_key} >

    for entry_id, data in entries:
        解析 device_code, group_code, ts, config_version, values

        mapping = mapper.get_or_load(device_code, group_code, config_version)
        检查目标子表是否存在（轻量校验）
        → 不存在：记录 ERROR 日志，不 XACK，跳过此条

        将 (entry_id, ts, values, mapping) 加入 pending buffer

    if flush_interval 到期 or buffer 超过 max_buffer_rows:
        rows = 按 stable/child_table 归并 buffer
        写 TDengine（batch insert）
        if 写入成功:
            XACK 所有 entry_id
        else:
            不 XACK，记录错误，等待下次重试
```

2. 重试计数：使用 `XPENDING` 读取每条消息的 delivery-count，超过 `pending_max_retry` 时写入 DLQ 并 XACK。

3. 监控：定期执行 `XINFO GROUPS rt:stream:qc:g001:0`，关注 `lag` 字段（消费滞后条数）。`lag > 10000` 时触发告警，说明 writer 处理速度跟不上写入速度。

### 任务 API-4：WebSocket 推送服务

**目标**：后端维护服务端合并订阅，每个 device+group 只有一个 Redis 轮询任务，广播给所有订阅者。

1. 新增 `backend/app/services/ws_push.py`，实现推送管理器：

```python
class WsPushManager:
    def __init__(self):
        # key: (device_code, group_code) → set of websocket connections
        self._subscribers: dict[tuple, set] = {}
        self._tasks: dict[tuple, asyncio.Task] = {}
        self._snapshots: dict[tuple, dict] = {}  # 上次快照，用于 diff

    async def subscribe(self, ws, device_code: str, group_code: str):
        key = (device_code, group_code)
        self._subscribers.setdefault(key, set()).add(ws)
        if key not in self._tasks:
            self._tasks[key] = asyncio.create_task(
                self._push_loop(device_code, group_code)
            )
        # 首次订阅推送完整快照
        snapshot = await self._read_latest(device_code, group_code)
        await ws.send_json({"type": "snapshot", ...snapshot})

    async def unsubscribe(self, ws, device_code: str, group_code: str):
        key = (device_code, group_code)
        self._subscribers[key].discard(ws)
        if not self._subscribers[key]:
            self._tasks[key].cancel()
            del self._tasks[key]

    async def _push_loop(self, device_code: str, group_code: str):
        key = (device_code, group_code)
        while True:
            await asyncio.sleep(0.1)  # 100ms
            latest = await self._read_latest(device_code, group_code)
            diff = self._calc_diff(key, latest)
            if diff:
                await self._broadcast(key, {"type": "diff", "values": diff})
            elif self._is_offline(latest):
                await self._broadcast(key, {"type": "offline"})
```

2. WebSocket 路由：

### 任务 FE-1：WebSocket 连接管理

步骤：

1. 新增 `composables/useRealtimeWs.ts`，封装 WebSocket 连接、订阅、断线重连（指数退避）：

> **重连重订阅**：`onopen` 回调在每次连接建立（含重连）时发送 `subscribe` 消息，断线后自动恢复订阅，无需调用方处理。退避从 3s 开始，每次重连翻倍，上限 30s，连接成功后重置为 3s。

```typescript
export function useRealtimeWs(deviceCode: string, groupCode: string) {
  const values = ref<Record<string, PointValue>>({})
  const status = ref<'connecting' | 'online' | 'offline'>('connecting')
  let ws: WebSocket | null = null
  let retryDelay = 3000  // 初始退避时间（ms）

  function connect() {
    status.value = 'connecting'
    ws = new WebSocket('/ws/realtime')
    ws.onopen = () => {
      retryDelay = 3000  // 连接成功后重置退避
      ws!.send(JSON.stringify({
        action: 'subscribe',
        device_code: deviceCode,
        group_code: groupCode,
      }))
    }
    ws.onmessage = (e) => {
      const msg = JSON.parse(e.data)
      if (msg.type === 'snapshot') {
        values.value = msg.values
        status.value = 'online'
      } else if (msg.type === 'diff') {
        Object.assign(values.value, msg.values)
      } else if (msg.type === 'offline') {
        status.value = 'offline'
      }
    }
    ws.onclose = () => {
      setTimeout(connect, retryDelay)
      retryDelay = Math.min(retryDelay * 2, 30000)  // 指数退避，上限 30s
    }
  }

  onMounted(connect)
  onUnmounted(() => {
    ws?.send(JSON.stringify({ action: 'unsubscribe', device_code: deviceCode, group_code: groupCode }))
    ws?.close()
  })

  return { values, status }
}
```
