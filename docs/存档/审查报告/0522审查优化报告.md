# Collector 模块审查与优化报告（2026-05-22）

> 范围：`collector/` 采集模块
> 性质：代码评审 + 旧代码清理 + 缺陷修复
> 关联文档：`docs/采集模块/code_review_report.md`（前序评审，本报告对其做了核对与修正）

---

## 概述

本次工作分两个阶段：

1. **评审阶段**：对 `collector` 全模块逐文件评审，并与前序 `code_review_report.md` 交叉核对、纠正分歧。
2. **执行阶段**：按"先修缺陷、再删旧链路、最后清配置"的 5 步计划，分批清理旧代码并修复确认的缺陷，每步独立验证。

业务背景：collector 主链路已重构为 **只写 Redis（latest / window / stream）→ 由独立 `writer` 进程入库 TDengine**。旧的 `DataBuffer → DataAggregator → TDengine 直写` 链路已退役，但代码、配置、文档中残留大量旧实现。

## 一、评审与前序报告的核对

前序 `code_review_report.md` 方向正确，但本次复审发现 3 处需纠正，并补充了它完全未覆盖的"正确性缺陷"维度。

### 1.1 已核实纠正的分歧

| # | 前序报告说法 | 核实结论 |
|---|---|---|
| 1 | 暗示 `monitor/metrics.py` 仍在用（"系统通过 metrics.py 进行采集计数统计"）| **错误**。`MetricsCollector` 仅在 `main.py` 被实例化，无任何方法调用，是死代码。与 `performance_monitor.py` 同为两套都没用的指标系统 |
| 2 | 建议"删除 `data_queue` 目录含 `buffer.py`" | **不可直接执行**。`DataPoint` 定义在 `buffer.py`，被 `executor.py`/`ingest_server.py` 全链路使用。正确做法：先迁出 `DataPoint`，再删 `DataBuffer` |
| 3 | 称 `device.py` 有 `_merge_continuous_blocks`（424 行）| **不存在**。grep 全模块无此方法；实际合并逻辑是 `_build_s7_read_blocks`/`_merge_ge_register_blocks`/`_merge_ge_discrete_blocks` |

### 1.2 前序报告正确、本次采纳

死代码判定（`tdengine.py`/`batch_writer.py`/`aggregator.py`/`cache.py`/`connection_pool.py`/`data_quality.py`/`performance_monitor.py`/`api_server.py`/`utils/`）、两个重复的 `ConnectionPool`、`plugin_system` 名存实亡——均一致。

前序报告有价值的补充：**PyInstaller 打包约束**——动态 `importlib` 插件加载在打包环境会丢依赖，所以 `_create_driver` 回退到静态分支反而是正确实现；以及 `scripts/rebuild_tdengine_stables.py` 属旧脚本。

### 1.3 前序报告未覆盖、本次补充

前序报告只做"死代码/重复"分析，未做任何正确性/健壮性评审。本次补充发现 5 个真实缺陷（见 2.3）。

## 二、评审发现汇总

### 2.1 死代码 / 旧链路

旧 TDengine 直写链路：`data_queue/aggregator.py`、`storage/tdengine.py`、`storage/batch_writer.py`、`scripts/rebuild_tdengine_stables.py`。

未接线模块（建好但从未接入生产链路）：`monitor/metrics.py`、`monitor/api_server.py`、`core/performance_monitor.py`、`core/cache.py`、`core/connection_pool.py`、`core/error_handler.py`、`core/plugin_system.py`、`utils/`。

闲置组件：`DataBuffer`（生产 executor 路径不再写入，仅旧兜底分支引用）。

### 2.2 重复实现

- 两个 `ConnectionPool`（`core/connection_pool.py` 与 `core/retry.py` 内各一份，均无人用）。
- S7/GE 地址正则与校验散落 3 处活代码（`s7_driver.py`、`device.py`、`config_validator.py`）+ 1 处死代码（`utils/helpers.py`）。
- `EndpointPortMapper` 的 sync/async 双版本几乎逐字重复。
- `connect_device` 与 `_connect_center_collection_device` 的熔断器逻辑复制粘贴。
- 两套指标系统（`metrics.py` / `performance_monitor.py`）。

### 2.3 真实缺陷（评审确认）

| 级别 | 缺陷 | 位置 |
|------|------|------|
| 严重 | 文件日志永不生效——`setup_logger` 用 `if not logger.handlers` 包住 handler 创建，两段式初始化时文件 handler 不挂载 | `core/logger.py` |
| 严重 | Stream 分片用进程随机化的 `hash()`，collector 重启后同设备落到不同 shard | `storage/redis_writer.py` |
| 中 | executor 写 Redis 是 fire-and-forget（`run_in_executor` 返回的 Future 不 await），无背压、可能乱序 | `collector/executor.py` |
| 中 | GE / OPC UA 驱动未覆写 `ping()`，健康检查恒为健康，断线不主动重连 | `drivers/ge_srtp_driver.py`、`opcua_driver.py` |
| 中 | 配置热重载不刷新 `ingest_server` 的设备/点位元数据与 `OpcDaTagMapper` | `main.py` |

### 2.4 其它

- **Schema 漂移**：`config_db.py` 读 `device_variable.point_group_id`、`device_point_group` 表、`device.variable_config_version`，与《数据库结构v3》文档不一致，需对实际库核实。
- **死配置**：`TDengineConfig`、`batch_size`/`flush_interval`/`max_window_seconds`/`queue_max_size`/`writer_workers` 仍被加载校验。
- **一致性**：`get_event_loop()` vs `get_running_loop()` 混用；OPC DA 链路用内置 `ConnectionError` + 中文消息，其它驱动用 `core.exceptions` + 英文。

## 三、本次执行的清理与修复

按 5 步计划执行，每步独立验证（`pytest` + 针对性冒烟），逐步经过确认。

### 步骤 1 · 最小高收益修复

- `core/logger.py`：`setup_logger` 改为幂等——先 `removeHandler()` + `handler.close()` 清空旧 handler，再无条件重建 console + 可选 file handler。修复文件日志不生效。
- `storage/redis_writer.py`：分片哈希 `hash(device_code)` → `zlib.crc32(device_code.encode("utf-8"))`，进程间稳定。
- `tests/test_redis_writer.py`：断言基准同步为 `zlib.crc32`。

### 步骤 2 · 删除旧 TDengine 直写链路

- 删除：`data_queue/aggregator.py`、`storage/tdengine.py`、`storage/batch_writer.py`、`scripts/rebuild_tdengine_stables.py`、`tests/test_data_aggregator.py`、`tests/test_tdengine_storage.py`。
- 同步：`storage/__init__.py`、`data_queue/__init__.py` 去掉死导出；`tests/test_integration.py` 只保留 executor 读失败重连测试（剥离 DataAggregator 部分）；`requirements.txt` 删 `taos-ws-py`；`data-watch-collector.spec` 删 `collect_all('taosws')`。

### 步骤 3a · 迁出 DataPoint

- 新建 `data_queue/types.py`，只放 `DataPoint`（顺带删除已废弃的 `to_tdengine_row()`）。
- `buffer.py`、`executor.py`、`ingest_server.py`、`data_queue/__init__.py` 改为从 `data_queue.types` 引入 `DataPoint`。

### 步骤 3b · 删除 DataBuffer 及旧兜底

- 删除 `data_queue/buffer.py`。
- `executor.py`：去掉 `buffer` 参数、`_total_dropped`、`redis_writer is None` 写 buffer 的兜底分支；**新增 `redis_writer` 必填 fail-fast**（`__init__` 中为 None 直接 `raise ValueError`），杜绝静默丢数据。
- `ingest_server.py`：去掉 `data_buffer`/`event_loop` 参数、两处 `redis_writer is None` 兜底分支、`/ingest/health` 的 `queue` 字段、不再使用的 `import asyncio`。
- `main.py`：去掉 `self.data_buffer` 及相关传参与日志字段。
- 同步 `tests/test_integration.py`、`tests/test_interface_ingest.py`。

### 步骤 4 · 删除未接线模块

- 删除：`core/cache.py`、`core/connection_pool.py`、`core/error_handler.py`、`core/performance_monitor.py`、`core/plugin_system.py`、`monitor/metrics.py`、`monitor/api_server.py`、`utils/`（3 文件）、`tests/test_cache.py`、`tests/test_error_handler.py`、`tests/test_performance_monitor.py`。
- 同步：`main.py` 去掉 `MetricsCollector`；`monitor/__init__.py` 去掉导出；`device/manager.py` 的 `_create_driver()` 删掉永远落空的 plugin 分支、简化为静态 `if/elif`（行为不变，符合 PyInstaller 约束）；`requirements.txt` 删 `prometheus-client`。
- 保留：`core/retry.py`（`with_retry`/`CircuitBreaker` 在用）、`core/data_quality.py`（有真实领域逻辑，单独决策，本轮保留）。

### 步骤 5 · 清理旧配置字段与 README

- `core/config.py`：删除 `TDengineConfig` 类及 `CollectorConfig` 的 `tdengine`/`batch_size`/`flush_interval`/`max_window_seconds`/`queue_max_size`/`writer_workers` 六字段。
- `config_loader.py`、`config_validator.py`、`main.py`、`tests/conftest.py`：同步去除对上述字段的引用；删除已死的 `create_sample_config()`。
- `config/settings.toml`、`config/settings.fake_bootstrap.toml`：删除 `[tdengine]` 段与死 `[runtime]` 键。
- `README.md`：删除 `[tdengine]` 配置说明与死 runtime 键；环境要求 `TDengine 2.6+` → `Redis 5.0+`；删除过时的"每变量一子表"建模说明。

### 补充优化 · README 全面订正

步骤 5 后复审发现 README 仍有已删除模块的示例和旧链路描述，已补充修正：

- 系统简介与主要特性改为当前 collector 职责：采集 → Redis（latest / window / stream）→ 独立 writer 入库 TDengine。
- 系统架构图替换为 MySQL 拓扑、DeviceManager、TaskScheduler、TaskExecutor、InterfaceIngestServer、Redis Writer、独立 writer 的当前链路。
- 核心组件章节删除 `DataAggregator`、`DataBuffer`、`plugin_system`、Prometheus/API Server、`connection_pool` 等已删除模块示例。
- TaskExecutor 示例改为 `TaskExecutor(device_manager=device_manager, redis_writer=redis_writer)`，匹配 `redis_writer` 必填的 fail-fast 语义。
- HTTP Push、测试、故障排查段落同步改为 Redis / 独立 writer 模型，避免继续提示检查 TDengine 直连或队列满。

### 验证

- 全程 `pytest` 绿：步骤 1~3 期间 153 passed；步骤 4 删 3 个测试文件后 119 passed；步骤 5 仍 119 passed。
- 步骤 3b 因删掉了唯一的全流程集成测试，对 executor 成功路径做了冒烟验证（mock driver → `execute()` → `write_latest`/`write_stream` 正确调用）。
- 步骤 5 用真实 `config/settings.toml` 跑 `python main.py --dry-run`：TOML 加载 → `CollectorConfig` 构造 → MySQL 拉取 2 设备/5 点位 → 设备注册 → 读取块合并 → 预检完成，端到端一致。

## 四、成果统计

- 删除文件 **20 个** + `utils/` 目录；新增 1 个（`data_queue/types.py`）。
- 净减少未接线/旧代码约 145 KB。
- 修复 2 个严重缺陷（文件日志、Stream 分片哈希）。
- `TaskExecutor` 接口收紧为 `redis_writer` 必填，消除静默丢数据风险。
- 依赖瘦身：移除 `taos-ws-py`、`prometheus-client`。
- 全程测试通过，生产主链路（采集 → Redis）行为无变更。
