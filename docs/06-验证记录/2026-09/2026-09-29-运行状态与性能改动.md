## 本批页面性能改动

下列行为来自 9 月 29 日交付的源码；部署时应使用同一发布提交构建的 Backend 与 Frontend 镜像：

| 范围 | 当前行为 |
| --- | --- |
| 设备列表 | `GET /device/list?includeSummary=false` 先按基础条件过滤、分页，再查询当前页活动时间；总数与在线状态统计由独立的 `/device/summary` 返回。统计卡在首次返回前显示占位。 |
| 点位列表 | MySQL 在数据库侧过滤、计数、分页；列表先显示配置数据，当前页实时值通过独立的 `/point/latest` 批量从 Redis 读取（每请求最多 100 个 ID），失败可单独重试。 |
| 工作台 | 各模块并行加载、独立呈现加载或错误状态并支持重试；趋势查询增加 30 秒内存缓存、超时与失败提示。 |
| 服务端限时与观测 | Redis 设备活动读取 3 秒超时并有短时缓存；TDengine 查询队列等待上限 3 秒，趋势查询另有限时。关键页面请求记录请求 ID、总耗时及 MySQL/Redis/TDengine 分段耗时；前端识别请求超时与网络失败。 |

这批改动的目标是缩短列表与概览的首屏等待，并让慢查询/故障有明确反馈；缓存有效期、限时和分批规模以当前实现为准。前述桥吊 100 验证只确认模拟数据进入库与 Redis，**不能代替**这些页面在完整浏览器负载下的性能验收。已有一次真实趋势服务请求耗时约 **0.148 秒**，仅代表该次请求，不推断全场景 P95/P99。历史阶段性测试见[验证记录索引](../README.md)。
