## 1. 结论摘要（先看这段）

项目**有相当完整的测试资产**（约 2100 条用例、9 个测试域），但**质量保障体系存在三处结构性缺口**：

| # | 缺口 | 影响 | 优先级 |
|---|---|---|---|
| A | `.github/workflows/` 只有 1 个 CLI 发布工作流，**没有任何 CI 测试门禁** | 任何 push/PR 都不自动跑测试；质量靠人工执行本地脚本 | P0 |
| B | 测试执行依赖 3 套互不兼容的 Python 解释器 + 手工 `PYTHONPATH`/`-Xgil=0` 组合，**没有统一入口** | 换机/换人即无法复现回归；`ingest` 至今无单一解释器可跑全量 | P0 |
| C | 跨模块端到端链路（PLC → Collector → Redis → Writer → TDengine）**没有自动化用例**，只有手工 Docker 脚本 | 数据丢失/串设备/质量码错等最严重缺陷类别无门禁 | P1 |

## 8. 补测优先级（P0 → P2）

### P0 — 不补则质量保障形同虚设

1. **建立 CI 测试门禁**（`.github/workflows/ci.yml`）
   - 触发：`push` 到 main + 所有 `pull_request`。
   - 至少覆盖：`cli/tests`、`writer/tests`、`edge/tests`、`frontend`（test + `vue-tsc --noEmit` + build）、`app`（test + `tsc` + `cargo check`）。
   - Python 版本与本地对齐（3.14 / 3.14t 矩阵），否则 collector 会因 `python_abi='cp314t'` 假失败。
   - 预期工作量：1～2 天（主要是矩阵与 PyInstaller 依赖缓存）。
2. **把 `scripts/regression.ps1` 的参数与路径全部参数化**（`-RepoRoot`、`-PythonT`、`-LogRoot`、解释器自动探测），并在 CI 中复用同一份模块→命令映射，消除「本地能跑、CI 不能跑」的双轨制。
   - 验收：在一台干净 Windows 机器上 `pwsh -File scripts/regression.ps1 -Modules cli,writer,edge` 退出 0。
3. **关闭 ingest 解释器分裂**（需决策）：要么在 `Python314t` 用户站点装 free-threading 版 `msgspec`，要么等 TurboAPI 出 GIL 兼容版。同时修正 `ingest/Dockerfile` 基镜像为 free-threading（或在容器内实测确认能启动）。
   - 验收：`ingest/tests` 在单一解释器下 0 failed、0 collection error。

### P1 — 关键链路缺口

4. **补跨模块端到端回归用例**（用隔离 Redis 16379 + 隔离 MySQL 13306 + 隔离 TDengine）：
   - 中心链：合成 PLC 数据 → Collector（cp314t）→ Redis Stream v2 → Writer → TDengine，做**全字段对账**（值/质量/时间戳/设备归属/点位映射）。`data_watch_shared/acceptance.py` 已有对账规则与故障注入自测，缺的是把它跑在真实组件上。
   - 边缘链：Edge Collector → SQLite Outbox → Uploader → Ingest → Redis → Writer → TDengine，含断网重连、坏帧隔离、时钟回拨、超大帧。
   - 实时链：Collector 写 latest → 后端 `rt:change` → WS 推送（`test_ws_push.py` 已有单测，缺联调）。
   - 预期工作量：3～5 天（复用 `scripts/validate_docker_pipeline.py` 的既有实现，改为 pytest + 自动起停隔离容器）。
5. **补齐「无测试源码模块」单测**（按影响面排序）：
   - `collector/monitor/health.py`（健康检查是设备在线/离线判据，直接影响实时页 offline 语义）；
   - `collector/storage/edge_outbox_writer.py`（边缘 writer，当前只有源码文本断言）；
   - `backend/app/services/health.py`、`backend/app/api/permissions.py`（权限是安全边界）；
   - `writer/system_log.py`、`backend/app/core/log_writer.py` / `log_scheduler.py`（日志丢失会影响排障）；
   - `backend/app/core/simple_xlsx.py`（导出正确性，已有 `test_history_export_failure.py` 但未直接覆盖解析器）。
6. **真实 TDengine 行为固化为回归**：把「显式 NULL 覆盖另一组已写值」「A/B/A 列顺序」这两个一次性容器实测变成 pytest fixture 驱动的用例（隔离 TDengine 容器，跑完即毁）。

### P2 — 提升质量与可维护性

7. **引入覆盖率统计**（`pytest-cov` + `--cov-fail-under` 分模块阈值，先只对 `backend/app`、`writer`、`edge` 生效），并在 CI 输出趋势。
