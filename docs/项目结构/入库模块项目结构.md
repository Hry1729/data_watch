# 入库模块项目结构

> 范围：`writer/`。入库模块结构较扁平，核心逻辑集中在根目录 Python 文件。`.venv-pack`、`build`、`dist` 等依赖与构建产物不展开。

```text
writer
├── .venv-pack              # 打包用 Python 虚拟环境，按依赖处理
├── build                   # PyInstaller 构建中间产物
├── config                  # 入库模块配置
│   └── settings.toml       # Redis、MySQL、TDengine、批量写入等配置
├── dist                    # PyInstaller 输出产物
│   └── data-watch-writer   # 打包后的 writer 可执行程序及其运行依赖
├── consumer.py             # Redis Stream 消费者，负责 XREADGROUP / ACK / 重试
├── data-watch-writer.spec  # PyInstaller 打包规格
├── dlq.py                  # 死信队列处理逻辑
├── main.py                 # writer 启动入口，加载配置并启动消费循环
├── mysql_mapper.py         # 从 MySQL 加载 var_id -> td_column_name 等映射
├── requirements.txt        # writer Python 依赖列表
├── system_log.py           # 入库模块系统日志写入/上报
└── tdengine_writer.py      # TDengine 批量写入、自动建超级表/子表逻辑
```

## 入库链路位置

```text
main.py
├── config/settings.toml
├── consumer.py
├── mysql_mapper.py
├── tdengine_writer.py
├── dlq.py
└── system_log.py
```

## 运行时职责

```text
Redis Stream
└── consumer.py
    ├── mysql_mapper.py       # 查询当前设备/点位映射
    ├── tdengine_writer.py    # 写入 device_data.sd{device_type}
    ├── dlq.py                # 异常帧进入死信队列
    └── system_log.py         # 写入运行日志
```
