### 0.4 对原报告的不准确之处的更正（R2）

- **原 §3 表（`_target_address` 行）所述**（同一说法被 §4 结果表与 §7 沿用）：「host 只允许主机名 / IPv4 字面量 / 方括号 IPv6 字面量」——
  **不准确**。原实现 `_HOST_PATTERN = r"^[A-Za-z0-9._-]+$"` 用的是 `$`，**尾随换行的 host（如 `"127.0.0.1\n"`）会被接受**。
- **实际影响（有界，非泄漏）**：端口独立校验（与 host 字符串无关）；`urllib` 对该 host 直接抛错 → `success=False`、接收端 0 请求；API 层「文本精确比较」已先把该书写形式判为「目标变更」→ 400。故验收者与本次复现均**未观察到凭据泄漏**，属**声明与实现的偏差**（这正是否定「该 host 可把请求骗到别处」的原因）。正则现已收紧为 `\Z`，该偏差消除。

## 5. 最小修改（文件与行为差异）

1. `admin.py` `health_check`：**凭据与目标绑定**。应用覆盖前比较 `host/port/user/database` 与存盘值；
   - 有差异且**存在任何形态的存储凭据**（`password_enc` 或非空明文 `password`；B11-R 前只看前者）、且本次未显式给 `password` → **HTTP 400**，提示显式提供临时口令（审计只记字段名）；
   - 有差异且给了显式凭据（或无存储凭据）→ `pop("password_enc")` **与** `pop("password")`，**绝不**把存储凭据带向新目标。
2. `health_checker.py`：三个 checker 统一走 `_target_address`（拒绝 scheme/userinfo/path/query/fragment 形式的 host 与越界端口；**B11-R 起用 `\Z` 而非 `$`，尾随换行 host 亦被拒**），`check_tdengine` 改用不跟随重定向、**且不读代理环境变量**（`_NoProxyHandler`，B11-R）的 opener（3xx 直接失败，凭据不外送）。
3. 未新增依赖；未改动 `_decrypt_password` 的「显式密码优先」语义。

**刻意的设计选择（诚实披露）**：

- 「目标是否变化」用**字符串精确比较**：任何文本差异（`LOCALHOST`、尾点、十进制/八进制 IP、`host:port` 组合）都算新目标 → 一律要求显式凭据。宁可多要求一次输入，也不靠 DNS 等价性判断（这正是 W1-验收协议 §3 反证 2 针对的绕过面）。
- `user`／`database` 被覆盖时**同样**要求显式凭据，即使 Redis 不使用 `user`（清单 299 行验收要求 four 字段任一被覆盖都成立）；代价是略微更严，属安全侧。
- 非法地址由 checker 内既有的 `except Exception` 收敛为 `HealthCheckResponse(success=False, message="… health check failed")`（**不抛 500、不回显 host**）。这意味着「非法地址」与「连不上」在响应上不可区分——取舍是：不把攻击者可控字符串写进响应/日志，且该分支**根本不发起连接**（由接收端 0 请求断言）。
