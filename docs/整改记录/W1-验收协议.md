# W1 独立验收协议（反证用）

本文件是 W1 修复完成后，**独立验收 agent** 的执行依据。目的：防止「修复者自述通过」被当成完成。

## 0. 验收者的硬性规则

1. **验收者不得是修复者**，也不得把修复者新写的测试作为唯一证据。
2. **必须自己重跑**修复者声称的复现命令，并核对输出与其报告是否逐字一致。不一致即视为未证实。
3. **每个条目至少构造一条修复者没想到的反例**（见 §3）。找不到反例也要写明「尝试了 X、Y、Z，均未推翻」。
4. **必须检查改动越界**：`git diff --stat` 是否只碰了该条目被授权的文件；有无顺手重构、有无删除既有死代码。
5. **必须检查假修复模式**（见 §2）。
6. **必须对照 W0-A 基线核对回归数字**，且确认测试**没有被删除、跳过或放宽**。
7. **必须复核现场栈安全基线**（`隔离测试环境.md` §3.7）：5 个容器仍 `Up` 且时长单调增长、现场 Redis `db0` 键数仍为 10。
8. 每条给出：**证实 / 推翻 / 无法判定**，并注明证据等级。无法判定的必须写明缺什么条件。

### 1.1 最终回归必须**串行**执行（并发已被实测证明会造假失败）

W1 期间**实测到并发污染**：W1-E1 在并行 agent 同时写 `edge/tests/` 的情况下跑全量，出现 `2 failed, 57 passed`，失败项**全部落在 W1-S3 当时正在写的新测试文件** `test_storage_ipc_auth_s3.py` 内；E1 自行核对后确认与自己 diff 无交集，其自身 4 个用例在该次运行中全绿。E1 已如实披露，判断正确。

**因此：**
- 最终验收回归**必须在所有修改型 agent 全部停止后**串行执行，一次只跑一个模块。
- 若某个数字与基线不符，**先确认当时没有其他进程在写同一模块**，再判定为真实回归。
- 凡是修复者报告里出现的"失败在别人的并发文件里"这类解释，验收者必须**自己重跑一次确认**，不得直接采信。

## 2. 必须主动排查的「假修复」模式

- [ ] 用 `try/except` 把异常吞掉，让测试变绿（尤其 B7、B11）
- [ ] 放宽断言（`==` 改 `>=`、删关键 `assert`、加大 tolerance）
- [ ] 新增 `@pytest.mark.skip` / `xfail` / `pytest.skip()`
- [ ] 注释掉原有断言或整段测试
- [ ] 只改 mock/fake 层，真实入口行为没变
- [ ] 改测试去迁就代码，而不是改代码满足契约
- [ ] **把「永久拒绝」整体删掉**来解决「误拒」——B7 不得把非法点也一起放过
- [ ] **把鉴权默认关闭**或整体跳过校验——S3/B15 不得以可用性换安全
- [ ] B15 用「静默轮换密钥」代替「拒绝空密钥启动」（会造成会话静默失效）
- [ ] B41 把失败路径的清理删掉了事，导致残留无法回收（要的是「保留可运行版本」，不是「什么都不删」）

## 3. 逐条反证要点

### B25（先锁后恢复）
- 必查：`edge/uploader_main.py` 中**取锁**是否确实早于任何 outbox 状态恢复。
- 反证 1：构造「锁已被占用」场景，验证失败实例**零**状态写入（比对 outbox 文件 mtime/内容哈希）。
- 反证 2：让胜出实例在「取锁成功后、恢复完成前」崩溃，再启动，验证旧租约能被正常恢复。
- 反证 3：并发启动多个进程（≥3），确认只有一个胜出且正常运行实例的 inflight 未被重置。
- 反证 4：单进程正常运行期间，确认没有把自己 inflight 误判为崩溃残留。

### B5（已 ACK 不被迁移重传）
- 必查：`edge/app/uploader.py` 是否在处理 session 异常之前就**持久提交**了已明确 ACK 的项。
- 反证 1：同批「前半 ACK、后半 `commit_unknown`」混合，确认已 ACK 项**不再**出现在迁移集合。
- 反证 2：ACK 应答丢失（服务端已确认但客户端未收到）后再切换 session，检查是否产生**不可审计的静默丢弃**。
- 反证 3：确认后本地崩溃、以及切换过程中崩溃，检查**数据守恒**：所有帧要么已确认、要么仍在 outbox，数量与身份都对得上。
- 必查反模式：是否用「清空 outbox / 跳过高水位之前数据」实现"不重传"——这是被明令禁止的。

### B6（三类计数分离）
- 必查：传输尝试、协议拒绝、数据错误是否使用**独立**计数。
- 反证 1：把网络重试打到远超 max_attempts，再触发**一次**真实序列异常，确认好数据**不**被判 dead。
- 反证 2（反向，防止矫枉过正）：构造一个**真正非法**的载荷，确认它**仍然会**被隔离/终结，不能因为分离计数而变成永不禁用、无限重试。
- 必查：dead 的人工恢复/保留/删除规则是否有明确定义，且**没有自动扩大删除权限**。

### B7（缓存失效 + 权威重读）
- 必查：`backend/app/services/catalog.py` 是否真的**新增**了失效发布（W0-B 确认原先完全没有）。
- 反证 1：人为保留旧缓存并立即上传新点，确认合法帧**不**变成 `rejected_consumed`。
- 反证 2：通知丢失（不投递失效消息）时，是否仍能靠受控权威重读恢复。
- 反证 3（反向）：构造一个**真正越权/非法**的点位，确认它**仍然被拒绝** —— 这条最关键，防止修复把拒绝逻辑整体删掉。
- 必查：失效发布是否在**提交成功之后**，不得先通知后提交；并发 miss 是否被合并（不能造成缓存击穿式的库压力）。

### B11（凭据不得跟着新目标走）
- 必查：目标变化时是否**不再**隐式沿用存储凭据。
- 反证 1：只改 `host`/`port`（不改凭据），用哨兵凭据的隔离接收端验证**收不到**原存储密码。
- 反证 2：host 变体绕过 —— `LOCALHOST`、`127.0.0.1.`（尾点）、`127.0.0.1:PORT@evil`、十进制/八进制 IP 形式，确认不会把凭据发到非预期目标。
- 反证 3：重定向 —— 目标返回 302 到另一个 origin，确认凭据**不**跟随。
- 必查：合法已配置目标的健康检查**仍然可用**（不能把功能改成不可用）；审计日志不含秘密。

### B15（空密钥不得启动）
- 必查：**既有**配置文件（非缺失场景）是否也走校验。
- 反证 1：`jwt_secret = ""`、`jwt_secret = "   "`（纯空白）、键缺失、类型错误（数组/数字）、损坏 toml —— 逐项确认服务**拒绝启动**而非静默接受。
- 反证 2：用空密钥伪造一个 token，确认**被拒**。
- 反证 3（反向）：**合法存量配置必须保持稳定**（不能被误伤导致现场起不来）；确认没有「静默频繁轮换密钥」导致会话反复失效。

### B41（更新失败仍留可运行版本）
- 必查：`cli/update_manager.py` 的 catch 是否**只撤销已完成步骤**，是否**不再**无条件删 current。
- 反证 1：逐个 Move-Item / 校验 / 清理步骤注入失败（含文件被占用、权限不足），每次断言「目录里始终存在至少一个可运行版本」。
- 反证 2：**二次失败** —— 在恢复路径本身上再注入一次失败，确认仍保留可运行版本。
- 反证 3：崩溃后重启，确认阶段状态能恢复且不误报成功。
- 必查：`apply` 是否**不再提前**报 `updateStarted`；失败时**不得**报升级成功。
  > **本行的字面要求已被任务卡的等价路线取代（2026-10-03 协调者更正）。** 本条原先按字面写死"不再提前报 `updateStarted`"，但 `W0-B-P0任务卡.md:698` 明示允许**等价路线**：*「或该字段语义改为『已提交待验证』并带独立验证入口」*。
  > B41 实际采纳等价路线：保留字段名与 `True`，但语义为"已提交待验证"，同时给出 `updateVerified=false` 与 `swap_state()` 独立验证入口；`B41.md §5.3` 已显式声明这是与本节字面要求的**已知偏差**。
  > **因此验收判定标准应为**：`apply` 在失败路径上**不得**以"升级成功"收尾；若采用等价路线，必须同时满足 ①`updateVerified=false` ②存在独立验证入口（如 `swap_state()`）③字面偏差被显式声明。**这条更正的原因是我两份文档前后不一致，责任在协调者。**
- 安全：所有注入必须在**临时目录**进行，绝不允许对真实安装目录执行。

### S3（IPC 认证）
- 必查：`do_POST` 是否**默认拒绝**无凭据请求；`storage_main.py` 绑定非回环是否被显式拒绝或需显式授权。
- 反证 1：**完全不带凭据**的客户端调 `outbox.complete`，确认**无法**把记录置为 `sent`/`dead`。
- 反证 2：合法三方（Collector / Uploader / Agent）**分别**验证仍可正常调用（不能让合法链路瘫掉）。
- 反证 3：凭据是否被**其他本地用户**可读（检查文件权限/ACL）；是否误用了拥有广泛管理权的 Agent service token（**明确禁止**）。
- 反证 4：`--host 0.0.0.0` 是否真被拒绝，而不是仅打印警告后照旧绑定全网卡。
- 必查：没有引入新的第三方依赖。

## 4. 验收输出格式

每个条目一段，逐条写：

```markdown
### <编号> 验收结论
- 验收者 / 依据的修复报告：
- 我重跑的命令与真实输出（关键片段）：
- 与修复者报告的差异（逐字核对结果）：
- 我构造的反例与结果：
- 反向检查（是否矫枉过正 / 是否破坏合法链路）：
- 假修复模式排查结果（§2 清单逐项）：
- 回归数字对照（模块 / 基线 / 现在）：
- 越界检查（git diff --stat 是否只碰授权文件）：
- 证据等级：纯函数 / 单元 / 真实入口 / 隔离集成 / 目标机验收
- 最终裁决：证实 / 推翻 / 无法判定（缺什么条件）
```

最后附一份**总表**：条目 → 裁决 → 证据等级 → 遗留问题。
