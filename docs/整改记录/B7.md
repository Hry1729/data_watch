### 5.1 `ingest/app/repository.py` —— 永久拒绝前的受控权威重读

> 以下为**修复轮原文**（行号按当时文件）；补齐轮对「可重读 reason 集合」与「轮数」的调整见 **§5.4**，行号已漂移。

- 新增常量 `_UNKNOWN_VAR_ID` / `_UNKNOWN_CONFIG_VERSION` / `_REREADABLE_REASONS`（20-25 行）与实例态 `_reread_at`（76 行）。
- `validate_items`（193-…）：接收 `_assignment_rows` / `_mapping_point_sets` 新返回的「本次实际查库的 key 集合」；对 reason ∈ `_REREADABLE_REASONS` 的项调用新增的 `_reread_and_revalidate`（260-361）。
- **`_reread_and_revalidate` 的三条控制**（这是「受控」的全部含义）：
  1. **按命名空间精确重读**：`unknown_var_id` 只可能由 `_mapping_cache` 落后造成，`unknown_config_version` 只可能由 assignment 行里的 `device_point_group.config_version` 落后造成，故各轮只重读对应的那一个命名空间（也避免了「一个非法点位帧消耗版本帧的重读配额」）；
  2. **两轮、顺序固定 `mapping → assignment`**：新点位帧会先撞 mapping 缺失，权威补上映射后才暴露版本落后（`repository.py:378` 在 `381` 之前），单轮不够；
  3. **不放大读**：本次已由 miss 直接查到的 key（并发 miss）不再重读；同一 key 在一个 `control_cache_ttl_seconds` 窗口内至多重读一次（`_claim_reread`）。
- `_assignment_rows`（356-）/ `_mapping_point_sets`（392-）：新增 `force_keys` 参数并返回「本次查库的 key」；`force_keys` 命中时跳过缓存、直接权威查库并回写缓存（**不做整表清空，避免踩踏**）。
- 判定与拒绝规则本身**一字未改**：不存在于 `point_storage_mapping` 的 `point_id`、领先于控制面的 `config_version`、`node_uuid` 不匹配、时间窗越界，仍然一律 `rejected_consumed`（§6 有专门断言）。

## 12.4 TTL 事实更正（原报告读错了口径）

| 项 | 原文（错） | 事实（更正） |
|---|---|---|
| `control_cache_ttl_ms` 生产默认 | 5000ms，窗口上界 ≈6s | **30000ms**，窗口上界 ≈**30s**；缓存侧过期上界 = 30s×1.2(抖动上限) ≈ **36s** |
| 依据 | 读了 **dataclass 字段默认值** `ingest/app/config.py:30`（`control_cache_ttl_ms: int = 5000`） | 生产路径是 `IngestSettings.from_env()`：`ingest/app/config.py:61-62` `int(os.getenv("INGEST_CONTROL_CACHE_TTL_MS", "30000"))`；`ingest/tests/test_config.py:49` 自己断言 `30_000`；全仓库无任何 `INGEST_CONTROL_CACHE_TTL_MS` 覆盖（deploy / docs 均无） |
| 实测 | — | 探针真实输出：`IngestSettings.from_env().control_cache_ttl_ms=30000`，同进程 `dataclass_field_default=5000` |
| 影响 | 残留窗口被**低估 5×**（6s → 30s） | 残留窗口仍在，量级按 **30s / 36s** 计；`_claim_reread` 冷却窗口 = `_control_cache_ttl_seconds`，与缓存 TTL 同源 |

**为什么读错（供下一个人避坑）**：`config.py` 里同一个配置有**两个**默认值——dataclass 字段默认值（`5000`，只在直接构造 `IngestSettings(...)` 时生效，测试里大量直接构造）与 `from_env()` 的环境变量默认值（`30000`，**生产唯一入口**）。判断「生产默认」必须以 `from_env()` 为准。另注意缓存抖动系数是 `_cache_expiry` 的 `0.8 + (crc32 % 4001)/10000 ∈ [0.8, 1.2]`，故条目实际存活 0.8~1.2 倍 TTL，**过期上界 = 1.2×TTL**。
