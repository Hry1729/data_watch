## 遗留修复（edge 组遗留修复 agent，2026-10-03）

验收者（`docs/整改记录/W1-验收-edge.md` §1 遗留问题 1）实测：B25 的正确性依赖「同锁 ⇒ 同库」这一**未被部署层保证、也未在代码层强制**的前提。本 agent 逐条复现并修复。

### 复现（改前，真实入口，仅临时目录 + 回环端口）

`DATAWATCH_EDGE_DB` 指向**同一** outbox 库、`DATAWATCH_DATA_ROOT` 分指 `rootA` / `rootB`：

```text
=== seeded crashed leases: [(1,'inflight','crashed-owner',<过去>), (2,'inflight','crashed-owner',<过去>)] ===
[A] 取 rootA\edge\uploader.lock，恢复 2 条崩溃租约 -> [(1,'retry_wait',None),(2,'retry_wait',None)]，alive=True
[A] 注入 A 的未过期 live 租约: [(1,'inflight','A-live-owner',<未来+300s>)]
[B] 取 rootB\edge\uploader.lock，alive=True；日志: 'Recovered 1 inflight outbox records'
[B] 后 state: [(1,'retry_wait',None),(2,'retry_wait',None)]
[结论] 同库不同锁可同时运行 = True
[结论] 锁A存在 = True  锁B存在 = True
[结论] B 重置了 A 运行中的 live 租约 = True  (A 存活=True)
```

即 B25 验收要求第 3 条「**正常运行实例的 inflight 不被重置**」在该配置组合下被实测违反。

### 修复选择与理由

**选「同源」而非「显式拒绝启动」**：`edge/uploader_main.py::settings_from_env()` 的 `lock_path` 由
`data_root / "edge" / "uploader.lock"` 改为 **`edge_database_path().parent / "uploader.lock"`**。

- 理由：锁本来就是用来保护那个 outbox 库的，锁的身份必须由**库的身份**决定。显式拒绝启动会让一种**本该可用**的配置（库与 data_root 分开挂载）直接不可用；同源则结构性消除「同库不同锁」，且默认部署链（`agent/app/routers/admin.py` 同时把两者设为同一 `data_root()`）**行为完全不变**（两者本就指向同一 `data_root\edge\`）。
- 修复点说明：`lock_path` 只有 `settings_from_env()` 一处定义，故只需改 `edge/uploader_main.py` 一个文件（未动 `edge/app/paths.py`、`edge/app/uploader.py`）。该文件**不在协调者初始允许清单内**，本 agent 停手请示后获**明确批准**（协调者确认为清单列窄）。
- 附带收益：裸跑入口时锁不再落到 `C:\ProgramData\DataWatch\edge\`，而是与它实际使用的库同目录。
