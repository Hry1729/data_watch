# 边缘机一键打包与部署说明（build.ps1 + Inno 安装器）

更新日期：2026-06-09

本文聚焦**本次新增的一键打包链路**：用一条命令把所有模块编译并封装成单个安装器
`DataWatch-Setup-x.y.z.exe`，目标机双击即装。
模块级手工打包、Docker 后端、现场验收等细节见《DataWatch目标机部署手册.md》，本文不重复，只在末尾交叉引用。

---

## 一、本次打包逻辑变更

| | 之前 | 现在 |
| --- | --- | --- |
| 打包方式 | 各模块手工分步打包，再手动铺 staging 目录 | `installer\build.ps1` 一条命令全自动 |
| 交付物 | 一个 staging 目录 + 手动拷贝/注册服务 | 单个 `DataWatch-Setup-x.y.z.exe`，双击一键装 |
| 服务注册 | 目标机手动跑 NSSM 脚本 | 安装器内置 NSSM 注册 + 两根环境变量注入 |

涉及两个文件：

- `installer\build.ps1` —— 一键发版编排脚本（编译 + 调 ISCC）。
- `installer\DataWatch.iss` —— Inno Setup 6 安装器脚本（封装 + 安装逻辑）。

二者均为**源脚本，已入库**；构建产物（dist/build/Output 等）一律不入库，由 `build.ps1` 随时再生。

## 二、改完代码后怎么打包

### 2.1 一键全量打包（推荐）

在仓库根 `D:\python\device_alarm\data_watch` 执行：

```powershell
pwsh -File installer\build.ps1
```

可选参数：ISCC 不在默认位置时显式指定：

```powershell
pwsh -File installer\build.ps1 -Iscc "D:\ruanjian\Inno Setup 6\ISCC.exe"
```

脚本按顺序做 6 件事，任一段失败立即中断（`$LASTEXITCODE` fail-fast）：

| 阶段 | 动作 | 产物 |
| --- | --- | --- |
| [0/6] 开工前检查 | 探测 ISCC（注册表三键）+ 校验外部静态件在位 | 缺失即报错 |
| [1/6] app | `pnpm install` → `pnpm tauri build` | `app\src-tauri\target\release\app.exe` + `resources\` |
| [2/6] agent | `agent\.venv-pack` 下 PyInstaller | `agent\dist\data-watch-agent\` |
| [3/6] collector | `collector\.venv-pack` 下 PyInstaller | `collector\dist\data-watch-collector\` |
| [4/6] writer | `writer\.venv-pack` 下 PyInstaller | `writer\dist\data-watch-writer\` |
| [5/6] proxy | `sidecars\opcda_proxy_service\build.ps1`（csc，net48/x86） | `...\bin\OpcDaProxyService.exe` |
| [6/6] ISCC | 编译 `DataWatch.iss` | `installer\Output\DataWatch-Setup-<版本>.exe` |

跑通后末尾会打印产物名、大小、时间，例如：

```text
=== DONE ===
Name          : DataWatch-Setup-0.1.0.exe
SizeMB        : 57.7
LastWriteTime : 2026/6/9 13:06:47
```

版本号取自 `DataWatch.iss` 的 `#define MyAppVersion`，改版本只改 `.iss` 一处即可，`build.ps1` 自动跟随。

### 2.2 一次性前置条件

`build.ps1` 不负责安装工具链，首次打包前需在本机准备好：

- **Inno Setup 6**（提供 `ISCC.exe`；本机当前在 `D:\ruanjian\Inno Setup 6`）。
- **Node + pnpm**、**Rust 工具链**（`pnpm tauri build` 需要）。
- **三个打包专用 venv**：`agent\.venv-pack`、`collector\.venv-pack`、`writer\.venv-pack`
  （各含 PyInstaller，建法见《目标机部署手册》§四.3/§四.4）。
- **外部静态件**（体积大/外部获取，不入库，需预先放好）：
  - `installer\win64\nssm.exe`
  - `installer\webview2\MicrosoftEdgeWebview2Setup.exe`（evergreen 引导器，离线机可换 ~127MB standalone 同名文件）
  - 配置模板：`agent\config.toml.example`、`installer\templates\collector-settings.toml.example`、`installer\templates\writer-settings.toml.example`

缺任何一项，`build.ps1` 在 [0/6] 阶段直接报明缺哪个、不会跑到一半才失败。

### 2.3 只改了某一块时

`build.ps1` 始终全量构建（保证可复现）。改动小、想省时间时也可只跑对应阶段，再单独跑 ISCC：

| 改了什么 | 单独重建命令（在对应目录） |
| --- | --- |
| 前端/Tauri | `cd app; pnpm tauri build` |
| agent Python | `cd agent; .\.venv-pack\Scripts\pyinstaller.exe data-watch-agent.spec --noconfirm` |
| collector Python | `cd collector; .\.venv-pack\Scripts\pyinstaller.exe data-watch-collector.spec --noconfirm` |
| writer Python | `cd writer; .\.venv-pack\Scripts\pyinstaller.exe data-watch-writer.spec --noconfirm` |
| OPC DA proxy（C#） | `cd collector\sidecars\opcda_proxy_service; .\build.ps1` |
| 重新封装安装器 | `& "D:\ruanjian\Inno Setup 6\ISCC.exe" installer\DataWatch.iss` |

> 拿不准依赖关系时，直接跑 `installer\build.ps1` 全量最稳。

## 三、打包产物在哪里、分别是什么

### 3.1 中间产物（各模块构建输出，不入库，供安装器封装）

```text
app\src-tauri\target\release\
├─ app.exe                         # 桌面 Console 主程序（Tauri）
└─ resources\                      # app 运行资源（icon 等）

agent\dist\data-watch-agent\
├─ data-watch-agent.exe            # Agent（FastAPI/uvicorn，监听 7070）
└─ _internal\                      # Python 运行依赖

collector\dist\data-watch-collector\
├─ data-watch-collector.exe        # 采集进程
└─ _internal\

writer\dist\data-watch-writer\
├─ data-watch-writer.exe           # 落库进程
└─ _internal\

collector\sidecars\opcda_proxy_service\bin\
├─ OpcDaProxyService.exe           # OPC DA 代理 sidecar（net48/x86，目标机需 .NET Framework 4.8）
└─ opcda_proxy_config.json
```

### 3.2 最终交付物（拷给客户的就是这一个文件）

```text
installer\Output\DataWatch-Setup-<版本>.exe     # 例：DataWatch-Setup-0.1.0.exe，约 57.7 MB
```

它把上面所有中间产物 + `nssm.exe` + 三个配置模板 + WebView2 引导器全部打进一个安装包。

## 四、安装器装了什么（DataWatch.iss 逻辑）

### 4.1 安装后的目录布局（双根契约）

程序文件落 `Program Files`（**只读**），运行配置/日志落 `ProgramData`（**可写**）。

```text
C:\Program Files\DataWatch\          ← DATAWATCH_INSTALL_ROOT（只读安装根）
├─ app\                              # app.exe + resources
├─ agent\                            # data-watch-agent.exe + _internal
├─ collector\                        # data-watch-collector.exe + _internal
├─ writer\                           # data-watch-writer.exe + _internal
├─ sidecars\opcda_proxy_service\bin\ # OpcDaProxyService.exe
├─ tools\                            # nssm.exe
└─ templates\                        # 三个 *.example 脱敏配置模板

C:\ProgramData\DataWatch\            ← DATAWATCH_DATA_ROOT（可写数据根）
├─ config.toml                       # Agent 配置（首次安装从模板下发）
├─ collector\config\settings.toml
├─ writer\config\settings.toml
└─ runtime\
   └─ logs\                          # 含 agent-service.out/err.log
```

> agent/collector/writer 的可执行路径、工作目录、settings.toml 路径，运行期由两根环境变量**自动派生**，
> **不**在 config.toml 里写绝对路径。

### 4.2 安装过程做的事（ssPostInstall）

1. 铺所有程序文件到 `Program Files\DataWatch\`。
2. 建 `ProgramData\DataWatch\` 下各运行目录。
3. **下发默认配置**（`ProvisionConfigs`，仅当目标不存在时拷，不覆盖现场已填配置）：
   模板 `*.example` → `config.toml` / `collector\config\settings.toml` / `writer\config\settings.toml`。
4. **注册 Windows 服务 `DataWatchAgent`**（`RegisterService`，NSSM）：
   - 先 stop/remove 同名旧服务（幂等），再 install 指向 `agent\data-watch-agent.exe`；
   - 经 `AppEnvironmentExtra` 在**进程启动前**注入 `DATAWATCH_INSTALL_ROOT` 与 `DATAWATCH_DATA_ROOT`；
   - 设开机自启 `SERVICE_AUTO_START`，重定向服务 stdout/stderr 到 `runtime\logs\`；
   - 启动服务。
5. **WebView2 检测**：Win10 缺运行时则静默安装（`/silent /install`），Win11 自带跳过。
6. 创建桌面与开始菜单快捷方式 `Data Watch Console`。

### 4.3 卸载行为

停止并删除 `DataWatchAgent` 服务；**保留 `C:\ProgramData\DataWatch\` 下的配置与数据**，不随卸载删除。

## 五、在目标机上部署

> 前提：目标机已具备 .NET Framework 4.8；MySQL/Redis/TDengine/Backend 已就绪（Docker 或现场服务，见旧手册 §五.1）。

1. **拷贝并运行安装器**（需管理员/UAC）：
   ```powershell
   Start-Process "DataWatch-Setup-0.1.0.exe" -Verb RunAs
   ```
   静默安装可用 `/VERYSILENT`。

2. **确认服务起来**：
   ```powershell
   Get-Service DataWatchAgent
   Invoke-RestMethod http://127.0.0.1:7070/bootstrap/status
   ```

3. **打开桌面 `Data Watch Console`**，完成 Bootstrap：填 MySQL/Redis/TDengine 连接与密码。
   密码在**目标机本机**经 DPAPI 加密存为 `password_enc`，写入 `ProgramData\DataWatch\config.toml`，
   **不可跨机复制**（DPAPI 绑机器+账户）。

4. **在 app 内启动 collector / writer**，验证状态与日志。
   有 OPC DA 中心采集时，Agent 会自动按需拉起 proxy 再启动 collector（无需手动跑 proxy）。

5. **SC-P06 现场验收**（最关键）：确认 Agent 服务账户在其上下文下能连通 OPC DA/DCOM 并**真实读到点位**，
   不能只看进程/端口起没起。详见旧手册 §七。

部署步骤的逐项验证、排错、OPC DCOM 权限细节，均以《DataWatch目标机部署手册.md》§六~§八 为准。

## 六、注意事项 / 已知待修

- **产物不入库**：`dist\`、`build\`、`Output\`、`__pycache__\`、`.venv-pack\` 等均不提交；改完代码重跑
  `build.ps1` 即可再生。提交时勿把这些二进制混入。
- **P1（待修）**：`DataWatch.iss` 的 NSSM `install/set/start` 当前**未检查返回码**，极端情况下服务注册/启动
  失败仍可能显示"安装成功"，目标机表现为"装好了但 Agent 没跑"。修复前，装完务必执行第五节第 2 步核验服务。
- **P2（待修）**：`agent\config.toml.example` 仍残留 `[collector]`/`[writer]` 的 `executable`/`working_dir`
  段（注释"必须配置否则 400"）。现逻辑已改为按双根自动派生，该段为**死配置**，填了不生效，仅作误导，待清理。
