**总体方案**

```
Docker 继续负责： MySQL / Redis / TDengine / Backend Windows 安装包负责： Data Watch Console app DataWatch Agent collector writer OPC DA proxy
```

**成功标准**
安装后应满足：

1. 桌面有 Data Watch Console。
2. Agent 作为 Windows 服务开机自启。
3. app 只调用 Agent，不直接启动任何进程。
4. app 点“启动 collector”时：
   - Agent 检测是否存在 opcda_center 设备；
   - 有则先启动 OpcDaProxyService.exe；
   - proxy 端口就绪后再启动 collector；
   - 无 OPC DA 则直接启动 collector。
5. app 点“启动 writer”时，Agent 启动 writer。
6. app 能看到 collector / writer 状态、日志、健康检查。

------

**Phase 0：冻结安装目录与运行目录**
建议固定：

```
C:\Program Files\DataWatch\ ├─ app\ ├─ agent\ ├─ collector\ ├─ writer\ └─ sidecars\opcda_proxy_service\ C:\ProgramData\DataWatch\ ├─ config.toml ├─ collector\config\settings.toml ├─ writer\config\settings.toml ├─ logs\ ├─ pids\ └─ runtime\
```

这一阶段只更新文档和配置约定。

------

**Phase 1：Agent 作为中枢补能力**
Agent 需要新增/完善：

```
start collector:  detect opcda_center  start required proxy  wait proxy port ready  start collector stop collector:  stop collector  optionally stop proxy status:  collector status  writer status  proxy status
```

需要处理：

- proxy 是否已运行，避免重复启动；
- proxy 端口是否占用；
- proxy 启动失败时 collector 不启动，并返回清晰错误；
- 日志写入 Agent 日志和 app 实时日志。

------

**Phase 2：OPC DA proxy 部署方式**
把这个目录纳入安装包：

```
collector\sidecars\opcda_proxy_service\
```

运行方式由 Agent 直接调用：

```
OpcDaProxyService.exe --config <generated-proxy-config.json>
```

不再依赖 collector 的 run.bat。

Agent 负责生成类似：

```
C:\ProgramData\DataWatch\runtime\proxy_9090.json
```

------

**Phase 3：collector / writer 打包标准化**
collector 和 writer 继续各自 PyInstaller：

```
collector\dist\data-watch-collector\ writer\dist\data-watch-writer\
```

安装包只拿最终产物：

```
data-watch-collector.exe data-watch-writer.exe config\settings.toml.example
```

注意：collector / writer 都必须支持以安装目录为工作目录启动。

------

**Phase 4：Agent 打包**
Agent 也建议打成 exe：

```
agent\dist\data-watch-agent\data-watch-agent.exe
```

然后由安装程序注册为 Windows 服务。

初期可以用 NSSM，后续再考虑原生 Windows Service。

------

**Phase 5：一体安装包**
建议先用 **Inno Setup**，比 NSIS 写服务注册、复制多目录、创建 ProgramData 配置更舒服。

安装包做这些事：

1. 复制 app / agent / collector / writer / proxy。
2. 创建 C:\ProgramData\DataWatch\...。
3. 复制默认配置模板。
4. 注册 Agent 服务。
5. 创建桌面快捷方式。
6. 可选：安装后自动启动 Agent。

------

**Phase 6：app 适配**
app 侧尽量少改。

只需要确认：

- 默认 Agent 地址还是 http://127.0.0.1:7070
- 默认 Backend 地址可配置
- app 不关心 collector / writer / proxy 的真实路径
- 所有进程操作都走 Agent API

------

**Phase 7：验收清单**
目标机测试顺序：

1. 安装 Docker 服务栈。
2. 安装 DataWatch 一体包。
3. 启动 app。
4. Bootstrap / 登录。
5. 设置数据库连接并保存。
6. 测试 Redis / MySQL / TDengine。
7. 启动 collector。
8. 验证有 OPC DA 时 proxy 自动启动。
9. 启动 writer。
10. 验证实时监控、模块状态、日志、趋势图。

------

**建议第一步**
先不要直接写安装包。第一步应该做：

```
Agent 启动 collector 前自动拉起 OPC DA proxy
```

也就是先把“中枢能力”做实。
安装包只是把这些能力打包起来，核心逻辑必须先在 Agent 里跑通。
