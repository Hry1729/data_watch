# 本地开发启动说明

更新日期：2026-05-21

---

## 一、前置依赖

| 依赖 | 说明 |
|------|------|
| Python 3.14t | 后端和采集模块运行时，free-threading 版本 |
| Node.js ≥ 20.19.0 | 前端开发服务器 |
| pnpm ≥ 8.8.0 | 前端包管理器 |
| MySQL | 配置库，数据库名 `device_watch` |
| TDengine (taosAdapter 6041) | 时序库，数据库名 `device_data` |
| Redis | 实时缓冲层，默认端口 6379 |

Python 3.14t 安装路径通常为：

```text
C:\Users\<用户名>\.local\bin\python3.14t.exe
```

后端的包依赖已预装在 `backend/.py314t-site/`，不需要额外 pip install。  
前端如果 `frontend/node_modules` 不存在，需先在 `frontend/` 目录执行一次 `pnpm install`。

## 二、配置文件

### 后端

后端配置优先读取环境变量，回退到文件 `backend/.env`，再回退到 `backend/.env.example`。

本地开发时复制并修改：

```powershell
Copy-Item D:\python\device_alarm\data_watch\backend\.env.example `
          D:\python\device_alarm\data_watch\backend\.env
notepad   D:\python\device_alarm\data_watch\backend\.env
```

重点修改（与 `.env.example` 默认值的差异）：

```env
MYSQL_PASSWORD=你的 MySQL 密码
TDENGINE_PASSWORD=你的 TDengine 密码
REDIS_PASSWORD=（无密码则留空）
AUTH_SECRET_KEY=dev-only-secret-key
```

其余字段（host、port、database）默认指向 `127.0.0.1`，本机运行不需要改。

### 采集模块

采集模块使用 TOML 配置，直接编辑：

```powershell
notepad D:\python\device_alarm\data_watch\collector\config\settings.toml
```

重点：

```toml
[mysql]
password = "你的 MySQL 密码"

[tdengine]
password = "你的 TDengine 密码"

[redis]
password = ""   # 无密码时留空
```

## 三、一键启动（推荐）

项目根目录提供了 `start-dev.ps1`，会自动检测 Python 路径，在两个独立窗口分别启动后端和前端：

```powershell
cd D:\python\device_alarm\data_watch
.\start-dev.ps1
```

启动后：

| 服务 | 地址 |
|------|------|
| 后端 API | http://127.0.0.1:8000 |
| 前端开发服务器 | http://127.0.0.1:5173 |

如果端口已被占用，脚本会跳过对应服务并提示。强制启动：

```powershell
.\start-dev.ps1 -Force
```

采集模块和 writer 需要单独启动（见第四节）。

## 四、手动分服务启动

### 4.1 后端

```powershell
cd D:\python\device_alarm\data_watch\backend

$env:PYTHONPATH  = '.py314t-site'
$env:PYTHONUTF8  = '1'
$env:PYTHONIOENCODING = 'utf-8'

& 'C:\Users\Hry\.local\bin\python3.14t.exe' -m uvicorn main:app --host 127.0.0.1 --port 8000 --reload
```

`--reload` 在代码变更时自动重启，开发阶段推荐加上。

### 4.2 前端

```powershell
cd D:\python\device_alarm\data_watch\frontend
pnpm dev
```

Vite 默认会打开浏览器。接口请求通过 `.env.development` 中的 `VITE_API_PROXY_URL = http://127.0.0.1:8000` 代理到后端，不需要修改。

### 4.3 采集模块

采集模块依赖 MySQL、TDengine、Redis 均可访问后才启动。

```powershell
cd D:\python\device_alarm\data_watch\collector
.\run.bat
```

`run.bat` 会自动检测 OPC DA 协议配置，按需启动 sidecar 代理进程，再启动采集主进程。

如果只想验证配置、不实际采集：

```powershell
.\.venv\Scripts\python.exe main.py --dry-run
```

### 4.4 writer

writer 负责从 Redis Stream 消费数据并批量写入 TDengine 宽表。它是独立进程，需要和 collector 同时运行数据才能落库。

配置文件：`writer/config/settings.toml`，重点修改密码：

```toml
[mysql]
password = "你的 MySQL 密码"

[tdengine]
password = "你的 TDengine 密码"

[redis]
password = ""   # 无密码留空
```

`[writer]` 段中的 `device_types` 必须覆盖现场实际设备类型（默认 `["qc", "asc", "agv"]`），`group_codes` 保持 `["g001"]`。

启动（复用 collector 的虚拟环境）：

```powershell
cd D:\python\device_alarm\data_watch\writer
..\collector\.venv\Scripts\python.exe main.py
```

启动成功后会看到：

```text
Redis connected: 127.0.0.1:6379 db=0
MySQL connected: 127.0.0.1:3306 db=device_watch
[tdengine] connected to 127.0.0.1:6041 db=device_data
Consuming N stream key(s): [...]
```

### 4.5 测试脚本（数据模拟 / 压测）

测试脚本位于 `docs/运维/测试脚本/`，详细说明见该目录下的 `README.md`。

所有脚本从项目根目录运行，使用 collector 虚拟环境：

```powershell
cd D:\python\device_alarm\data_watch
```

#### `redis_mock_writer.py` — 模拟采集器，向 Redis 写数据

key 格式与真实 collector 完全一致（v0.6 schema），设备列表从 MySQL 加载，配置读 `writer/config/settings.toml`。

```powershell
# 干跑：确认设备加载是否正确
collector\.venv\Scripts\python.exe "docs\运维\测试脚本\redis_mock_writer.py" --dry-run

# 仅写 latest/window（验证前端实时显示）
collector\.venv\Scripts\python.exe "docs\运维\测试脚本\redis_mock_writer.py"

# 同时写 Stream，配合 writer 验证 → TDengine 落库链路
collector\.venv\Scripts\python.exe "docs\运维\测试脚本\redis_mock_writer.py" --enable-stream

# 持续运行直到 Ctrl+C
collector\.venv\Scripts\python.exe "docs\运维\测试脚本\redis_mock_writer.py" --enable-stream --duration-seconds 0
```

**依赖**：MySQL 和 Redis 必须运行。加 `--enable-stream` 时，writer 同步启动才能消费写 TDengine。

## 五、TDengine 初始化（首次）

如果 `device_data` 数据库的宽表超级表/子表还未创建，运行一次初始化脚本：

```powershell
cd D:\python\device_alarm\data_watch
collector\.venv\Scripts\python.exe scripts\init_tdengine_v2.py
```

脚本会在 `device_data` 库下为每种设备类型创建超级表 `st_{type}_g001`（列 `v0001`～`v3072`，全 DOUBLE），并为每台设备创建对应子表 `t_{device_code}_g001`。

可以用 `--dry-run` 先预览 SQL：

```powershell
collector\.venv\Scripts\python.exe scripts\init_tdengine_v2.py --dry-run
```

## 七、常见问题

### Python 找不到

`start-dev.ps1` 按以下顺序查找 Python：

```text
C:\Users\Hry\.local\bin\python3.14t.exe
backend\.venv-314t\Scripts\python.exe
C:\Users\Hry\AppData\Local\Python\pythoncore-3.14-64\python.exe
```

如果以上路径都不存在，会报 `Unable to locate a Python executable`。需要确认 Python 3.14t 安装路径，并根据实际路径修改 `start-dev.ps1` 的 `$pythonExe` 候选列表。

### 端口冲突

后端默认 8000，前端 5173。如果端口已有进程占用：

```powershell
netstat -ano | findstr :8000
netstat -ano | findstr :5173
```

> **注意**：端口 3006 在此机器上被 Windows 系统保留（`netsh int ipv4 show excludedportrange` 显示 2912-3011 区间被排除），绑定 `0.0.0.0:3006` 会报 `EACCES`。已于 2026-05-22 将前端端口改为 5173（Vite 默认端口，不在任何排除区间）。

### 前端代理失败（API 请求 502）

确认后端正在运行，且 `frontend/.env.development` 中的 `VITE_API_PROXY_URL` 指向正确的后端地址（默认 `http://127.0.0.1:8000`）。

### Redis 连接失败

后端启动日志会报 `Redis connection failed`，采集模块日志会报 `redis`。确认 Redis 服务正在运行：

```powershell
redis-cli ping
```

返回 `PONG` 表示正常。
