# 三角色安装包验收清单

> 适用于 `0.1.0` 三角色纯 Windows 安装包。目标是确认角色固定、Docker 与 EXE 分轨、两条数据链路可用且故障后可恢复。建议三台干净 Windows 虚拟机分别验收，最后增加一台同机并存测试机。

## 1. 验收结论规则

- **必须全部通过**：包体/哈希、安装边界、服务与端口、角色进程、Docker 不受安装器影响、对应数据链路、升级卸载。
- **任一项命中即拒收**：中心包超过 100 MB；安装目录出现 Docker tar/Compose/数据库；边缘包出现 Writer；服务或端口串用；断网数据未落 SQLite；恢复联网后无法追赶；安装或卸载操作了 Docker 容器、镜像或数据卷。
- **容量门禁**：普通现场完成本文功能验收即可；正式承诺 2000 QPS/P99 前，仍需按《Ingest容量压测》在独立压测机复核。

## 2. 环境与证据

### 2.1 建议环境

- [x] 三台干净 Windows 10/11 或 Windows Server 测试机，分别安装中心式、分布式边缘、分布式中心。
- [x] 一台可同时安装三角色的并存测试机。
- [x] Docker 中已独立部署 Backend、Frontend、MySQL、Redis、TDengine；Redis Compose 端口仅从 Windows 宿主机回环地址访问，不向所有网卡发布。
- [ ] 分布式中心 nginx 已配置 `/ingest/* -> host.docker.internal:8010`。
- [ ] 准备至少一台真实或模拟采集设备，以及可识别的测试点位。
- [ ] 验收前保存 `docker ps`、数据库行数、Redis Stream 长度和测试机快照。

### 2.2 每项保留证据

- [ ] 命令输出或截图。
- [ ] 安装包名称、大小、SHA-256。
- [ ] Windows 服务、端口、安装目录和 ProgramData 目录截图。
- [ ] Collector/Storage/Uploader/Ingest/Writer 日志。
- [ ] Redis Stream、SQLite outbox、TDengine 行数的前后对比。
- [ ] 验收人、时间、机器名、结论和问题编号。

## 4. 中心式安装包

### 4.1 文件、服务与端口

- [x] 安装目录为 `C:\Program Files\DataWatch Centralized`。
- [x] 数据目录为 `C:\ProgramData\DataWatch`。
- [x] Windows 服务为 `DataWatchCentralizedAgent`，状态为 Running。
- [ ] Agent 仅监听 `127.0.0.1:7070`。
- [ ] 包含 App、Agent、Collector、Writer、OPC DA proxy。
- [ ] 不包含 Edge Collector、Uploader、Ingest、`center\docker-images`、Compose 或 Docker tar。

```powershell
Get-Service DataWatchCentralizedAgent
Get-NetTCPConnection -LocalPort 7070 -State Listen
Invoke-RestMethod http://127.0.0.1:7070/bootstrap/status
Get-ChildItem 'C:\Program Files\DataWatch Centralized' -Force
```

### 4.2 配置与数据链路

- [ ] App 不显示分布式边缘本机页或中心节点管理页。
- [ ] Bootstrap 可连接独立 Docker 中的 Backend、MySQL、Redis、TDengine。
- [ ] `agent_service_token.txt` 位于 `C:\ProgramData\DataWatch`；Backend `backend.env` 使用同一 token 和 `host.docker.internal:7070`。
- [ ] 启动 Collector 后，测试点位按配置的 `scan_rate` 刷新。
- [ ] Redis latest 与 Stream 出现测试数据。
- [ ] Writer 消费 Stream，TDengine 行数增加，PEL 最终回落。
- [ ] App/Web 实时页与历史页都能查询到测试点位。

## 5. 分布式边缘安装包

### 5.1 文件、服务与离线可用性

- [ ] 安装目录为 `C:\Program Files\DataWatch Edge`。
- [ ] 数据目录为 `C:\ProgramData\DataWatch Edge`。
- [ ] Windows 服务为 `DataWatchEdgeAgent`，仅监听 `127.0.0.1:7071`。
- [ ] 包含 Edge App、Edge Agent、Storage、Edge Collector、Uploader、SQLite outbox、OPC DA proxy。
- [ ] 不包含 Writer、Ingest、Backend、Redis、MySQL、TDengine、Compose 或 Docker tar。
- [ ] Storage 仅监听 `127.0.0.1:7073`，`/healthz` 和 `/v1/status` 可用。
- [ ] 中心断网时 Edge App 仍能查看本机设备、采集状态、Storage 状态、SQLite 积压和日志。

```powershell
Get-Service DataWatchEdgeAgent
Get-NetTCPConnection -LocalPort 7071 -State Listen
Get-NetTCPConnection -LocalPort 7073 -State Listen
Invoke-RestMethod http://127.0.0.1:7071/bootstrap/status
Invoke-RestMethod http://127.0.0.1:7073/healthz
Invoke-RestMethod http://127.0.0.1:7073/v1/status
Get-ChildItem 'C:\Program Files\DataWatch Edge' -Force
Get-ChildItem 'C:\ProgramData\DataWatch Edge' -Force
```

### 5.2 注册、断网与恢复

- [ ] 首次引导生成 `node_uuid` 和 Ed25519 密钥，并通过 enrollment code 注册。
- [ ] 中心审批后，边缘成功拉取 assignment/config revision。
- [ ] Agent 启动顺序为 Storage ready 后再启动 Edge Collector/Uploader；停止 Storage 时先处理依赖模块。
- [ ] Edge Collector 数据经 Storage 先写 SQLite outbox，不直接连接中心 Redis。
- [ ] Collector/Uploader 不直接打开 SQLite 写事务；并发运行时 Storage `errors_total` 无异常增加。
- [ ] `writer_queue_depth` 不持续增长，`commit_p99_ms` 满足本机最快有效采集节拍。
- [ ] 正常联网时 Uploader 严格按序上传，中心 high watermark 单调增加。
- [ ] 人工断开中心网络 3～5 分钟，采集不中断，未发送 outbox 数量持续增加。
- [ ] 恢复网络后 Uploader 从原序号追赶，无 gap、无乱序、无重复业务数据。
- [ ] 追赶完成后 backlog 回落，中心节点页显示在线、正确配置版本和积压水位。
- [ ] 慢设备只延迟自身样本，不阻塞其他已落 outbox 数据上传。

## 6. 分布式中心安装包

### 6.1 文件、服务与端口

- [ ] 安装目录为 `C:\Program Files\DataWatch Distributed Center`。
- [ ] 数据目录为 `C:\ProgramData\DataWatch Distributed Center`。
- [ ] Windows 服务为 `DataWatchDistributedCenterAgent`，仅监听 `127.0.0.1:7072`。
- [ ] 包含 Center App、Agent、Ingest、Writer。
- [ ] 不包含 Collector、Uploader、OPC DA proxy、Backend、数据库、Compose 或 Docker tar。
- [ ] Ingest 监听宿主机 8010，nginx 8080 的 `/ingest` 可达；停止 nginx 后边缘进入积压，恢复后自动追赶。

```powershell

Get-NetTCPConnection -LocalPort 8010 -State Listen
Invoke-RestMethod http://127.0.0.1:7072/bootstrap/status
Invoke-RestMethod http://127.0.0.1:8010/healthz
Get-ChildItem 'C:\Program Files\DataWatch Distributed Center' -Force
```

### 6.2 管理与中心链路

- [ ] Center App 显示边缘节点管理页，不显示 Collector 页面。
- [ ] `agent_service_token.txt` 位于对应 ProgramData；Backend 使用同一 token 和 `host.docker.internal:7072`。
- [ ] 节点注册、审批、吊销、密钥轮换、assignment 和配置修订可用。
- [ ] 合法签名上传成功；错误签名、过期 nonce、越序 seq、obsolete session 被正确拒绝。
- [ ] Ingest 写入正确 Redis Stream 分片，latest 不被旧时间戳倒退覆盖。
- [ ] Writer 四个分片消费者运行，成功写入 TDengine，PEL/DLQ 无异常增长。

## 7. Docker 与数据库边界

```powershell
docker compose -f .\deploy\docker-compose.yml config --services
docker ps --format 'table {{.Names}}\t{{.Image}}\t{{.Status}}'
```

- [ ] 默认 Compose 服务只有 `backend`、`frontend`。
- [ ] MySQL 使用独立 Docker 容器或外部实例，不由 Windows 安装器创建。
- [ ] Redis/TDengine 可使用现场已有容器；需要 DataWatch Compose 托管时才启用 `infra` profile。
- [ ] `backend.env` 按部署形态配置数据库地址：Compose infra 使用 `redis`/`tdengine` 私有服务名，外部服务才使用 `host.docker.internal` 或受控实际地址；Redis 密码与 ACL/TLS 已验收。
- [ ] Backend `/healthz`、Frontend/nginx 8080、`/api/*`、WebSocket 和签名 `/ingest` 请求均可用。
- [ ] 本地 Vite 5173 仅用于页面开发，不作为边缘 `center_url`；边缘仍指向 8080 统一入口。
- [ ] 安装、升级、卸载任一 Windows 角色都不会停止或删除 Docker 容器、镜像、网络、卷和业务数据。

## 8. 同机并存与角色隔离

- [ ] 同机依次安装三个角色，三个 Windows 服务同时 Running。
- [ ] 7070、7071、7072、7073 无端口冲突，三个 App 各自连接正确 Agent，7073 仅属于 edge 角色。
- [ ] 三个安装目录、ProgramData、AppId、服务名互不覆盖。
- [ ] 启停或升级其中一个角色，不影响另外两个角色及其子进程。
- [ ] 中心式 App 无节点管理页；Edge App 无全局管理页；Center App 有节点管理页且无 Collector 页。

## 9. 重启、升级与卸载

- [ ] 重启 Windows 后角色 Agent 自动启动，所需子进程可恢复到预期状态。
- [ ] 覆盖安装同角色新版后 ProgramData 配置、token、SQLite outbox 和运行数据保留。
- [ ] 升级一个角色不停止其他角色服务。
- [ ] 卸载时选择保留数据，ProgramData 保留；重新安装后可继续使用。
- [ ] 卸载时选择删除数据，仅删除本角色 ProgramData，不删除其他角色或 Docker 数据。
- [ ] 回滚到上一版安装包后能够重新启动；数据库 schema/业务数据按独立备份策略处理。

## 10. 最终端到端判定

### 中心式链路

- [ ] `设备 -> Collector -> Redis -> Writer -> TDengine -> Backend/App/Web` 全链路成功。

### 分布式链路

- [ ] `设备 -> Edge Collector -> Storage -> SQLite outbox -> Uploader -> nginx/Ingest -> Redis -> Writer -> TDengine -> Backend/App/Web` 全链路成功。
- [ ] 断网、Agent 重启、Storage 重启、Uploader 重启后均能继续追赶，不需要人工改序号或清库才能恢复。
