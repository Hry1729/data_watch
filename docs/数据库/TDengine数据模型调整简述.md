# TDengine 数据模型调整简述

> 更新时间：2026-04-14
> 适用范围：工业数据采集与监控平台当前 TDengine 设计基线

---

## 一、调整背景

旧模型采用：

```text
单库 -> 设备类型超级表 -> 设备子表 -> 多变量混存
```

该方案在同一时间戳写入多个变量时，存在数据覆盖风险，不适合作为当前项目的正式时序模型。

---

## 二、当前统一模型

现统一采用：

```text
设备类型数据库 -> 设备超级表 -> 变量子表
```

对应关系：

- 一个设备类型对应一个数据库，如 `qc`、`asc`、`agv`
- 一台设备对应一个超级表，如 `qc100`、`asc7011`、`agv801`
- 一个变量对应一个子表，如 `qc100_1`、`asc7011_85`、`agv801_100`

---

## 三、命名规则

### 1. 数据库名

- 按设备类型小写命名：
  - `qc`
  - `asc`
  - `agv`

### 2. 超级表名

- 与 MySQL 中的 `device.device_code` 保持一致
- 示例：
  - `qc100`
  - `asc7011`
  - `agv801`

### 3. 子表名

- 规则：

```text
{device_code}_{变量编号主体}
```

- 示例：
  - `qc100_1`
  - `qc100_11901`
  - `asc7011_85`
  - `asc7011_4200`
  - `agv801_100`

说明：

- 若变量编码原始值为 `qc1`，则子表名取 `qc100_1`
- 若变量编码原始值为 `asc85`，则子表名取 `asc7011_85`
- 若变量编码原始值为 `agv100`，则子表名取 `agv801_100`

---

## 四、表结构约定

### 1. 超级表字段

- 列：
  - `ts`
  - `value`

- TAG：
  - `device_id`
  - `variable_id`

### 2. 变量子表字段

- 仅保存单个变量的时间序列：
  - `ts`
  - `value`

---

## 五、当前代表性测试样本

当前文档与脚本统一采用以下 3 台代表设备：

- `qc100`：在线 + 持续更新（`online + update`）
- `asc7011`：数据陈旧 / 离线（`stale / offline`）
- `agv801`：在线 + 告警（`online + alarm`）

场景语义说明：

- `online`：设备当前有最新样本，连接状态判定为在线
- `update`：数据会持续刷新，适合验证实时更新链路
- `stale`：数据存在但已超时，属于“陈旧样本”
- `offline`：长时间无新样本，连接状态应判定为离线
- `alarm`：最新样本触发告警条件，适合验证异常态展示

对应示例子表：

- `qc100_1`
- `qc100_11901`
- `asc7011_85`
- `asc7011_4200`
- `agv801_100`
- `agv801_200`

与当前更贴近真实结构的联调补充样本：

- QC 补充：`qc101_1`、`qc101_11901`
- ASC 补充：`asc7021_85`、`asc7021_4200`
- AGV 补充：`agv802_100`、`agv802_200`

说明：

- 代表性场景口径仍以 `qc100` / `asc7011` / `agv801` 为主
- 若需要更贴近真实库结构的联调，可同时启用 `qc101`、`asc7021`、`agv802`
- 当前 ASC 全量编码按 121 台口径采用 `asc7011` + `asc7021/asc7022` ... `asc7611/asc7612`，暂不默认引入 `asc7012`
