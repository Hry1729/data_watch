```
┌─────────────────────────────────────────────────────────────────────┐
│                         数据采集流                                   │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  MySQL 配置中心                                                       │
│  device / device_variable / comm_protocol / device_type              │
│             │                                                        │
│             ▼                                                        │
│  DeviceManager -> ScanTask(device + scan_rate) -> ReadBlock[]        │
│             │                                                        │
│  ┌──────────┴───┬──────────┬───────────────┬──────────────┐         │
│  │ S7/GE PLC    │ OPC UA   │ OPC DA center │ HTTP/OPCDA   │         │
│  │ Driver       │ Driver   │ proxy Driver  │ Push ingest  │         │
│  └──────┬───────┴────┬─────┴──────┬────────┴──────┬───────┘         │
│         │            │            │               │                 │
│         ▼            ▼            ▼               ▼                 │
│  TaskExecutor 批量读取/解析  <----- /ingest, /ingest/opcda-tags      │
│         │  S7 I/Q/M 连续字节合并后按 result_map 还原变量             │
│         ▼                                                            │
│  DataPoint {device_id, variable_id, value, timestamp, quality}       │
│         ▼                                                            │
│  DataBuffer (asyncio.Queue, 非阻塞入队, 满队列显式丢弃计数)          │
│         ▼                                                            │
│  DataAggregator (value+quality 去重 / 时间窗口 / 失败 batch 回放)    │
│         ▼                                                            │
│  BatchWriter (按变量子表分组 / 重试 / 批量 INSERT)                   │
│         ▼                                                            │
│  TDengine: 设备类型数据库 -> 设备超级表 -> 变量子表(ts,value,quality) │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

## 三、HTTP 端点

| 端点 | 方法 | 功能 | 说明 |
|------|------|------|------|
| `/ingest/health` | GET | 健康检查 | 返回队列状态和映射数量 |
| `/ingest` | POST | 通用点位接收 | 需要 `device_id` + `variable_id` |
| `/ingest/opcda-tags` | POST | OPC DA 专用 | schema: `opcda_tag_batch_v1` |

### /ingest/opcda-tags 请求格式

```json
{
  "source": "opcda_sidecar",
  "schema": "opcda_tag_batch_v1",
  "points": [
    {
      "device_id": "agv801",
      "item_id": "OPD_Server.AGV801.ViewMain.Tag30041800",
      "value": 123.45,
      "quality": 192,
      "timestamp": "2026-05-02T18:00:00+08:00"
    }
  ]
}
```

### 响应格式

```json
{
  "accepted": 100,
  "unmapped": 2,
  "dropped": 0,
  "errors": []
}
```

## 四、MySQL 配置说明

### 设备表 (device)

| 字段 | 说明 | OPC DA 填写示例 |
|------|------|-----------------|
| device_code | 设备编码 | `agv801` |
| protocol_id | 协议ID | `opcda_sidecar` 协议的 ID |
| endpoint | 端点 | `127.0.0.1:8090` (collector 地址) |

### 点位表 (device_variable)

| 字段 | 说明 | OPC DA 填写示例 |
|------|------|-----------------|
| device_id | 设备ID外键 | 关联 agv801 |
| var_seq | 点位序号 | `1`, `2`, `3`... |
| var_address | 完整地址 | `OPD_Server.AGV801.ViewMain.Tag30041800` |

## 六、启动流程

```python
# main.py 启动流程
CollectorApp.start():
  1. device_manager.register_devices()    # 注册设备+变量
  2. tdengine.connect()                   # 连接 TDengine
  3. tdengine.init_storage_topology()     # 初始化数据库/超级表/子表
  4. device_manager.connect_all()         # 连接 PLC 设备
  5. scheduler.add_tasks(tasks)           # 构建采集任务
  6. scheduler.start()                    # 启动调度循环
  7. ingest_server.start(opcda_mapper)    # 启动 HTTP 服务
  8. aggregator.run()                     # 启动聚合循环
  9. health_checker.run()                 # 启动健康检查
  10. await _shutdown.wait()              # 等待退出信号
  11. shutdown()                          # 清理资源
```

## 七、协议支持

| 协议 | 驱动文件 | 直连支持 | Sidecar |
|------|----------|----------|---------|
| S7 (Siemens) | `s7_driver.py` | ✅ | - |
| GE SRTP | `ge_srtp_driver.py` | ✅ | - |
| OPC UA | `opcua_driver.py` | ✅ | - |
| OPC DA center | `opcda_center_driver.py` | ✅ 通过本机 x86 代理 | - |
| OPC DA sidecar | - | ❌ 64 位 Python 不直连 COM | ✅ `opcda_push_service` -> `/ingest/opcda-tags` |
| HTTP Push | - | - | ✅ `/ingest` |

S7 额外能力：DB 地址保持 `DBX/DBB/DBW/DBD` 标准语义；I/Q/M 区连续或重叠字节会合并为 `%IB/%QB/%MB` BYTE 块读取，再由 `ScanTask.result_map` 和 `TaskExecutor` 还原到变量值。

GE SRTP 额外能力：`%R/%AI/%AQ` 按 word 区间合并，最大 125 words；`%I/%Q/%M` 第一版按 BOOL bit 区间合并，最大 512 bits。真实轨道吊 GE 点位表只读模拟验证为 4539 个可读变量合并成 476 个读取块。DINT/REAL/DWORD 当前默认 `low_high` word 序，现场必须用已知值校验。

## 九、关键设计决策

| 决策 | 选择 | 原因 |
|------|------|------|
| 采集模式 | asyncio + run_in_executor | PLC 驱动为同步库，用线程池包装 |
| 连接方式 | 长连接 + 自动重连 | 避免 PLC 端资源耗尽 |
| 去重策略 | 内存字典记录上次 value+quality | 节省 TDengine 存储，同时保留质量变化 |
| 批量写入 | 按变量子表分组写 `ts,value,quality` | 变量独立时间序列，支持质量标记 |
| TDengine 连接 | WebSocket (taos-ws-py) | 官方推荐，依赖小 |
| OPC DA 接入 | C# x86 sidecar | 32 位 COM 无法被 64 位 Python 直连 |
| Tag 映射 | var_address → variable_id | 简单直接，无需解析 |
| GE SRTP 合并 | 默认连续合并，不跨空洞 | 降低 PLC 请求压力，同时保留现场字序/地址基准校验边界 |
