# 代码设计逻辑说明

## 一、整体设计思路

### 1.1 架构原则

本系统采用以下设计原则：

1. **分层解耦** - 各层职责明确，通过接口和事件总线解耦
2. **异步优先** - 全链路异步，提高并发性能
3. **插件化扩展** - 支持动态加载和扩展
4. **高可靠设计** - 多重保障机制，确保系统稳定
5. **可观测性** - 完整的监控、日志、指标体系

### 1.2 核心数据流

```
设备配置 → 设备注册 → 连接建立 → 任务构建 → 数据采集 → 
数据缓冲 → 智能聚合 → 批量写入 → 持久化存储
```

当前实现补充：

- 数据点模型为 `DataPoint(device_id, variable_id, value, timestamp, quality)`。
- 采集主链路已经写入 `quality` 字段；PLC 轮询默认 `quality=0`，OPC DA sidecar 会将原始 OPC quality 映射为内部质量码。
- `core/data_quality.py` 是规则引擎能力，尚未自动接入主链路做值域/变化率等质量判定。

#### 关键特性
- **值/质量变化去重** - 相同 value+quality 不重复存储，质量变化会保留

- **时间窗口** - 超过最大时间强制写入

### 4.1 地址合并算法

以下为算法意图示意；实际实现还会保留 `result_map`，用于把合并块的读取结果还原到原始变量。

```python
def merge_continuous_blocks(variables: List[Dict]) -> List[Tuple]:
    """合并连续地址块"""
    merged = []
    if not variables:
        return merged
    
    # 按区域和偏移量排序
    sorted_vars = sorted(variables, key=lambda x: (x["area"], x["offset"]))
    
    current_block = None
    for var in sorted_vars:
        if (current_block and 
            var["area"] == current_block["area"] and 
            var["offset"] == current_block["end_offset"] + 1):
            # 连续地址，合并
            current_block["end_offset"] = var["offset"]
            current_block["count"] += 1
        else:
            # 不连续，保存前一个块
            if current_block:
                merged.append((
                    current_block["start_address"],
                    current_block["count"]
                ))
            # 开始新块
            current_block = {
                "area": var["area"],
                "start_offset": var["offset"],
                "end_offset": var["offset"],
                "count": 1,
                "start_address": var["address"]
            }
    
    # 添加最后一个块
    if current_block:
        merged.append((
            current_block["start_address"],
            current_block["count"]
        ))
    
    return merged
```

### 4.2 熔断器算法

```python
class CircuitBreaker:
    """熔断器实现"""
    
    def __init__(self, failure_threshold=5, recovery_timeout=60):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.failure_count = 0
        self.last_failure_time = None
        self.state = "CLOSED"  # CLOSED, OPEN, HALF_OPEN
        
    async def __call__(self, func, *args, **kwargs):
        if self.state == "OPEN":
            if self._should_attempt_reset():
                self.state = "HALF_OPEN"
            else:
                raise CircuitBreakerOpenError()
        
        try:
            result = await func(*args, **kwargs)
            self._on_success()
            return result
        except Exception as e:
            self._on_failure()
            raise
```

### 4.3 数据质量检测算法

```python
def _check_rate_of_change(self, variable_id, value, timestamp, parameter):
    """增强的变化率检测"""
    max_change = parameter.get("max_change", float('inf'))
    time_window = parameter.get("time_window", 60)
    
    last_value, last_time = self._last_values.get(variable_id, (None, None))
    
    if not last_value or (timestamp - last_time).total_seconds() > time_window:
        return DataQualityResult(..., quality=DataQuality.GOOD)
    
    # 计算变化率
    change_rate = abs(value - last_value) / (timestamp - last_time).total_seconds()
    
    if change_rate > max_change:
        # 检查是否是阶跃变化
        if change_rate > max_change * 5:
            # 检查历史数据
            historical_changes = self._get_historical_changes(variable_id, time_window)
            if historical_changes and max(historical_changes) > max_change * 3:
                # 历史上有类似变化，可能是真实的
                return DataQualityResult(..., quality=DataQuality.GOOD)
            else:
                return DataQualityResult(..., quality=DataQuality.BAD)
        else:
            return DataQualityResult(..., quality=DataQuality.SUSPECTED)
```
