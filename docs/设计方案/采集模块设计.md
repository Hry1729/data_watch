# 自动化设备数据采集平台项目文档

## 一、项目背景

随着国内自动化码头建设的不断推进，码头设备的自动化程度和信息化水平持续提升，设备产生的大量实时数据成为管理和维护的重要依据。为了提高设备监控和运维效率，需要建设一套统一的设备数据采集平台，以支持对码头设备（如桥吊、轨道吊、AGV 等）的数据采集、存储和分析。

本项目旨在通过建立一套高性能的设备数据采集平台，实现自动化码头设备的数据采集与监控，提升运维效率，支持后续智能化运维与决策分析。

## 二、架构设计

### 1. 系统总体架构

本系统采用分层架构，数据采集模块分为以下几个关键层次：

- **设备层**：负责与设备（如 PLC）进行通信，获取设备运行数据。
- **数据采集层**：负责采集设备数据并进行初步处理。
- **数据存储层**：MySQL 负责配置与主数据，TDengine 负责实时 + 历史时序数据。
- **平台服务层**：提供设备管理、数据监控、报警系统、数据查询等服务。
- **应用层**：前端展示与用户交互。

### 2. 系统组件

- **统一驱动接口**：为不同协议（如 Snap7、GE、OPC）提供统一接口，支持协议解耦与扩展。
- **异步调度与任务管理**：采用异步 I/O 机制，通过任务调度系统按需调度采集任务。
- **批量采集机制**：同一设备的多个点位可以通过批量读取进行采集，提升采集效率。
- **队列与缓冲**：数据采集通过队列和聚合器进行解耦，避免采集与写入过程相互阻塞。
- **数据存储**：采集值直接写入 TDengine，满足实时展示与历史查询的统一存储需求。

说明：

- **Redis 当前暂不使用**，不作为采集模块运行依赖。

------

## 三、数据采集模块设计

### 1. 驱动与设备管理

采集服务采用模块化设计，底层通过统一驱动接口封装不同 PLC 通信协议，实现协议解耦与扩展。每个驱动（如 Snap7、GE、OPC）作为一个独立模块，可以轻松扩展支持更多设备类型。

系统中的每个设备都对应一个连接实例，每个设备下可以有多个变量，每个变量都有独立的采集周期。

### 2. 数据采集架构

数据采集采用异步 I/O 机制，所有设备的采集任务通过调度器进行管理，确保高并发且不阻塞。每个设备的采集任务根据设备的不同采集周期进行分组，以提升系统性能。

### 3. 批量采集与高效处理

批量采集模块根据设备和点位的连续性自动生成批量读取块，减少单次读取频率和延迟。采集结果先进入内存队列与聚合器，再由批量写入器统一落 TDengine。

### 4. 数据存储与历史管理

实时数据与历史数据统一存储在 TDengine 中：

- **实时展示**：通过查询最新值或最新时间窗口数据实现；
- **历史查询**：通过时间范围查询实现；
- **趋势统计**：通过连续聚合视图或聚合查询实现。

## 四、性能优化与可扩展性

### 1. 异步 I/O 与高并发处理

使用 Python 的 `asyncio` 实现非阻塞 I/O，确保多个设备的并发采集。每个设备的采集任务可以独立执行，避免某一设备卡住影响其他设备采集。

### 2. 数据批量采集与存储优化

通过 **批量读取** 机制，减少单次请求数量；通过 **批量写入 TDengine**，减少高频单条写入带来的性能损耗。

### 3. 数据存储方案

- **MySQL**：用于设备、点位、分组、报警规则等配置与主数据；
- **TDengine**：用于实时 + 历史时序数据的统一存储与查询；
- **Redis**：当前暂不使用。

### 4. 系统稳定性

系统采用长连接机制，避免频繁连接设备带来的性能问题。通过定期心跳检测和自动重连机制，确保连接的稳定性和可靠性。

------

## 五、技术选型与关键技术

### 1. 技术选型

- **Python & asyncio**：用于实现异步 I/O 和高并发任务调度。
- **MySQL**：用于配置与主数据存储。
- **TDengine**：用于实时 + 历史时序数据存储与查询。
- **Snap7、GE、OPC**：提供多种 PLC 协议支持，满足设备接入需求。

### 2. 关键技术

- **异步采集**：利用 `asyncio` 和多任务并发进行设备数据采集，保证高并发和高性能。
- **批量采集**：根据设备点位地址连续性生成批量读取块，提高采集效率。
- **长连接管理**：设备与采集服务之间采用长连接，避免频繁连接导致的性能瓶颈。
- **日志与监控**：采集任务通过日志系统进行记录和监控，确保采集过程可追溯。

------

## 六、系统稳定性与容错设计

### 1. 自动重连与心跳机制

系统中采用 **心跳检测** 和 **自动重连** 机制，在设备掉线或连接中断时，能够及时恢复连接并继续采集。

### 2. 数据缓冲与队列

通过 **队列缓冲**，采集模块与写入模块进行解耦，确保在高并发情况下数据能够高效落库。

### 3. 错误报警与采集监控

系统通过日志与监控模块对采集过程进行实时监控，并在出现异常时自动报警，确保设备和采集系统的稳定运行。

------

## 七、总结

本项目设计了一套高性能、可扩展的自动化设备数据采集平台，采用模块化设计以支持多协议设备接入。平台通过异步 I/O 和批量采集技术，确保大规模设备数据的高效采集与实时存储。当前实际架构统一为：

- **MySQL 管配置/主数据**
- **TDengine 管实时 + 历史时序数据**
- **Redis 暂不使用**

该平台不仅满足当前码头自动化设备监控需求，还具备较强的可扩展性，能够支持未来设备和协议的持续接入。
