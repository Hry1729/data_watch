**工业设备监控平台标准后端架构**

------

# 一、系统总体后端架构

建议把系统拆成 **两个独立服务**：

```
设备平台
│
├─ backend        (TurboAPI业务系统，FastAPI compatible)
│
├─ collector      (设备数据采集服务)
│
└─ frontend       (ArtDesignPro)
```

原因：

- 采集系统稳定运行
- 业务系统重启不影响采集
- 后期可扩展多采集节点

整体架构：

```
PLC设备
   │
   │ snap7 / GE SRTP / OPC
   │
采集服务 (collector)
   │
   │ 写入实时 + 历史时序数据
   │
TDengine 时序数据库
   │
   │
TurboAPI 后端
   │
   ├── 查询实时最新值 / 历史时序
   │
   └── 结合 MySQL 主数据组装接口
        │
MySQL 数据库（主）/ PostgreSQL（备用）
   │
   │
ArtDesignPro 前端
```

说明：

- **MySQL** 负责配置与主数据；
- **TDengine** 负责实时 + 历史时序数据；
- **Redis 当前暂不使用**，不作为运行依赖。

# 五、数据库结构设计（核心）

数据库分工建议明确为：

1. **MySQL**：设备、点位、分组、报警规则、用户、日志等主数据；
2. **TDengine**：实时最新值查询与历史时序查询；
3. **Redis 暂不使用**：不设计为当前后端主链路依赖。

### 1 设备表

```
device
```

| 字段 | 说明 |
|------|------|
| id | 主键 |
| device_code | 设备编号 |
| device_name | 设备名称 |
| device_type | QC / ASC / AGV |
| protocol | s7 / ge / opc |
| status | 启停状态 |
| create_time | 创建时间 |

### 2 点位表

```
device_variable
```

| 字段 | 说明 |
|------|------|
| id | 主键 |
| device_id | 设备ID |
| var_seq | 点位序号（纯序号，TDengine 子表名由 `device_code + '_' + var_seq` 派生） |
| var_name | 点位名称 |
| var_address | PLC地址 |
| data_type | 数据类型 |
| scan_rate | 采集周期 |
| is_storage | 是否入 TDengine |

### 3 实时与历史时序

实时值与历史值统一落 TDengine：

- TDengine 按**设备类型分数据库**
- 每台设备在所属数据库下拥有**独立超级表**
- 每个点位（变量）在设备超级表下拥有**独立子表**
- 实时页读取 **最新一条或最新窗口数据**
- 历史页读取 **指定时间范围内的时序数据**
- Dashboard 读取 **聚合结果或连续聚合视图**

# 六、实时与历史查询设计

当前不再设计 Redis Key。

后端应采用以下方式读取数据：

### 1. 实时初始化

- MySQL：读取设备、点位、分组等静态信息
- TDengine：按“设备类型数据库 -> 设备超级表 -> 变量子表”查询每个点位最新值与时间戳
- backend：统一组装为 `realtime-init` 响应

### 2. WebSocket 推送

- collector 持续向 TDengine 写入采集值
- backend 基于最新值查询、订阅或轮询结果生成统一事件
- 对前端输出 `snapshot / update / alarm / error / pong`

### 3. 历史查询

- 直接查变量子表时间范围数据，必要时在后端聚合多变量结果
- 返回 `times + points[].values` 结构

# 八、数据采集流程

采集服务启动：

```
加载设备配置（MySQL）
    ↓
加载点位配置（MySQL）
    ↓
建立PLC连接
    ↓
创建采集任务
    ↓
周期读取PLC
    ↓
写入TDengine
    ↓
后端读取最新值 / 历史值
```

# 十、关键建议

你这个系统 **一定要做一个统一的数据模型**。

统一：

```
设备
↓
点位
↓
实时/历史时序值
```

这样系统可扩展性会更好，而且更符合当前仓库已经形成的 **MySQL + TDengine** 双库结构。
