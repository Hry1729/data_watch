# 一、系统总体架构

本系统采用分层解耦架构：

1. **设备接入层**
2. **数据采集层**
3. **时序存储层**
4. **业务服务层**
5. **前端展示层**

整体数据流：

```
PLC设备 → 数据采集服务 → Redis（100ms 实时快照 / 短窗口）
                     ↘
                      TDengine（500ms/1s 批量历史时序）
                     ↘
                      MySQL（配置 / 主数据）
                             ↓
                          TurboAPI
                             ↓
                    前端系统（ArtDesignPro + Perspective）
```

当前实际架构定义：

- **MySQL 管配置/主数据**
- **Redis 管 100ms 实时最新值与短窗口**
- **TDengine 管宽表历史时序数据**
- **Perspective 提供历史数据可视化与分析**（v2 新增）

# 四、数据采集服务设计

职责：

```
1 连接PLC
2 读取变量
3 数据解析
4 写入 Redis 实时缓存
5 写入 Redis Stream 待入库队列
```

采集流程：

```
启动采集服务
      ↓
读取MySQL配置
      ↓
建立PLC连接
      ↓
周期采集变量
      ↓
数据解析 / 聚合
      ↓
写入Redis最新快照/短窗口
      ↓
追加Redis Stream
      ↓
入库模块批量消费Stream并写TDengine
```

采集频率建议：

```
设备状态      1秒
重要变量      500ms
普通变量      2秒
```

> **注意**：采集模块只写 Redis。TDengine 历史态由独立入库模块按 500ms/1s 从 Redis Stream 批量消费并写入。Perspective 仅在后端查询 TDengine 历史数据后使用。

# 五、Redis 实时查询设计

当前前端 100ms 实时监控不再直接依赖 TDengine 最新值查询，实时页优先依赖 Redis 最新快照与最近 N 行短窗口。

建议做法：

### 设备实时快照

- 按设备编码读取 Redis 最新快照
- 后端统一组装为 `realtime-init`

### 点位最新值

- 以设备 + 点位为维度取最新记录
- 包含 `value / updateTime`

### 实时推送

- 后端基于 Redis 最新帧或短窗口变化生成 `snapshot / update / alarm / error / pong`

# 六、数据写入服务设计

当前主流程为：

```
collector → Redis(latest/window/stream) → 入库模块 → TDengine
```

工作流程：

```
采集任务产生数据点
       ↓
进入内存队列 / 聚合器
       ↓
写入Redis实时快照/短窗口
       ↓
追加Redis Stream待入库队列
       ↓
入库模块每500ms/1s批量消费
       ↓
写入TDengine并ACK Stream消息
       ↓
后端读取最新值 / 历史值
```

优势：

```
实时态与历史态解耦
100ms 前端监控不压 TDengine
采集模块不被TDengine抖动反向拖慢
TDengine 采用大批量写入，提高吞吐稳定性
```

# 七、数据库设计

数据库职责划分：

- **MySQL**：设备、点位、分组、报警规则、用户、日志
- **Redis**：实时最新值、最近 N 行短窗口、待入库 Stream
- **TDengine**：宽表历史时序数据

其中：

- 设备树 / 设备列表主要来自 MySQL
- Realtime / WebSocket 时序部分优先来自 Redis
- History / Dashboard 历史趋势来自 TDengine

# 十、Perspective 集成设计（v2 新增）

### 10.1 集成模式

采用**客户端/服务器复制模式**：

- 服务端维护 Perspective Table 主副本
- 客户端通过 WebSocket 同步数据到本地副本
- `<perspective-viewer>` 组件渲染本地数据

### 10.2 数据流

```
用户查询历史数据
       ↓
后端查询 TDengine
       ↓
写入 Perspective Table
       ↓
WebSocket 同步到客户端
       ↓
前端 Perspective Viewer 渲染
```

### 10.3 并发处理

```
用户A ──┐
用户B ──┼──► Perspective Server ──► 共享 Table ──► 广播更新
用户C ──┘
```
