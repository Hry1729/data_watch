# 一、系统总体架构

本系统采用分层解耦架构：

1. **设备接入层**
2. **数据采集层**
3. **时序存储层**
4. **业务服务层**
5. **前端展示层**

整体数据流：

```
PLC设备 → 数据采集服务 → TDengine（实时 + 历史时序）
                     ↘
                      MySQL（配置 / 主数据）
                             ↓
                          TurboAPI
                             ↓
                    前端系统（ArtDesignPro + Perspective）
```

当前实际架构定义：

- **MySQL 管配置/主数据**
- **TDengine 管实时 + 历史时序数据**
- **Redis 暂不使用**
- **Perspective 提供历史数据可视化与分析**（v2 新增）

# 三、系统模块设计

核心模块包括：

- **collector**：负责设备连接、采集调度、批量读取和时序写入
- **backend**：负责 API、WebSocket、主数据读取、时序查询、Perspective Server（v2 新增）

- **database**：负责 MySQL / TDengine 结构设计与治理
- **test**：负责真实服务链路下的测试假数据与联调验证

# 四、数据采集服务设计

职责：

```
1 连接PLC
2 读取变量
3 数据解析
4 批量写入TDengine
```

采集流程：

```
启动采集服务
      ↓
读取MySQL配置
      ↓
建立PLC连接
      ↓
周期采集变量
      ↓
数据解析 / 聚合
      ↓
写入TDengine
```

采集频率建议：

```
设备状态      1秒
重要变量      500ms
普通变量      2秒
```

> **注意**：采集模块数据直接写入 TDengine，不参与 Perspective 数据流。Perspective 仅在后端查询 TDengine 后使用。

# 五、TDengine 实时查询设计

当前不再使用 Redis 作为实时缓存层，实时页直接依赖 TDengine 最新值查询。

建议做法：

### 设备实时快照

- 按设备类型数据库、设备超级表、变量子表定位最新点位值
- 后端统一组装为 `realtime-init`

### 点位最新值

- 以设备 + 点位为维度取最新记录
- 包含 `value / updateTime`

### 实时推送

- 后端基于 TDengine 最新值变化生成 `snapshot / update / alarm / error / pong`

# 六、数据写入服务设计

当前主流程为：

```
collector → TDengine
```

工作流程：

```
采集任务产生数据点
       ↓
进入内存队列 / 聚合器
       ↓
批量写入TDengine
       ↓
后端读取最新值 / 历史值
```

优势：

```
链路更直接
实时与历史口径统一
减少中间缓存层漂移
```

# 十、Perspective 集成设计（v2 新增）

### 10.1 集成模式

采用**客户端/服务器复制模式**：

- 服务端维护 Perspective Table 主副本
- 客户端通过 WebSocket 同步数据到本地副本
- `<perspective-viewer>` 组件渲染本地数据

### 10.2 数据流

```
用户查询历史数据
       ↓
后端查询 TDengine
       ↓
写入 Perspective Table
       ↓
WebSocket 同步到客户端
       ↓
前端 Perspective Viewer 渲染
```

### 10.3 并发处理

```
用户A ──┐
用户B ──┼──► Perspective Server ──► 共享 Table ──► 广播更新
用户C ──┘
```

### 10.4 详细设计

详见：`docs/设计方案/Perspective集成设计.md`
